## Наблюдения
1. **«не по ожиданию» (1) и (2) объяснены — это не потеря отпечатков, а ротация подписки.**
   Оба сравнения (до→после установки и после «Обновить») дали «пропало 21, появилось 21», но
   события обновления подписки показывают настоящую замену: в apply-событии после «Обновить»
   удалено 21 запасных серверов и добавлено 20 новых (после установки — аналогично). То есть
   источник подписки сам меняет ~21 запасной сервер при каждом скачивании; отпечатки изменились
   ровно у этих серверов. Отпечатки остальных 92 серверов — общие по всем трём снимкам, включая
   переход старый код → новый код → «Обновить»: нестабильности отпечатков у неизменившихся
   серверов не видно. Выбор вручную (сервер не из ротируемых запасных) держался на всех шагах.
2. Проверка «отпечатки прежние после обновления» по замыслу ТЗ чисто не отделяется от ротации
   подписки: при каждом «Обновить» состав запасных меняется самим источником. Предположение для
   следующей проверки: снимать снимок отпечатков до и после обновления одной и той же подписки
   без её изменений (или сравнивать не список, а историю: у неизменившихся серверов в
   fingerprints.json не должно появляться новых записей).
3. «Основной сервер: нет» на всех шагах — объясняется настройкой на панели: включён режим
   «Один основной сервер» с текстом «пока сервер выбран вручную, основной сервер не выбирается»,
   трафик идёт через ручной выбор (главная карточка «Выбран вручную… весь трафик идёт через
   него»). Шаг 3.1 по этому случаю пропущен по «Если не так».
4. Команда шага 3.1 подставила тег «нет» в `xgw probe` — шлюз выполнил пробу запасных серверов
   (виден хвост из трёх строк: OK, 57620 Б за 0,3–0,7 с). Предположение: с несуществующим тегом
   `xgw probe` проверяет запасные. Сама проба показала новый формат вывода с байтами и секундами.
5. Проба профиля по файлу целиком и «отвечает только с дроблением ClientHello» видны в событиях
   (профиль обхода применён через API без перезапуска, затем — «отвечает только с дроблением
   ClientHello — оно включено»): скан-лестница работала во время наблюдения.
6. Правила сети: удалённая таблица `ip xgw` вернулась за 1,6 с с одним событием перехвата
   «правила сети не были загружены — загружены заново»; за окно сканов «правила загружены
   заново: 0» — сигнал правил не терялся ни в окне загрузки, ни в буре событий (событий сети за
   окно было много, но «внеочередная проверка» не потребовалась).
7. Машина в конце: режим пула off (как до проверки), HEALTHY с 13:01, перехват включён, 4 службы
   active, ручной выбор сервера подписки сохранён (proxy-lv-12ef), история отпечатков — права
   600, только хеши, таймеров нет, копий настроек нет.
