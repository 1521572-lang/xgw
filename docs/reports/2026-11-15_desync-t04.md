## Хотфикс readiness (точечный, с повторной проверкой)

**Дефект, найденный живой приёмкой**: builder в standalone заменяет routing целиком — без
секции `balancers` (тест разработчика `test_desync_standalone` сам это фиксирует:
`assert "balancers" not in closed["routing"]`). При этом readiness apply-а
(`applier._restart_and_wait`) требует ответа `balancer_info("auto")` — API отвечает ошибкой
для несуществующего балансировщика → 15 c ожидания → «Xray не поднялся» → откат на last-good.
Standalone-apply на машине не мог пройти в принципе; первый `set_standalone` это воспроизвёл
(журнал: откат, перехват fail-closed кратко, затем восстановление last-good).

**Исправление** (`src/xgw/apply/applier.py`, строка ~260): в цикле ожидания после неудачи
`balancer_info` добавлена вторая проба живости — `list_outbounds()`; успех любой из двух = «ядро
поднялось». Для VPN-конфигураций поведение прежнее (первая проба успешна), для standalone —
readiness достигается корректно. Хотфикс внесён в установленный слой и в манифест
(`new_sha` applier.py обновлён, помечен hotfix), включён в отчётный коммит отдельным точным
путём. Повторная проверка: `set_standalone` → worker активен через 12 c.
