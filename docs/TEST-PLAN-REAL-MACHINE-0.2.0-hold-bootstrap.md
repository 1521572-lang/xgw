# ThinkCentre: защита при отсутствии рабочего конфига Xray

Цель PR-2 — когда включён перехват и выбран hold=block, обычный интернет машины и клиентов
за роутером должен быть закрыт до появления конфига Xray. Подписку получает сам XGW.
Проверяем два пути: с временной машины-шлюза и с клиента за ней в отдельных сетях ядра
ThinkCentre. Контрольный сервер и весь тестовый трафик находятся там же. Рабочий config.json,
адаптеры, WAN/LAN, правила, Tailscale, подписки, пул и ручной выбор владельца не менять.
Flash может использовать все доступные инструменты, включая зрение. Рабочий on сохранять.
Доступность каждого VPN-сервера не является критерием. PR-1 и G1 не повторять.

## 1. Зафиксировать код и исходное состояние

Команды рассчитаны на bash. Вести шаги в одном терминале. Сначала:

```bash
cd ~/xgw && test -z "$(git status --porcelain)" && git switch freepool &&
git fetch origin && git merge --ff-only origin/freepool
```

При конфликте или локальных изменениях — STOP, ничего не сбрасывать. Затем:

```bash
CODE=b8814a4bb54f19b7699568f23c95a2562d4a0a95
BASE=e3601965fbd703153cb3bf992ca8a948915c60e5
D=$(mktemp -d "$HOME/xgw-hold-check.XXXXXXXX")
TARGET="$D/new"; PREV="$D/previous"; H="$TARGET/docs/helpers/hold_bootstrap_check.py"
git worktree add --detach "$TARGET" "$CODE" && git worktree add --detach "$PREV" "$BASE" &&
test "$(git -C "$TARGET" rev-parse HEAD)" = "$CODE" &&
test "$(git -C "$PREV" rev-parse HEAD)" = "$BASE" &&
printf '%s  %s\n' '4f1d6bf87378664a1431bf3b9bbfe2dee1732274cc88b5fee76b9f70648771ef' "$H" | sha256sum -c -
```

Ожидается `OK`, rc0. Иной результат — STOP. Временно сохраните приватно:

```bash
umask 077
sudo python3 -I "$H" health && sudo xgw status --json >"$D/before.json" &&
sudo sha256sum /etc/xgw/config.toml >"$D/config.sha" &&
sudo xgw diag --no-net >"$D/diag-before"
```

Ожидаются `OK on`, `OK https`, отсутствие новых аварий. Записать числа OK/WARN/FAIL,
режим пула и ручной выбор приватно. Если исходный on/HTTPS не подтверждён, STOP.
Не публиковать сырые файлы. Не запускать G1 или старые задания волны 3.

## 2. Один изолированный прогон с сохранением rc

Команда ниже сохраняет и stdout, и фактический rc, даже если Flash отсоединится.
До запуска запишите путь D приватно. Для чтения при возвращении восстановите переменную D.
Отдельный источник интернета, пароль подписки и доступ к клиенту владельца не нужны.

```bash
sudo sh -s -- "$H" <<'SH'
set -eu
umask 077
mkdir -m 700 /run/xgw-hold-test
cd /run/xgw-hold-test
nohup setsid sh -c 'python3 -I "$1" isolated; rc=$?; printf "%s\n" "$rc" >rc.tmp; mv rc.tmp rc' sh "$1" </dev/null >steps 2>&1 &
SH
```

При занятом каталоге второй запуск запрещён. Результат читается той же командой ожидания:

```bash
sudo sh -c 'cd /run/xgw-hold-test && for i in $(seq 55); do test ! -f rc || break; sleep 2; done; cat steps; test -f rc && printf "isolated_rc=%s\n" "$(cat rc)"'
```

Ожидаются rc=0 и строки OK в следующем порядке:
1. isolated, positive_controls — до включения защиты шлюз и клиент получили контрольное тело.
2. Для missing, broken, encoding по порядку — суффиксы _rules, _host_lan_closed,
   _subscription. Для каждого состояния обычный HTTP закрыт с двух сторон, правила и барьер
   проверены, тот же HTTP через штатный загрузчик подписок с меткой вернул ожидаемое тело.
3. dhcp_packet, time_packet — контрольный узел получил по одному UDP-пакету на служебных
   портах. Это проверка прохода пакетов, а не выдача аренды или синхронизация часов.
4. closed_direct, open_block, explicit_off — прямой путь доступен в разрешённых режимах;
   enabled — снова закрыт; on_again — после появления временного конфига загружены правила on.
   Сессия Xray и реальная подписка в изолированных сетях не требуются.

При отсутствии rc, нарушении последовательности, STOP или таймауте — установку пропустить,
сообщить последний OK и сохранённый rc либо «не получен». Не выводить rc из числа строк.
Не запускать child вручную, не устранять сбой правками сети. Помощник завершает временные
процессы. Оставить файлы эксперимента для чтения.

## 3. Согласие и штатная установка

После успешного шага 2 спросить владельца: «Установить b8814a4 поверх e360196 штатным
установщиком и автоматически вернуть e360196 при ошибке установки, сверки пакета или
on/HTTPS?» Старое согласие использовано. При отказе записать INSTALL_NOT_RUN и перейти к отчёту.
До установки проверить, что результаты и файлы относятся к этому прогону.

```bash
test "$(sudo cat /run/xgw-hold-test/rc)" = 0 && test -z "$(git -C "$TARGET" status --porcelain)" &&
test -z "$(git -C "$PREV" status --porcelain)" && sudo sh -s -- "$H" "$PREV" <<'SH'
set -eu
umask 077
d=/run/xgw-hold-job
mkdir -m 700 "$d"
cd "$d"
nohup setsid sh -c 'python3 -I "$1" deploy "$2"; echo "$?" >result.tmp; mv result.tmp result' sh "$1" "$2" </dev/null >worker.log 2>&1 &
echo 'Установка запущена'
SH
```

Ожидается «Установка запущена». Работник сначала сверяет установленный пакет с BASE и
проверяет on/HTTPS. При отказе до `OK baseline` — STOP без записи пакета. Затем он фиксирует rc
установщика, сверяет файлы с CODE и проверяет on/HTTPS. Если установка началась и приёмка
пакета не прошла, тот же процесс запускает установщик BASE и проверяет файлы и здоровье.
Каталог уже существует — только прочитать результат. Не удалять каталоги и не повторять старт.

```bash
sudo sh -c 'd=/run/xgw-hold-job; for i in $(seq 120); do test ! -f "$d/result" || break; sleep 5; done; cat "$d/worker.log"; printf "worker_rc="; cat "$d/result"'
```

После восстановления связи читать тот же результат. Норма — `install_rc=0`, `OK installed`,
`worker_rc=0`. Если был возврат — указать `rollback_rc` и `rollback_verified`.
Возврат не подтверждён — сразу связаться с владельцем. Самостоятельно ничего не чинить.
Если ожидание длится больше 10 минут — только чтение журнала и состояния процесса, сообщить
владельцу о зависании. Ни второй установки, ни принудительной остановки.

## 4. Работа шлюза и отчёт

При принятой установке оставить шлюз на обычной нагрузке две минуты. Затем:

```bash
sudo python3 -I "$H" health && sudo sha256sum --status -c "$D/config.sha" &&
sudo xgw status --json >"$D/after.json" && sudo xgw diag --no-net >"$D/diag-after"
```

Норма — `OK on`, `OK https`, rc0, новых FAIL нет. Приватно сравнить пул и закрепление с
исходным срезом. Изменение этих настроек, потеря раздачи со слов владельца либо сбой конечной
проверки — PARTIAL, сообщить владельцу, новых воздействий не выполнять. Рабочий HTTPS и
путь синтетического клиента фиксировать отдельно. Настоящий клиент за роутером не измерялся.

Один отчёт в freepool, `docs/TEST-REPORT-REAL-MACHINE-0.2.0-hold-bootstrap-ДАТА.md`.
При STOP допустим короткий отчёт с фактическим rc и последним успешным этапом.
Проверить diff: только этот файл. Публиковать обычным push без force. Не включать адреса,
домены, имена серверов, устройств, подписок, конфиг, сырой JSON, MAC, логи и скриншоты.

- Дата, CODE/BASE, сумма OK, исходный on/HTTPS, diag (три числа).
- Изолированные сети: сохранённый rc, последний OK, три случая конфига, обычный и
  помеченный запрос, клиент, DHCP/время, direct/open/off и возврат к on.
- Согласие, install_rc, worker_rc, возврат и его проверка либо NOT_RUN.
- Конечный on/HTTPS, совпадение конфига, пул/pin, diag, замечания владельца.
- Итог PASS (шаги 1–4 прошли), PARTIAL либо STOP. Первый непройденный шаг и что осталось.
