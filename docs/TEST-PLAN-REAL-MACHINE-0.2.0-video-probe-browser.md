CODE `15852e6d7aed9d5a21c6cbec8e5896af02013a1c`, база `82ee6a2`. Исполнитель GLM-5.3-Flash.
Отчёт video-probe-source дал direct_video_missing. Проверяем, позволяет ли штатный браузер
получить свежий адрес видеосети и повторить загрузку отдельным GET через тот же VPN-выход.
Запуск из worktree. Шлюз, службы, маршруты, VPN, pin, пул, подписки и настройки сохраняются.
Нужен уже установленный Firefox. Пакеты и расширения не ставятся, обычный профиль не открывается.
Адрес ролика выбирает владелец. В отчёте только числа и признаки, без URL, подписей, доменов,
серверов, сырых статусов, страниц, браузерных журналов и пути временного каталога.

## 2. Один браузерный запуск

Согласовать один запуск через одного живого безлимитного участника VPN. Браузеру отведено до
120 секунд и 16 МиБ переданных через локальный прокси данных в обе стороны. Отдельный GET
запрашивает диапазон до 64 КиБ с общим сроком 8 секунд. Учитывать сетевые заголовки и буферы.

По умолчанию берётся настроенный youtube_sign_url или первый подходящий watch-адрес из
zapret2.probe_urls. Для другого публичного ролика владелец задаёт одну строку в `$D/page.txt`
с правами 0600. Адрес не передаётся аргументом командной строки.

От обычного пользователя с sudo выполнить один из вариантов. Первый использует настройки.

```bash
sudo python3 -I "$H" --state "$D/result.json"
```

Если владелец подготовил файл, вместо первого варианта выполнить:

```bash
sudo python3 -I "$H" --state "$D/result.json" --page-file "$D/page.txt"
```

Квитанция создаётся до запуска Firefox. Повтор с этой квитанцией запрещён. При NOT_RUN из-за
отсутствующего адреса можно выполнить один запуск после передачи ссылки владельцем.
Firefox запускается без окна от SUDO_USER, через локальный прокси с ограниченным списком
доменов страницы, видеосети и ресурсов плеера. При запросе о cookie выбирается один отказ
от необязательных. Запрос входа, проверка на робота и ошибки плеера фиксируются как отказ плеера.

Помощник наблюдает продвижение времени видео без рекламы минимум на две секунды. Из списка
ресурсов выбирается HTTPS-адрес видеосети в настроенных доменах, путь videoplayback и expire
от 5 минут до суток. Браузер закрывается, временный профиль удаляется. Затем помощник повторяет
запрос выбранного адреса через тот же VPN-выход с User-Agent Firefox. Перенаправления не следуются.
Критерий успеха — HTTP 200 или 206, минимум 16 КиБ и Content-Type video/*.

## 3. Исходы

| Результат | Значение |
|---|---|
| browser_video_verified | Адрес, полученный Firefox, отдал видео и при отдельном GET через VPN. Следующий эксперимент — получение и повторная загрузка на одном прямом выходе через zapret2. |
| browser_url_missing | Подходящий адрес для повторного GET не получен. Если playback=1, отдельно проверить сетевые события браузера для этого формата. |
| replay_failed / replay_not_video | Повторный GET не выполнил критерий видеопробы. Смотреть HTTP, объём и video_mime. |
| player_refused / media_error / consent / ad / no_video / no_playback | Условия наблюдения за видео не выполнены. Нужны строки RESULT и BROWSER для выбора следующего шага. |
| browser_start_failed / browser_control_failed / browser_budget | Запуск, управление Firefox или лимит остановили прогон. Разобрать конкретный исход, повтор в этом ТЗ не делать. |
| NOT_RUN / STOP | Условия запуска либо сверки не выполнены. Зафиксировать метку, состояние шлюза проверить отдельно. |

При playback=1 помощник наблюдал продвижение времени плеера. Видео и успешный GET относятся
к VPN-выходу этого эксперимента. Для прямого пути нужна отдельная проверка.

```bash
sudo xgw diag --no-net >"$D/diag-after"
```

Ожидаются `OK settings_and_processes_same`, capture on, zapret2 off и отсутствие новых FAIL.
Если конфиг или PID сменился штатно во время запуска, указать причину по приватным данным.
Квитанцию, ссылку и сырые файлы в Git не добавлять.
