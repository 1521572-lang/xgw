## Дефекты

### Д1. Неудачная переустановка на работающем шлюзе оставляет дом без интернета

Степень: критичная (для дома). К Ф1 не относится: это поведение установщика и откатa.

**Как повторить.** На работающем шлюзе запустить `sudo sh packaging/install.sh --yes` в момент, когда демон занят очередным шагом цикла (скан запасных серверов или применение конфига).

**Что ожидалось.** Либо установка дожидается остановки демона (systemd даёт на неё до 90 с), либо, если установка всё же откатывается, **сеть дома остаётся рабочей**: прежний профиль `xgw-lan` и прежние правила возвращаются.

**Что получилось.** `systemctl restart xgw.service` не уложился в 60 с, установщик счёл это сбоем настройки сети и выполнил `Uninstaller(keep_files=True)`:

```
✓ панель управления: http://127.0.0.1:8781/, ярлык «XGW» в меню приложений
✗ настройка сети не удалась: systemctl restart xgw.service: таймаут 60 с
Возвращаю сеть в исходное состояние…
  ✓ службы xgw, xgw-dhcp, xgw-singbox, xgw-xray, xgw-net остановлены
  ✓ таблицы nftables, ip rule, маршрут и интерфейс TUN убраны
  ✓ /etc/xgw/dnsmasq.conf удалён
  ✓ профиль xgw-lan удалён, прежние профили возвращены
  ✓ sysctl возвращён, IPv6 на enp3s0f0 — как до установки
  ✓ сон размаскирован
  ✓ файлы служб удалены
  ✓ ярлык панели удалён
```

После отката (снимок 19:58:16): пять служб `inactive`, файлов `/etc/systemd/system/xgw*.service` нет, у `enp4s0` **нет адреса** `192.168.60.1/24` — то есть LAN-интерфейс без адреса и без DHCP. Проводная сеть дома осталась без шлюза: адреса выдавать некому, выходить в сеть некуда. Восстановление — повторной установкой (19:58:18 → код 0); между откатом и восстановлением дом был без интернета ≈ 11 минут (19:47:50–19:59:00).

Для шлюза «в боевом режиме» это опаснее самого окна blocked: окно возвращается само за 91 с, а здесь сеть не вернулась бы без ручной повторной установки.

### Д2. Демон не прерывает текущий шаг при остановке; установщик ждёт меньше systemd

Степень: средняя (причина Д1).

Остановка демона заняла 79 с (19:48:04 «Stopping xgw.service» → 19:49:23 «Deactivated successfully»). В это время демон доделывал текущий шаг:

```
19:48:18 xgw: скан spare-nl-f4a0: TIMEOUT, 0 байт за 15.1 с
19:49:19 xgw: singbox: sing-box не принял новый конфиг (rollback): sing-box не запустился: systemctl reload: таймаут 30 с
19:49:20 xgw: демон XGW остановлен
```

То есть `SIGTERM` только выставляет флаг, а цикл доходит до конца шага (сканы, применение конфига). Установщик при этом ограничен 60 с (`install.py:711`, `timeout=60.0`), меньше штатных 90 с systemd, — поэтому медленная, но нормальная остановка выглядит как сбой установки. Полезнее было бы: перед `restart` мягко останавливать демон с запасом по времени (или `restart` с таймаутом systemd + резерв), а сбой возврата сети не считать поводом снимать установку целиком.

## Наблюдения

- **Н1. «Долго грузил, потом ошибка» на телефоне — так и должно быть при blocked.** Пакеты отбиваются мгновенно (с самой машины: `отбито (сброс) за 0.00 с`), но телефон получает DNS-сервер `192.168.60.1` (`dhcp-option=option:dns-server,192.168.60.1`), а dnsmasq XGW работает с `port=0` (DNS выключен — его подменяет Xray). В blocked запросы DNS не получают ответа и ждут таймаута, поэтому браузер показывает ошибку через несколько секунд, хотя TCP отбивается сразу. Дефектом не считаю.
- **Н2. Мостов Docker два правила, хотя мост один.** `pre.txt`: «мосты Docker: docker0» (`br-*` нет). При этом «отбой выхода контейнеров в forward: правил 2» — в `forward` есть правило по `docker0` и правило по шаблону `br-*` (на случай сетей Docker). При одном мосте это ожидаемо.
- **Н3. Устройств «мимо VPN» 0** (`bypass_hosts`), поэтому В3 — «нет устройства»; проверять на устройстве было нечего.
- **Н4. Глобального IPv6 на машине нет**, проверка `d` (IPv6 наружу) не выполнялась — и в обычном режиме, и в окне «НЕ ПРОВЕРЕНО». `v6_guard` в таблице `ip6 xgw6` при этом есть.
- **Н5. Демон сразу после окна и после повторной установки работоспособен:** «Состояние: HEALTHY», Xray отвечает, sing-box работает, участников 4, уровень приоритета «высокий».
- **Н6. Ручной выбор сервера в окно и после него не менялся** (выбор не снимался, `xgw unpin` не вызывался), приоритеты участников не трогались.
- **Н7. Панель при повторной установке выдала новый токен** и открыла вход в браузере сама; в отчёт токен не переносится.
- **Н8. 0.1.15 уже стоял до испытаний**, поэтому снимок «до обновления» (§1.2) содержит тот же код с Ф1; номер версии по программе не меняется.

## Что не проверено и почему

- IPv6 наружу (пункт `d` проверки связи) — на машине нет глобальных IPv6-адресов (`network.ipv6 = off`, `v6_guard` в правилах есть).
- Устройство «мимо VPN» — в конфиге `bypass_hosts` пуст, такого устройства в сети нет; ответ В3 — «нет устройства».
- Повторная проверка `install.sh` на «медленной остановке» специально не воспроизводилась: чтобы поймать условие, нужно снова оставить дом без шлюза на время отката.
