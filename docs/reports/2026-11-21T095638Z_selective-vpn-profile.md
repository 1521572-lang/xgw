## Интерпретация (для Codex)

1. **Шейпинг затрагивает длинные соединения с самого начала**: короткие
   запросы того же URL через тот же прокси дают 3.4–4.2 МБ/с (A/B, 1–2.7с)
   и бурсты 7–11 МБ/с на 10 МиБ (~1с), а 24-МиБ поток ограничен ~200 КБ/с
   уже в первой 5с-корзине — «бурст→спад» внутри потока не наблюдается.
   Похоже, решение шейпера принимается в первые секунды жизни соединения
   (или по его типу), а не по накопленному объёму: длительный поток
   получает лимит сразу, короткие успевают закончиться на высокой
   скорости.
2. **Запас 2.0× к битрейту 720p** достаточен для реального воспроизведения
   (без остановок), но не наращивает буфер быстрее реального времени —
   это объясняет THROTTLED по буферу (<5с) у всех линий в mpv-замерах.
3. **302 на старте одного из двух запросов** — GGC-перебалансировка
   влияет и на длинные VPN-загрузки; кандидату с follow-once это
   компенсируемо, базовой пробе — нет (совпадает с блокировками допуска
   на базе).
4. Практический вывод для профиля допуска: сустейн ~200 КБ/с —
   воспроизводимая константа пути VPN (не артефакт mpv), поддерживающая
   720p с запасом 2×; требования «большого сустейна» для 900с-фаз
   реализуемы текущим путём, буфер растёт медленно.
