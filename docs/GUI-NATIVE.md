# Нативное окно XGW (Ubuntu 24.04, PyQt6)

`xgw gui` — окно управления шлюзом на рабочем столе. Это клиент той же локальной панели, что и
браузерная (`watch/panel.py`), а не второй backend: всё состояние и все действия идут через её
HTTP API на 127.0.0.1. Браузерная панель, значок в трее, API приложения Android и CLI остаются
как есть.

## Что найдено в существующей архитектуре

Панель (`src/xgw/watch/panel.py`, класс `Panel`):

| Запрос | Что отдаёт | Доступ |
|---|---|---|
| `GET /api/state` | `Panel.state()` — всё состояние шлюза (поля ниже) | cookie панели |
| `GET /api/pool` | `Panel.pool_servers()` — сотни строк бесплатного пула, отдельно от state | cookie |
| `GET /api/traffic?days=N` | `Panel.traffic()` — расход по устройствам, подпискам, пулу, напрямую | cookie |
| `GET /records/<имя>` | файл записи трафика `.pcap` | cookie |
| `POST /api/<действие>` | `Panel.act()` → `{"ok", "text", "notes"}` | cookie + `X-XGW-Panel: 1` |
| `/api/tray`, `/api/tray/<действие>` | сводка и два действия значка | только токен трея |

Поля `Panel.state()` (сняты настоящим кодом в `tests/fixtures/gui/state-*.json`): `state`,
`action`, `since`, `updated`, `now`, `version`, `xray {ok, version}`, `capture {mode, lan, local,
lan_if, fail_mode, lifecycle, lifecycle_reason, lan_problem, inbound_missing, loaded, blocked,
bypass}`, `power {can_on, can_off, why}`, `members`, `spares`, `servers` (строки: `tag`, `name`,
`status` member/spare/disabled/skipped, `source`, `alive`, `speed_mbps`, `rtt_ms`, `delay_ms`,
`score`, `multiplier`, `priority`, `core`, `core_pin`, `capability`, `profile`, …), `removed`,
`sources`, `pin`, `main`, `sticky`, `tier`, `reserve`, `stranded`, `class_warning`, `whitelist`,
`free_pool {mode, pin, summary}`, `subscriptions`, `links`, `lan`, `kernel_direct`, `devices`,
`records`, `events`, `budget`, `nodes`, `probe_target`, `probe_hosts`, `resolvers`, `guard`,
`singbox`, `singbox_pending`, `pending_restart`, `busy {refresh, scan, speed, speed_one, cores}`,
`cores`, `speed_progress`, `netcheck`, `tailscale`, `phones`.

Действия `Panel.act()`: `power`, `pin`, `unpin`, `add`, `servers`, `priority`, `core`, `device`,
`device/route`, `direct`, `device/direct`, `record/*`, `tailscale/*`, `phones/*`, `cores/check`,
`cores/update`, `cores/rollback`, `subscription/remove`, `subscription/edit`, `link/remove`,
`freepool/mode`, `freepool/pin`, `freepool/refresh`, `sticky`, `speed/one`, `netcheck`,
`refresh`, `scan`, `speed`.

Безопасность панели, которую окно соблюдает и не ослабляет: Host только `127.0.0.1:<порт>`
(или tailnet при Serve); вход — токен или одноразовый код (`new_login`, 60 с, один раз) → cookie
`xgw_panel` = HMAC(токен); POST — только с cookie и заголовком `X-XGW-Panel: 1`, при Origin — тот
же адрес; тело до 64 КиБ.

Рабочий стол: `desktop.as_admin` (pkexec: 126 — окно пароля закрыли, 127 — пароль не принят),
`xgw panel --login` (код входа в браузер человека), `tray.py`/`trayapp.py` (значок от имени
человека, его порт и токен трея — в `~/.config/xgw/tray.json`, одна копия по блокировке).

## Как устроено окно

```
src/xgw/gui/
  model.py   — без Qt: смысл состояний (как ui/app.js), форматы, опрос, сеанс, вход
  client.py  — QNetworkAccessManager: опрос /api/state, действия, /api/pool, /api/traffic
  login.py   — pkexec → `xgw panel --gui-login` → код → cookie
  theme.py   — светлая тема по решению владельца, QSS по токенам цвета
  window.py  — окно: верхняя строка, навигация, страницы
  app.py     — `xgw gui`: один экземпляр (QLocalServer), запуск от пользователя
```

Вход: кнопка «Войти» запускает `pkexec /usr/local/bin/xgw panel --gui-login`. Команда от root
печатает одну строку JSON `{"port", "code"}` в канал вывода (не в командную строку и не в
журнал), окно меняет код на cookie запросом `/?login=<код>` (ответ 303) и хранит
`{"port", "cookie"}` в `~/.config/xgw/gui.json` (0600) — как браузер хранит ту же cookie год.
Постоянный токен панели окну не достаётся. Удалённая панель по tailnet — не в этой версии.

Вид: светлая тема, узкая навигация со значками, подсказками и Ctrl+1…8. В «Обзоре»
список серверов слева; карта стран фоном основной области, состояние и кнопка сверху,
замеры и сведения о перехвате снизу. Повторной панели навигации справа нет.
Клик, Enter или Space по серверу открывают отдельное окно со снимком данных на момент
открытия. Полное имя, состояние, скорость, задержка, протокол и профиль показываются,
когда они доступны. В списках подписок и пула действуют такие же карточки.
Закрытие карточки не переключает сервер; «Выбрать» и замер скорости — отдельные кнопки.
Карта не обращается к внешним сервисам, не угадывает точный адрес сервера и не заменяет
проверку географии выхода. Источник контуров: [Natural Earth](GUI-MAP-SOURCE.md).

Опрос: один запрос `/api/state` за раз, раз в 3 с, пока окно видно, раз в 15 с — свёрнуто;
после сбоя — 2, 4, 8 … 60 с ±20 %; ответ на 401 останавливает опрос и показывает вход. Ответ
старого запроса после смены сеанса не применяется. Действие с тем же ключом не уходит второй
раз до ответа панели; успех — только по её ответу. Закрытие окна обрывает запросы без ответа и
не трогает демон, Xray и sing-box.

## Этапы

1. Клиент API, вход, модель состояния — **готово**.
2. Каркас окна, темы, навигация, «Обзор», `xgw gui` — **готово**.
3. Серверы (подписок и пула) и подписки — **готово** (п. 333).
4. Устройства, трафик, диагностика перенесены в окно (п. 363–365).
5. Tailscale, телефоны, обновление ядер перенесены в раздел «Ещё» (п. 365).
6. Значок («Открыть XGW» → окно) и ярлык — **готово** (п. 344); автозапуск окна не делается.
7. Демо-сцены для всех экранов, проверка на Ubuntu 24.04.

«Серверы» и «Подписки» (этап 3): логика — `listing.py` без Qt, виджеты — `pages.py`.
Серверы подписок — карточки (их десятки, у каждой свои кнопки). Пул — тоже карточки, но
на виду только рабочие и допущенные, остальные — по кнопке, до 300 строк на источник;
сотни строк пула приходят из /api/pool, только пока вкладка открыта и когда демон
пересчитал сводку. Необратимое (убрать сервер, подписку, ссылку, весь дом через пул) —
с вопросом.

«Устройства»: карточки DHCP и сохранённых маршрутов из /api/state. Можно вернуть устройство
в VPN, выбрать сервер или изменить маршрут российских адресов. Исключение из config.toml
показано с пояснением. Выбор бесплатных серверов и обход VPN требуют подтверждения.
Записи пакетов доступны по кнопке перехода в браузерную панель.

«Трафик»: получено и отправлено за сегодня, 7 или 30 дней. Строки устройств, подписок и
выходов берутся из /api/traffic. Расход с множителями отделён от фактических байтов. Окно
запрашивает отчёт при выборе периода и затем примерно раз в минуту на открытой странице.

«Диагностика» показывает итог проверки сети и последние события. Кнопка запускает ту же
проверку, что в браузерной панели. В «Ещё» доступны настройки Tailscale, привязка телефонов
по QR и операции с выпусками ядер. Перед изменениями доступа и заменой ядра окно показывает
подтверждение. Коды входа и привязки видны только в сеансе панели.

В «Обзоре» под кнопкой VPN есть состояние zapret2. Нажатие открывает отдельный раздел
с кнопками сравнения с VPN, включения для выбранных доменов и выключения. Кнопка «Настроить»
меняет домены, стратегию и адреса проверок, пока режим выключен. Адреса проб вводятся скрыто,
сохранённые адреса API не возвращает. Пустые поля сохраняют прежние адреса.
Выбранный режим и фактическое состояние показаны отдельно. Есть причины недоступности кнопок,
возврата на VPN, ошибки возврата и результаты каждого запроса в сравнении. «Применение настроек»
заканчивается только после снимка демона с той же версией настроек.
Раздел требует обновления кода панели и демона вместе с окном. Старый сервер показан отдельным
сообщением. Сравнение выполняет один круг, после него режим нужно выключить для нового запуска.
HTTP-успех не означает, что подтверждено воспроизведение видео.

## Запуск

```sh
xgw gui                                   # окно (от пользователя, не через sudo)
python3 tests/panel_demo.py --gui         # демо: панель на выдуманных данных и окно, без root
QT_QPA_PLATFORM=offscreen python3 -m pytest tests/test_gui_qt.py tests/test_gui_model.py
```

Нужен пакет `python3-pyqt6` (его ставит установка XGW для значка в трее). Нет PyQt6 —
`xgw gui` пишет, что установить; браузерная панель работает и без него.

## Что можно взять у Proton VPN (идеи, не код)

Исходники github.com/ProtonVPN (GPL-3.0) читались только ради идей:

- Машина состояний соединения: «отключено → подключается → подключено → отключается»,
  ошибка — отдельное состояние с причиной; «подключается» и «отключается» оповещают
  подписчиков сразу, до работы. Окну XGW это даёт честное «Включаю…/Выключаю…» до ответа
  демона (сделано на стороне окна).
- Переподключение: пауза 2^n с ±10 %, сброс по событию «сеть появилась» (проба
  `ip route get 192.0.2.1` раз в 5 с) и по разблокировке сеанса; при отказе входа не
  повторять.
- Kill switch: отдельные таблицы nftables для inet и ip6, применение одной пачкой с
  удалением-добавлением, в конце reject (TCP RST, ICMP) вместо тихого drop — программы
  сразу видят отказ, а не ждут таймаута. Их открытые пункты (DNS на порт 53 к резолверу
  в сети, адрес сервера пропускается без метки, нет сверки правил после загрузки) стоит
  сверить с перехватом XGW отдельной задачей — здесь не проверялось.
- Смена сервера: случайный другой в той же стране, текущий — только если других нет.
