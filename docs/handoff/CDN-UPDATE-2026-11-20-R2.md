# ThinkCentre — открытие формы, замена CDN и сопоставимость снимков

Flash сама выполняет проверку на Ubuntu 24.04 LTS и публикует один
обезличенный отчёт при любом исходе. При недоступном терминале, браузере,
настоящем Qt или sudo запроси доступ и продолжи сама. Команды, критерии
и код подготовлены Codex.

В [прошлом проходе](../reports/2026-11-20T120641Z_selective-cdn-update.md)
прошли установка, API, обычная замена в веб-форме, Qt-фикстура и старт
720p через zapret2. Обновление при активном Selective и естественное
истечение адреса остались NOT_RUN. В этот раз проверь первое открытие
формы, одну сохранённую транзакцию и причину отказа сравнения снимков.

## 1. Временная установка

В том же Bash выполни §1 [ТЗ замены CDN](CDN-UPDATE-2026-11-20.md),
подставив следующий SHA в переменную `CANDIDATE` установочного блока.

```bash
CANDIDATE=946a86940ee3152d6f2e862240acb47be5394e72
```

База файлов та же, что в прошедшем отчёте. Кандидат был снят после
прошлого прогона, поэтому сверяй исходный пакет, а не временный
`187653f`. Для root начни с `sudo -n true`. Используй тот же lock и
90-минутный таймер оверлея. При блокере остановись на конкретном шаге,
после запуска таймера пройди восстановление из §4 первого ТЗ. Подготовь
приватный каталог с `umask 077`.

После установки запусти указанные там тесты под Linux и добавь
`tests/test_desync_route_evidence.py` и `tests/test_selective_probe_watch.py`.
Запусти `node --check src/xgw/ui/zapret2.js`. Проверь VPN-control в off.
Графические проверки проведи через браузер и vision.

## 2. Веб и Qt

Из браузера в авторизованной панели запиши исходную ревизию. В off/off
сохрани пару из `/t/terms` и истёкшей фикстуры из §2 первого ТЗ с
**выключенной** HTTPS-проверкой. В overview должны быть
`probe_count=2`, `can_replace_cdn_probe=true` и
`youtube_transport_probe=false`. Фикстуры используются только в off.

1. Заново открой страницу панели. Сразу нажми «Настроить». Вкладку
   «Перечитать настройки» в этом опыте не используй. Убедись, что форма
   появляется после GET overview и сразу содержит интервалы и бюджет
   из него. Адресные поля пусты. Повтори при уже начавшемся очередном
   запросе overview. Достаточно двух кликов, один на каждое состояние.
2. Удали один интервал или поставь 0, затем отправь форму. Ожидаются
   видимое сообщение в форме, отсутствие POST и сохранение черновика.
   Верни правильное число. Проверь также сообщение при попытке
   сохранить только страницу.
3. Включи в форме HTTPS-проверку, оставь страницу пустой и введи
   только второй адрес-фикстуру из прежнего ТЗ. Должен уйти один POST
   с `youtube_transport_probe=true`, `cdn_probe_url` и текущим
   `expected`. В результате одна новая ревизия, прежний `page_kind=terms`,
   новый срок CDN и состояние off/off. В публичный отчёт запиши
   только имена полей и статус. Проверку старой ревизии выполни как в
   §2 первого ТЗ. POST только с новым адресом CDN при выключенной опции без
   `youtube_transport_probe=true` должен отклоняться.
4. Проверь ту же операцию в Qt. Если установленное окно не отображает
   новую форму, в checkout используй `QT_QPA_PLATFORM=offscreen` и
   `SettingsDialog` с сохранённой парой и выключенной опцией. После
   установки флажка и заполнения только CDN `values()` должны
   содержать обе настройки. Укажи реальное окно или фикстуру.
5. Подтверди старые действия: два адреса сохраняют полную пару, очистка
   удаляет оба, смена ревизии в другом окне сохраняет старый черновик и
   блокирует запись с его `expected`.

Критерии: `WEB_FIRST_OPEN=PASS` для готовой формы без дополнительного
клика, `WEB_VALIDATION=PASS` для понятного сообщения без POST,
`ATOMIC_CDN=PASS` для одной записи из выключенной пробы. Сбой
авторизации или браузерной сессии отмечай отдельным исходом.

## 3. Снимки Xray и короткий живой контроль

Для снимков используй диагностический код из кандидата. Подготовь
корневую копию из того же закреплённого SHA, как и для прежнего `diag`.
Диагностика читает Xray, поэтому в отчёте указывай названия разделов
из `changed_sections`. Хэши разделов и снимки храни локально.

```bash
CDN_TOOLS=$(sudo -n mktemp -d /opt/xgw/handoff/cdn-update-diagnostics.XXXXXXXX)
if [[ -n $CDN_TOOLS ]] && git -C "$REPO" archive "$CANDIDATE" src/xgw |
    sudo -n tar --no-same-owner -x -C "$CDN_TOOLS" &&
   sudo -n chmod -R go-w -- "$CDN_TOOLS"; then
  snapshot() {
    sudo -n env PYTHONPATH="$CDN_TOOLS/src" "$PY" -B -P \
      -m xgw.desync.route_evidence snapshot >"$D/$1.json"
  }
  run diag-off-before snapshot diag-off-before
  run diag-off-site site
  run diag-off-after snapshot diag-off-after
  run diag-off-delta "$PY" -m xgw.desync.route_evidence delta \
    "$D/diag-off-before.json" "$D/diag-off-after.json"
fi
```

Положительный контроль — в одном процессе Xray и при неизменной
конфигурации сравнение допускается, а снимки содержат
`config_sections_sha256`. Отрицательный контроль
`test_live_snapshots_compare_reformatted_config_and_reject_routing_order_changes`
на Linux меняет порядок правил **в тестовой копии** и ожидает отказ
`field=applied_config, changed_sections=["routing"]`. Если живое окно
несопоставимо, укажи `field` и `changed_sections`. Причина считается
установленной только там, где эти сведения подтверждены.

Сетевой шаг §3 из [ТЗ замены CDN](CDN-UPDATE-2026-11-20.md) можно
выполнить одним стартом. Используй действительный адрес, полученный
штатно, и сохрани опцию с адресом одним POST. Для `trace_playback`
возьми функции из §1 [ТЗ потока](MEDIA-FLOW-2026-11-20.md), передав
в `TRACE_CODE` тот же `CANDIDATE` и используя новое `snapshot`. Прежний
принятый старт остаётся сведением из предыдущего отчёта. Для свежих
данных оцени фактические 720p, группу выхода, стабильность ревизии
и отказ сравнения, если он наблюдается. Тестовая фикстура адреса
не участвует в живых запросах.

При появлении второго действующего адреса проверь один POST замены
при активном Selective. Запиши только состояние новой ревизии.
В противном случае `LIVE_ACTIVE_UPDATE=NOT_RUN` с причиной.
`LIVE_EXPIRY=PASS` возможен только при естественном истечении внутри
выделенного окна. Продлевать окно ради него не требуется.

## 4. Откат и отчёт

Выполни §4 [ТЗ замены CDN](CDN-UPDATE-2026-11-20.md) даже при
неудаче. Подтверди хэши временной установки после отката, off/off,
активный демон, рабочий VPN и остановленный таймер. В отчёте укажи
`INSTALL`, `WEB_FIRST_OPEN`, `WEB_VALIDATION`, `ATOMIC_CDN`,
`QT`, `SNAPSHOT_DIFF`, `LIVE_PLAY`, `FLOW`, `LIVE_ACTIVE_UPDATE`,
`LIVE_EXPIRY` и `RESTORE`. Укажи SHA, проверенные формы, реальные
времена и степень подтверждения. Ссылки CDN, IP, идентификаторы,
cookie и сырые снимки остаются на машине.

Для автоматической публикации используй §3 [ТЗ пересчёта](MEDIA-COUNTERS-2026-11-20.md)
с суффиксом `_selective-cdn-update-r2.md`. Опубликуй при любом исходе
и укажи ссылку на доступный коммит.
