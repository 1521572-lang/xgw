# Батч 1: контракт zapret2 и миграция

Целевая система: Ubuntu 24.04 LTS. Разработка и переносимые тесты: Windows 11.
База backend: gui-light, 48f7ebae15096c40aaa4b82b7f3b19488ab24dd3.
Источник GUI-накладок: freepool, 7c20f59023ec39e5c5ce4606767ea915c3b91f64.
Этот батч не переносит сетевые режимы freepool, не запускает автоподбор и не меняет nft.

## Политика

`src/xgw/desync/schema.py` — чистые функции без ОС, subprocess и сети.
`migrate(settings, source="freepool" | "gui-light")` переводит старую секцию `[zapret2]`
в полный документ v1. Для частичных старых настроек обязательно указывать источник:
списки доменов по умолчанию у веток различаются. `migrate(policy)` проверяет полный документ;
повторная миграция идемпотентна. Чтение не переписывает config.toml или panel.json.

```json
{
  "schema_version": 1,
  "selected": {
    "mode": "off",
    "domains": ["domain:youtube.com", "domain:googlevideo.com"],
    "strategy": "multisplit",
    "probe_urls": [],
    "check_seconds": 180,
    "retry_seconds": 300,
    "daily_probe_mb": 256
  },
  "engine": {
    "engine": "off",
    "engine_profile": "seqovl",
    "engine_offload": true
  },
  "runtime": {
    "binary": "/opt/xgw/zapret2/1.0.7/nfqws2",
    "lua_dir": "/opt/xgw/zapret2/1.0.7/lua",
    "blob_dir": "",
    "queue_num": 200,
    "engine_queue": 200,
    "probe_port": 19999
  }
}
```

В TOML это `[desync]`, `[desync.selected]`, `[desync.engine]`, `[desync.runtime]`.
В panel.json это объект `desync`. Он содержит приватные probe_urls и остаётся в файле 0600.
В публичный API весь объект не передавать. Разрешён только непрозрачный fingerprint.

Порядок применения:

1. Старые поля TOML и полный `desync` в том же TOML обязаны совпадать по явно заданным полям.
2. Полный `desync` из panel.json заменяет нижестоящую политику TOML.
3. Без полного документа панели её старый частичный `zapret2` дополняет/переопределяет TOML.
4. Внутри panel.json два представления также должны совпадать; неизвестные поля/версии,
   неправильные типы и конфликт не игнорируются.
   Повреждённый/нечитаемый panel.json теперь также отклоняется через ConfigError: иначе
   потеря сохранённой политики могла бы незаметно активировать настройки из TOML.
   Это намеренное изменение прежнего поведения «предупредить и игнорировать файл».
5. `Config.desync` хранит желаемую политику. `Config.zapret2` — проекция для текущего runtime;
   прежняя проверка сетевых предпосылок остаётся. Если она пытается выключить/изменить
   выбранный режим, загрузка завершается ConfigError: выключение selective не должно
   незаметно активировать engine=auto. Снимок демона содержит хэш его эффективных настроек.
   Несовпадение с новой конфигурацией панели показывается как pending, не активный новый режим.

`project(policy, target=...)` экспортирует старую секцию без изменения смысла.
В действующем backend T04 поддерживает standalone и дополнительные selected-стратегии
в Selective. Compare принимает две стратегии с Lua-трассировкой, multisplit и multidisorder.
При mode=off любая **известная схеме** selected-стратегия
сохраняется без замены и в документе, и в Config.zapret2. Это не разрешение её запуска:
попытка включить неподдерживаемую стратегию по-прежнему завершается ошибкой до сохранения
или загрузки. Неизвестная стратегия не принимается даже при off. Отдельный engine сохраняет
своё явно заданное состояние; off выбранных доменов сам по себе не выключает engine=auto.
Хэши желаемой и эффективной политики совпадают и для сохранённой выключенной стратегии.
В freepool отклоняются непредставимые настройки отдельного engine. Сама миграция их
сохраняет: отказ относится к активации/экспорту, а не к потере исходного документа.
Различающиеся `strategy=seqovl` и `engine_profile=seqovl` не объединять: параметры различны.
`engine=auto` вместе со standalone/selective/compare сохраняется; runtime подавляет engine,
пока включён контроллер выбранных доменов. Этот батч не разрешает два worker на queue 200.

`managed.set_desync()` сохраняет полную поддерживаемую политику под существующей файловой
блокировкой. Повторное сохранение не пишет файл. Функция не выставлена как HTTP-команда.
Новый формат нельзя отдавать старому backend, который его игнорирует: перед откатом
сохранить/восстановить прежние файлы или явно экспортировать поддерживаемую секцию.
Пути Ubuntu разбираются через PurePosixPath; реальные операции с локальными файлами
config.toml/panel.json используют Path на машине, где они выполняются.

## Карточка `/api/state.zapret2`

Карточка всегда присутствует в ответе авторизованного `/api/state`. GET ничего не запускает.
Отдельный endpoint/CRUD не добавлены: это работа последующих батчей.

| Поле | Контракт |
|---|---|
| schema_version | 1 |
| mode / engine_mode | Настройки двух старых контроллеров, не доказательство маршрута |
| source | selected при включённом selected-режиме, иначе engine |
| state | off/active/absent/error/unknown/pending/preparing/blocked/fallback/compared |
| fresh / observed_at | Свежесть снимка демона, а не время HTTP-ответа; предел 90 с |
| config_key / policy_matched | Хэш желаемой политики и совпадение с эффективной конфигурацией демона |
| strategy | Подтверждённый активный профиль; null без подтверждения |
| configured_strategy | Настроенный профиль, может отличаться от фактического engine-профиля |
| worker.profile / queue | Наблюдения только из свежего совпадающего снимка |
| without_vpn | Не выводится из готовности worker; в gui-light этого батча false |
| counters | Все значения null: счётчики ещё не инструментированы |
| evidence | transport=unknown, playback=not_tested; worker active не означает видео PASS |
| can_off / can_edit | false, POST-команд управления в этом батче нет |
| blockers / capabilities | Явное отсутствие управления, чтобы старый GUI не предложил неработающий POST |

Универсальный engine: fallback -> error, off+not_found -> absent.
Для selected fallback требуется подтверждение закрытия прямого gate; доступность VPN
из этого не следует. Нет ревизии в старом снимке -> unknown; новая ревизия -> pending.
Просроченные, будущие и некорректные timestamps не подтверждают состояние.
Причины берутся из allowlist, argv/URL/произвольная ошибка worker в API не попадают.

`zapret2_policy_key` в status.json подтверждает конфигурацию наблюдения.
`zapret2_reservation` содержит unit, queue и generation текущего владельца слота или
null. Generation растёт при каждой новой резервации в рамках процесса демона. Слот занят
с начала запуска до подтверждённой остановки и восстановления offload. Для готовности
engine проверяется MainPID → inode сокета → port ID → номер NFQUEUE. Selected дополнительно
требует подтверждения маршрута и срока gate. Поле `without_vpn` в T04 подтверждает
готовность Standalone по свежему снимку. Оно требует применённой конфигурации без
обхода через VPN, остановленных VPN-мостов XGW, готового worker, правил и gate.
`evidence.vpn_control` показывает результат отдельной служебной VPN-пробы после возврата.
`vpn_control_reason` содержит код результата или невыполненного условия, `vpn_control_at` —
время исходной проверки. Во время ожидания повтора у Selective сохраняется исходный результат
при закрытом gate и снятом прямом правиле. Панель показывает его из свежего снимка с совпавшей
политикой; успешное подключение по пробе относится к выбранному HTTPS URL и VPN-участнику.

`selected.observe_synack` — опциональный флаг T05. При отсутствии или false действует прежний
формат политики и сохраняется её fingerprint. Включение добавляет в ту же очередь zapret2
отмеченный IPv4 SYN/ACK при живом gate. Пакетная метка выбранного выхода, fake-bit и бит
conntrack для рукопожатия выполняют разные задачи. Флаг не меняет стратегию, sysctl и offload.
Формат proc опирается на исходники
[NFQUEUE](https://github.com/torvalds/linux/blob/master/net/netfilter/nfnetlink_queue.c) и
[netlink](https://github.com/torvalds/linux/blob/master/net/netlink/af_netlink.c).

## GUI

gui-light не содержит всего нового Proton GUI. Здесь находятся две накладки на принятый
freepool GUI: `vpn_ui/xgw/overview.py` и `src/xgw/gui/zapret2.py`. Их нельзя выдавать за
самостоятельный GUI-дистрибутив. NEXT_STEP требует проверить фактический установленный
frontend и применить накладки к его отдельному дереву с резервной копией.
Если GUI ещё не установлен, проверять полный закреплённый GUI checkout с накладками;
такой результат обозначать PREVIEW, не INSTALLED_GUI_PASS.

## Локальная проверка

```powershell
python -m pytest --portable tests/test_desync_schema.py tests/test_zapret2_panel.py
```

Режим разрешает только эти явно перечисленные файлы. Linux-модули на Windows имеют
импортные заглушки, которые падают при попытке системной операции. Subprocess и сетевые
соединения запрещены фикстурой. Файловая блокировка в тесте записи политики замокана;
проверку настоящего flock, прав 0600 и systemd выполнить на Ubuntu.

Полный старый набор остаётся Linux-only. Обновлена ожидаемая реакция старого теста
test_toml_validation_and_separate_marks: неизвестная стратегия теперь ConfigError,
а не молчаливое выключение режима при загрузке.
