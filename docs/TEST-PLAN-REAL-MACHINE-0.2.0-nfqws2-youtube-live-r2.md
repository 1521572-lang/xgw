# ThinkCentre. Исправленные TLS-профили и прямое видео YouTube

Прогон завершён, [отчёт r2](TEST-REPORT-REAL-MACHINE-0.2.0-nfqws2-youtube-live-r2-2026-11-14.md) — FAIL.
Следующее основное задание — [расширенный проход r3](TEST-PLAN-REAL-MACHINE-0.2.0-nfqws2-youtube-live-r3.md).

Ветка `gui-light`. CODE = `ad76983eadb2ebd6a8ffc32739895065d140e919`.
BASE = `c7500f6f40bdfbc9d16b1b23056063813a71a839`, установлен по r5.
[Последний отчёт](TEST-REPORT-REAL-MACHINE-0.2.0-nfqws2-youtube-live-2026-11-14.md) — FAIL.
В аргументах XGW отсутствовал `--new`, поздний UDP-фильтр исключал TLS из обработки.
Предыдущий прогон не доказывает неэффективность трёх TLS-стратегий. Исправляем границы
профилей и проверяем seqovl, hostfakesplit-md5, fakedsplit-md5 в одном сеансе.
MD5-кандидаты взяты из [частично успешного r6](https://github.com/1521572-lang/xgw/commit/65c3756).
Цель — воспроизведение видео по WAN через zapret2, без VPN для страницы и видеоданных.

## 1. Исполнитель и пределы прогона

Модель сама выполняет команды, установку, работу в браузере с vision, анализ и публикацию.
При недоступности терминала, root или браузера запросить доступ и продолжить самостоятельно.
Не предлагать владельцу запускать команды. Пароль и системный диалог подтверждает владелец.
Задание владельца разрешает этот ограниченный перебор и возврат машины после него.
Временные direct-домены затронут YouTube всех клиентов, универсальный движок — подходящие
потоки Xray/sing-box. Остальной VPN продолжает работать. Это доказывает независимость пути
YouTube от VPN, но не работу всей сети при полностью остановленном VPN-ядре.
Разрешены замена одного модуля, перезапуск только демона, временные настройки ниже,
узкая трассировка и штатный `xgw apply --now`, если применение маршрута отложено.
Последний может перезапустить Xray. Зафиксировать причину и PID, не повторять без нужды.
Не обновлять ядра/зависимости, не менять offload, подписки, выбранный сервер и общую политику.
При ухудшении контрольного HTTPS/VPN, чужой очереди или ошибке возврата остановить перебор.

## 2. Подготовка и установка одного модуля

```bash
set -eu
umask 077
git fetch origin gui-light
CODE=ad76983eadb2ebd6a8ffc32739895065d140e919
BASE=c7500f6f40bdfbc9d16b1b23056063813a71a839
PLAN=$(git rev-parse FETCH_HEAD)
git merge-base --is-ancestor "$CODE" "$PLAN"
D=$(mktemp -d "$HOME/xgw-youtube-r2.XXXXXXXX")
git worktree add --detach "$D/source" "$PLAN"
git -C "$D/source" rev-parse HEAD
cd "$D/source"
PYTHONPATH=src:. python3 -m pytest -p no:cacheprovider -o addopts= -q tests/test_nfqws2.py
```

Использовать имеющееся окружение pytest. Ожидается 26 PASS, subtests считаются отдельно.
При отсутствии pytest не устанавливать пакеты, записать NOT_RUN тестов и продолжить.
При падении — STOP до замены. Для установки брать **только** `src/xgw/nfqws2.py` из CODE,
даже если PLAN новее. Бинарник и Lua остаются установленными.
Сохранить приватно конфиги и panel.json с правами, SHA установленного модуля, applied JSON,
PID Xray/демона, очередь, nft-таблицы, `nf_conntrack_acct`, полный `ethtool -k` WAN.
Проверить HEALTHY и контрольный HTTPS через обычный VPN. Движок и selective исходно off.
Путь модуля определить по Python из ExecStart xgw.service, не угадывать каталог установки.
Сверить модуль с BASE. При другом коде проверить совместимость, не затирать неизвестные правки.
Сохранить резервную копию, установить модуль из CODE с root:root и штатными правами,
сверить SHA. Перезапустить xgw.service, проверить здоровье и PID Xray. При сбое вернуть копию.

До включения очереди проверить аргументы на установленном nfqws2. В root-терминале задать
CFG абсолютным путём действующего конфига, PY — Python сервиса, D — приватным каталогом.
Использовать установленный модуль, выйти из source, не задавать PYTHONPATH.

```bash
cd "$D"
env -u PYTHONPATH "$PY" - "$CFG" >"$D/preflight.txt" 2>&1 <<'PY'
import subprocess, sys
from xgw.config import load
from xgw.nfqws2 import arguments, find_installation
cfg, warnings = load(sys.argv[1])
inst = find_installation(cfg)
assert inst is not None, "nfqws2 installation missing"
for name in ("seqovl", "hostfakesplit-md5", "fakedsplit-md5"):
    args = arguments(cfg, inst, name)
    print(name, args, flush=True)
    subprocess.run([*args, "--debug=1", "--intercept=0"],
                   check=True, timeout=15)
PY
```

`--intercept=0` проверяет Lua и параметры без привязки очереди. Во всех трёх запусках
должно быть 2–4 пользовательских профиля, отдельно TLS и QUIC, опционально голос/STUN.
В TLS-блоке должен оставаться `--filter-l7=tls`. Это проверка конфигурации, ещё не обхода.
При ошибке — STOP с причиной, возврат модуля и публикация, без самовольной правки Lua.

## 3. Один прямой путь для контроля и кандидатов

Временно добавить к существующему `[routing].direct_domains`, не заменяя список,
`domain:youtube.com`, `domain:googlevideo.com`, `domain:youtubei.googleapis.com`,
`domain:youtube-nocookie.com`. Проверить применённый JSON, а не только config.toml.
Страница и CDN должны идти в `direct`/freedom с `capture.mark_bypass`, до catch-all VPN.
Если применение отложено из-за dns, один раз выполнить `xgw apply --now`, дождаться
применения и проверить здоровье. При возврате разрешён такой же apply по необходимости.
Убедиться, что kernel_direct, proxy_domains или частное правило не меняет этот путь.
Не добавлять VPN fallback. Сохранить режим перехвата, временно `nf_conntrack_acct=1`.
Во всех опытных фазах `[zapret2] mode="off", engine="auto"`. Конфиг редактировать
штатно, без дублирования TOML-секций. engine_offload не менять, disorder не запускать.
Сверять active worker, номер очереди, фактический профиль и `/proc/<worker PID>/cmdline`.
Обученный профиль VPN-сервера может иметь приоритет над engine_profile. Если ожидаемый
профиль не применился, выяснить причину, отметить кандидат NOT_RUN, не засчитывать чужой профиль.

## 4. Короткий перебор до первого работающего варианта

Выбрать публичный ролик ≥30 минут, с 1080p, без аккаунта/ограничения возраста/эфира.
URL хранить приватно. Использовать тот же ролик, маршрут и качество во всех фазах.
Браузер — установленный Chrome/Chromium от пользователя графической сессии, новый профиль
для каждой попытки, `--no-proxy-server --disable-quic --user-data-dir=<новый каталог>`.
DevTools Network, Disable cache, окно видимое, sandbox и TLS-проверку не выключать.

| Порядок | Настройка | Проверка |
|---|---|---|
| A | engine=off | Свежий старт страницы/ролика, до 90 с. Зафиксировать отказ либо первые видеокадры. |
| B1 | engine_profile=seqovl | Исправленный TLS-блок, до 90 с на свежий старт. |
| B2 | engine_profile=hostfakesplit-md5 | Только если B1 не дал полного успеха. `hostfakesplit:midhost=midsld:tcp_md5`. |
| B3 | engine_profile=fakedsplit-md5 | Только если B2 не дал полного успеха. `fakedsplit:pos=midsld:tcp_md5`. |

Для каждой фазы сохранить время, effective argv, PID, ошибки и контрольный HTTPS.
Дополнительно один короткий curl к странице с `--noproxy '*' --http1.1 --connect-timeout 8
--max-time 20`, без `-k`, вывод в приватный файл. Отдельно отличать DNS, TCP и TLS.
Ошибка curl не отменяет браузерную пробу — ClientHello отличается. Не зацикливать запросы.
При первых кадрах перейти к §5 сразу, без нового задания. Если длинный прогон провалился,
проверить здоровье и перейти к следующему кандидату. После полного успеха перебор завершить.
Если все три не прошли, выполнить только диагностику §6, вернуть машину и опубликовать FAIL.

## 5. Длинное видео и доказательство пути

У кандидата с первыми кадрами сначала определить CDN и новый TCP-кортеж медиапотока,
затем начать засчитываемый сеанс в ещё одном чистом профиле. Смотреть 15 минут с начала,
перемотать за пределы буфера (ориентир 20:00) и смотреть ещё 5 минут. Рекламу не учитывать.
Модель наблюдает кадры/позицию и «Статистику для сисадминов» на 0/5/10/15 минутах,
после перемотки и в конце, измеряет паузы >2 с. Первые кадры ≤90 с, восстановление после
перемотки ≤30 с, без фатальной ошибки и непрерывной буферизации >30 с дают PLAYBACK=PASS.
Требуется 1080p либо 720p, если 1080p у выбранного ролика отсутствует, HTTP/2 или HTTP/1.1.
Снижение качества после сбоя отметить отдельно, не выдавать за PASS исходного качества.

По §4 [первого ТЗ](TEST-PLAN-REAL-MACHINE-0.2.0-nfqws2-youtube-live.md#4-доказательство-пути-в-фазе-b)
связать новый `videoplayback` с видеотреком, сокет Xray к CDN на WAN и NFQUEUE этого же
TCP-кортежа. Сначала узкая nft-трассировка, затем свежий старт браузера. Помощник из PLAN
`docs/helpers/nfq_video_trace.py`, SHA-256
`d157e31a79ad96fccf69ff9e66866b8b0d724202a504f8d3ef738e6f40dab4a2`.
Выполнять только процедуру доказательства пути из старого ТЗ, выбранный профиль не заменять
на seqovl. Общую дельту NFQUEUE и произвольные rawsend не считать доказательством TLS/видео.
При старте и после перемотки подтвердить новые сетевые видеоданные, рост входящих байтов
прямого WAN-сокета и неизменность маршрута. При смене соединения привязку повторить.
Неполное доказательство — PARTIAL, даже при плавном видео. Свою nft-таблицу удалить.
Если A не играла, а B прошла, повторить engine=off в свежем профиле (A2, ≤90 с).
Повторный отказ при неизменном direct даёт BENEFIT=OBSERVED, иначе UNCONFIRMED.

## 6. Если все кандидаты не прошли

Не повторять долгие просмотры и не перебирать параметры без границ. Оставить один
hostfakesplit-md5 на короткое окно ≤45 с, проверить его argv и отдельный TLS-блок.
Одновременно со свежим стартом браузера снять приватный pcap только WAN TCP/443
к одному наблюдаемому IP страницы, через уже имеющийся tcpdump/tshark, и nft-след
этого же кортежа по процедуре §5. Если IP сменился — одно повторное окно, затем завершить.
В pcap искать ClientHello, fake-сегмент с TCP MD5 option, ответ/таймаут/сброс по времени.
Если инструмента нет — отметить NOT_RUN наблюдения, пакеты не устанавливать.
Отдельно проверить журнал worker на EPERM в эти секунды. Разделить в выводе
«не дошло в очередь», «дошло, обработка не подтверждена», «MD5 fake наблюдался, TLS не прошёл».
rc0 rawsend не доказывает приём удалённым сервером, RST/таймаут не доказывает отправителя блока.
Сырые следы, адреса и кадры пакетов не публиковать. Новый обход в рамках этого прогона не писать.

## 7. Возврат и обязательная автопубликация

Закрыть свои браузеры, вернуть исходные конфиги с правами, panel.json и acct, дождаться
применения маршрута, при необходимости штатный apply. Сверить отсутствие временных direct,
worker/очереди/таблиц, полный ethtool, HEALTHY и контрольный HTTPS/VPN. Зафиксировать PID.
Исправленный модуль оставить, если его установка/работа не дала регрессии, даже когда обход
не найден. При регрессии вернуть резервный модуль и перезапустить только демон. Указать итоговый SHA.
При сбое возврата сначала восстановить доступную исходную конфигурацию и отдельно описать FAIL.

Автоматически при любом исходе сохранить
`docs/TEST-REPORT-REAL-MACHINE-0.2.0-nfqws2-youtube-live-r2-ДАТА.md` в `gui-light`.
Одна таблица A/B1/B2/B3/A2 с TLS/страницей/видео/фактическим профилем, CODE/PLAN,
PLAYBACK/DIRECT/NFQ_VIDEO/BENEFIT, качество, длительности, возврат и короткий вывод.
PASS требует PLAYBACK, DIRECT и NFQ_VIDEO=PASS. При недостающей привязке — PARTIAL,
при отказе корректно испытанных кандидатов — FAIL, при недоступных условиях — NOT_RUN.
Не делать вывод «zapret2 невозможен» по конечному набору кандидатов. Непроверенные строки — NOT_RUN.
В чистом дереве свежей origin/gui-light добавить только обезличенный отчёт, проверить diff,
commit и обычный push, сверить удалённый SHA, дать ссылку. Подтверждение публикации не запрашивать.
Конфиги, URL, имена, адреса, HAR, pcap и полные логи оставить в приватном каталоге.

Семантика границ профилей и Lua — [руководство закреплённого zapret2 1.0.7](https://github.com/bol-van/zapret2/blob/038c97e5819df10f8e8c22a2f1fffe57f2f7379b/docs/manual.md#использование-множественных-профилей).
