## Наблюдения

1. **В запрос подписки попасть не удалось за 3 попытки.** По программе это не дефект (шаг 3 проверяет то же на установленном коде), но причина видна в коде: запрос из панели `request_refresh()` только ставит отметку и будит шаг watchdog (`daemon.py:424–429`), а сам опрос исполняется внутри `tick()` (`daemon.py:631–645`) — уже после проверок состояния и проб. Перезапуск через 0,3 с после ответа панели приходится на начало шага, до сетевого запроса, поэтому отменять ещё нечего.

2. **Из чего состоит остановка 2,26–2,81 с.** Цикл демона завершается быстро: строка «демон XGW остановлен» появляется примерно через 0,5 с после `Stopping`. Дальше около 2,2 с процесс закрывает HTTP-сервер панели (`cli.py:719–742` → `panel.stop()`, `watch/panel.py:259–266`) — это попадает в «остановку» для systemd, хотя к опросу подписок отношения не имеет. Порог программы (< 3 с) пройден, но запас невелик: если закрытие панели подрастёт, порог будет задет.

3. Отметка «доли секунды» из ASSUMPTIONS п. 216 на этой машине подтверждается на уровне запроса: событие остановки выставлялось через 1 с, ответ `Cancelled` приходил на 1,00–1,07 с, то есть реакция практически мгновенная. Полное время `systemctl restart` больше из-за пункта 2.

4. `WARN — 1` в `diag` одинаков до и после установки: «Система: Ubuntu 24.04.5 LTS, Python 3.12 — XGW проверялся только на Ubuntu 26.04». К испытанию отношения не имеет, поведение не изменилось (23 OK, 1 WARN, 0 FAIL).

5. Каталог кода: программа предполагает `~/xgw`, на машине клон лежит в `/home/xxx/zcod/xgw` — использован он. Ветка `install-d1d2`, код `f985921`, версия `0.1.15` — совпадают с ожидаемыми. Других отклонений от программы не было.
