  публикуются как **`preparing`** при закрытом прямом маршруте; новый тест
  закрепляет `{"state": "preparing", "reason": "vpn_stopping",
  "gate_closed": True}`.
- Хелпер: ждёт до 120 с, логирует каждую смену фазы и причины
  (`standalone_progress`), `blocked` с переходной причиной не считает

  `standalone_not_ready` — тест `queue_busy` проверяет, что причина
  попадает в вывод.
- Смена режима в процессе ожидания даёт `unexpected_mode`; истечение
  дедлайна — `standalone_deadline` с последней фазой и причиной.
- Это закрывает замечания 1 и 11 отчёта r2 и бо́льшую часть замечания 2:

## §3 Возврат управляемого поколения (`managed-contract`)

Контракт на фиктивном шлюзе подтвердил всю цепочку:

- после остановки мостов намерение вернуть управляемое поколение
  сохраняется (`resume_managed`), маркер managed-режима снят;
- базовый sing-box поднимается первым; повторное применение того же
  конфига требуется только пока действует признак возврата;
- шаг демона запускает возврат не чаще интервала повтора;
- отказ проверки кандидата оставляет работать базовый юнит, не обращается
  к API Xray и сохраняет признак ожидания;
- после успешной проверки и применения через API состояние становится
  `blue` или `green`, признак очищается, базовый юнит переходит в штатный
  drain, маркер восстановлен.
