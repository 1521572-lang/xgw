# Проверка YouTube и маршрута на установленном XGW

ThinkCentre, Ubuntu 24.04 LTS amd64. Рабочая база `08d31ee`, инструменты
`402cda1ca6494698d423b0e1d3dc45ab1f7f2fca`. Flash сама выполняет команды,
проверяет интерфейс через vision и автоматически публикует один новый отчёт.
При отсутствии терминала, sudo, браузера или авторизованной панели сама
запрашивает доступ. Код и критерии готовит Codex. Выполняй проверки из checkout.
Пакет шлюза уже установлен. [Результаты предыдущего прохода](../reports/2026-11-19_admission-matrix.md)

Цель — получить на одной политике 900 секунд пригодного видео 720p и ещё 300
после перехода за буфер, связать передачу с выбранным выходом, проверить обычный
сайт через VPN. Отдельный исход каждого этапа обязателен даже при блокере.

## 2. Контроль браузера и возврат политики

Выбери публичный обычный ролик длительностью более 35 минут с доступным 720p.
Присвой `VIDEO` его ID из адресной строки. Все сравнения проведи на одном
ролике, в видимом Chrome, при скорости 1×, с выключенным QUIC. Сборщик создаёт
отдельный временный профиль для каждой попытки и выбирает момент запуска по
состоянию медиаплеера. Flash через vision обслуживает consent и выставляет 720p.
Пока идёт запись, оставь вкладку видимой. Не нажимай F5 и k во время замера.

```bash
test "${#VIDEO}" -eq 11
trial() {
  local label=$1 phase=$2 attempts=$3
  shift 3
  "$BROWSER_PY" -m docs.helpers.youtube_telemetry --verify "$phase" --attempts "$attempts" \
    --video "$VIDEO" --height 720 --disable-quic --label "$label" --out "$D/$label" "$@" \
    >"$D/$label.log" 2>&1 || return $?
}
if trial vpn-desktop control 2 --desktop-chrome; then echo VPN_PLAYER_OK; else echo VPN_PLAYER_FAILED; fi
```

Сохрани длительность, failed_checks и исход **каждой** попытки из
`$D/vpn-desktop/verification.json`. Для FAIL до получения файла прочитай
приватный лог. При провале контроля выполни один короткий `trial vpn-launcher
control 1` в стандартном режиме Playwright. Если повторяется ошибка плеера,
сверь тот же ролик в [обычном Chrome без подключения сборщика](YOUTUBE-TELEMETRY.md#замер-в-обычном-chrome).
Если работает только один способ запуска, используй его для всех последующих
автоматизированных сравнений и явно назови. При провале обоих автоматизированных
контролей опубликуй результат диагностики браузера. Это самостоятельный исход.
Запиши приватно IPv4 выхода VPN по свежему запросу к известному сервису проверки
адреса вне доменов YouTube, доступному через установленный VPN. Повтори тот же
запрос в Selective и после возврата.

```bash
vpn_address() {
  curl -4fsS --noproxy '*' --connect-timeout 5 --max-time 15 https://api.ipify.org \
    | "$PY" -c 'import ipaddress,sys; print(ipaddress.IPv4Address(sys.stdin.read().strip()))'
}
vpn_address >"$D/vpn-before.ip"
```

Если этот сервис недоступен, возьми прежний рабочий сервис определения IPv4 и
используй его последовательно в трёх окнах. Запрос идёт из клиентской области
перехвата XGW. При перехвате только LAN выполняй контроль с тестового LAN-клиента.

Перед любым изменением политики возьми прежний общий lock, сохрани настроенный
panel.json и вооружи независимый возврат. Работай из того же shell.

## 4. Длительное воспроизведение, перемотка и путь

Продолжай при свежем active/https_reachable. Число очереди бери из
`worker.queue` текущей карточки. Веди монитор состояния, отдельно снимай
не более 180 с коротких пар на каждую фазу. Сбор начинается до видео. При
возобновлении после неудачной попытки используй новое окно измерения пути,
если прежние пары относятся только к первому запуску.

```bash
live
"$PY" -m xgw.desync.client status >"$D/active.json"
QUEUE=$("$PY" - "$D/active.json" <<'PY'
import json, sys
v = json.load(open(sys.argv[1]))
assert v["fresh"] and v["policy_matched"] and v["mode"] == "selective" and v["state"] == "active"
assert v["evidence"]["transport"] == "https_reachable" and type(v["worker"]["queue"]) is int
print(v["worker"]["queue"])
PY
)
"$PY" -m xgw.desync.client monitor --output "$D/active.jsonl" --seconds 4800 --interval 15 &
MON_PID=$!
pairs() {
  sudo -v
  sudo -n env PYTHONPATH=/opt/xgw/lib "$PY" -B -P "$BACKUP/watch.py" \
    --queue "$QUEUE" --seconds 180 --media-pairs --socket-stats >"$D/$1.jsonl" &
  PAIR_PID=$!
}
observed_trial() {
  local phase=$1 label="$PROFILE-$1" player first second='' rc=0
  live || return 4
  pairs "$label-1"
  first=$PAIR_PID
  sleep 12
  trial "$label" "$phase" 2 "${LAUNCH[@]}" &
  player=$!
  while kill -0 "$player" 2>/dev/null; do
    if [[ -d "$D/$label/attempt-2" ]]; then
      pairs "$label-2"
      second=$PAIR_PID
      break
    fi
    sleep 1
  done
  wait "$player" || rc=$?
  wait "$first" || echo "Первое окно маршрута неполно"
  if [[ -n "$second" ]]; then wait "$second" || echo "Второе окно маршрута неполно"; fi
  return "$rc"
}
if observed_trial long; then echo LONG_OK; else echo LONG_FAILED; fi
```

Сверь время попытки с монитором и парой фона. При успешном long, прежнем
профиле и active выполни следующий блок. При неудаче вернись к короткому
VPN-контролю после возврата. Один запасной кандидат допустим, если его два
pass свежи и до возврата остаётся достаточно времени на полный измеряемый
интервал. Сохраняй новые каталоги/имена файлов для каждого кандидата.

```bash
live
if observed_trial seek; then echo SEEK_OK; else echo SEEK_FAILED; fi
```

Следующая команда сопоставляет каждую попытку с её собственным окном. В
`media_bytes` попадают приращения с IP и временем события из Chrome. Сумма
при закрытии запроса, попадания в кэш и неизвестные адреса в этот ряд не входят.
На экран выводятся только счётчики. Результат с совпадением ещё требует проверки
фона, служебных проб и обычного VPN в том же интервале.

```bash
"$PY" - "$D" "$PROFILE" <<'PY'
import json, sys
from itertools import pairwise
from pathlib import Path
root, profile = Path(sys.argv[1]), sys.argv[2]
for phase in ("long", "seek"):
    label = f"{profile}-{phase}"
    for attempt in (1, 2):
        net = root / label / f"attempt-{attempt}" / "network.jsonl"
        watch = root / f"{label}-{attempt}.jsonl"
        if not (net.is_file() and watch.is_file()):
            continue
        events = [e for line in net.read_text().splitlines()
                  if (e := json.loads(line)).get("kind") == "media_bytes"]
        snapshots = [json.loads(line) for line in watch.read_text().splitlines()]
        matches = accepted = 0
        for left, right in pairwise(snapshots):
            pair = right.get("media_pair", {})
            if pair.get("state") != "accepted":
                continue
            accepted += 1
            if pair["probe_before"] != pair["probe_after"]:
                continue
            old = {s["socket"]: s for s in (left.get("tcp") or {}).get("sockets", [])}
            peers = set()
            for s in (right.get("tcp") or {}).get("sockets", []):
                prior = old.get(s["socket"])
                if prior and prior["peer_ip"] == s["peer_ip"] and all(
                    isinstance(r.get("bytes_received"), int) for r in (prior, s)
                ) and s["bytes_received"] > prior["bytes_received"]:
                    peers.add(s["peer_ip"])
            total = sum(e["encoded_bytes"] for e in events if e["remote_ip"] in peers and
                        pair["start_unix"] <= e["start_unix"] <= e["end_unix"] <= pair["end_unix"])
            if total:
                matches += 1
                print(label, attempt, pair["start_unix"], pair["end_unix"], total,
                      pair["nft_packets"], pair["queue_sequence_delta"], pair["groups"])
        print(label, attempt, "accepted_pairs", accepted, "time_and_socket_matches", matches)
PY
```

- **Видео.** Для long/seek анализатор требует 900/300 пригодных секунд,
  прогресс ≥98%, 720p ≥95%, пропуски выборки ≤5 с, ≥1 МиБ новых медиабайтов.
  Во второй фазе он проверяет событие seeked в запрошенной точке за буфером.
  PASS после повтора записать вместе с первым исходом. Время двух попыток
  складывать нельзя. Для ошибки без установленной причины указать видимое
  сообщение, время и состояние сети/буфера. Vision дополняет журнал плеера.
- **Маршрут.** В каждой фазе сопоставь Unix-время samples, network.jsonl и
  [коротких пар](T12-SELECTIVE-MEDIA-PAIRS.md). Нужны новая медиапередача,
  совпавший адрес помеченного сокета, прирост downlink/очереди сверх фона вне
  служебной пробы, прежние ревизия и воркер. Обычный сайт одновременно открывается
  с тем же VPN-выходом. Во время каждой фазы повтори `vpn_address` в приватный
  файл и проверь совпадение с `$D/vpn-before.ip` через `cmp -s`. Укажи
  CONFIRMED, PARTIAL или UNKNOWN и недостающее поле
  отдельно для long и seek. Переход в fallback во время ролика фиксировать по времени.
- **Восстановление.** Только после подтверждённых фаз проверь отказ выбранного
  воркера штатной командой `sudo systemctl kill --kill-whom=main --signal=SIGKILL xgw-zapret2.service`.
  Перед этим проверь MainPID и принадлежность очереди Selected. Проследи снятие
  правила, fallback и новый CDN-сеанс через VPN. Доставку подтверждают свежие
  байты и маршрут. Если доказательство неполно, зафиксируй конкретный пробел.
- **Сутки.** При успехе обеих фаз, пути, обычного VPN и восстановления допускается
  уже запланированное наблюдение Selective. Прежние 18,51 ч закрыты как
  NOT_COMPLETED. Для нового окна сначала верни off, затем до включения Selective
  вооружи отдельный таймер на 26 ч на тот же возврат конфигов. Готовая команда ниже.
  При другом исходе сразу переходи к §5.

```bash

DAY="$UNIT-day"
sudo systemd-run --unit="$DAY" --on-active=26h --timer-property=AccuracySec=1s \
  /bin/bash "$BACKUP/restore.sh" "$PY" unused "$BACKUP" "$PANEL" accept
sudo systemctl is-active "$DAY.timer"
sudo systemctl stop "$UNIT.timer"

```

Включи прежний успешный профиль в Selective, проверь active. Запусти наблюдение
и дождись результата. После UTC-перехода проверь короткое видео и обычный VPN.


## 5. Возврат и автоматическая публикация

Если предохранитель был вооружён, отмени **своё** активное задание при наличии,
выбери off. Если панель недоступна, сразу вызови независимый возврат. При
автоматическом срабатывании сначала дождись завершения его service, затем проверяй
результат. Приведи исходный конфиг, VPN, панель и PID воркеров к проверенному
начальному состоянию. Останови свой монитор, если он ещё работает.

```bash
if ! sudo test -f "$BACKUP/restore-completed"; then
  sudo /bin/bash "$BACKUP/restore.sh" "$PY" unused "$BACKUP" "$PANEL" accept
fi
sudo sha256sum -c "$BACKUP/config-before.sha256"
sudo test -f "$BACKUP/restore-completed"
systemctl is-active xgw.service
systemctl show xgw-zapret2.service xgw-nfqws2.service -p ActiveState -p MainPID
"$PY" -m xgw.desync.client status >"$D/final.json"
```

После свежего off/off, рабочего VPN и панели останови именно `"$UNIT.timer"`.
Живой короткий монитор можно завершить командой `kill "$MON_PID"`, предварительно
сверив его командную строку и файл `$D/active.jsonl`. При провале видео повтори
один короткий контроль VPN на том же ролике после возврата.

причины пропущенных шагов, для каждой попытки её режим/профиль, тип запуска,
пригодные секунды, прогресс, разрешение, байты и маршрут. Запиши состояние
после возврата. Сырые URL/IP, подписки, профили Chrome, сетевые журналы и куки
оставь на машине. Работай в отдельном checkout публикации.

```bash
git -C "$REPO" fetch origin "$BR"
git -C "$REPO" worktree add --detach "$D/publish" FETCH_HEAD
cd "$D/publish"
REPORT="docs/reports/$(date -u +%Y-%m-%dT%H%M%SZ)_playback-verification.md"

```

```bash
test -s "$REPORT"

if ! git push origin "HEAD:refs/heads/$BR"; then
```
