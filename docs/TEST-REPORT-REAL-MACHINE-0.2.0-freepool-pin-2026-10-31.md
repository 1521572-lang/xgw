## Наблюдения
1. **Точный учёт подписок подтверждён**: загрузка 30 МБ легла в одну подписку (+36.6 ≥ 29,
   остальные +0.0); в прошлой вехе той же команде соответствовало +26.8 у одной подписки и
   +5.7 у другой (пересборка сервера между отсчётами раз в минуту). Отсчёт Xray на каждом шаге
   демона потерю устранил; WAN (+57.8) сходится.
2. Ручной выбор «в работе» закрепляется мгновенно (0 с) и без перезапуска Xray — применение
   через API (правила роутинга).
3. Механизм «выбранный молчит» проверился живьём дважды: выбранный FR-сервер замолчал через
   ~4 минуты после выбора — трафик автоматически повёл выбранный шлюзом (событие «выбранный
   вручную не отвечает»), затем сервер вернулся и снова стал ведущим; выбранный NL-сервер
   (шаг 5.5) не отвечал все 240 с — в панели у него метка «выбран · не отвечает» и кнопка
   «Автовыбор», `pinned` честно показывает «в «pool»: да; ведёт трафик: нет».
4. Автовыбор не прыгает на другой живой сервер: тег «сейчас через» остался тем же
   (pool-it-da66), сменилась только строка «выбран вручную: держится» → «нет».
5. Дефект помощника (правило 8 ТЗ): режим `pinned` на коде **до** установки падает с
   Traceback (`'Managed' object has no attribute 'free_pool_pin'`) — поля в старом коде нет;
   после установки работает. Сам файл помощника не правил.
6. Замер времени нажатия: bash-команда шага стартует после клика, поэтому метки `t-*`
   записываются позже события, и `events`/`applies` с меткой `t-*` могут оказаться пустыми;
   повтор с меткой −120 с показал все события шага. Замечание к методике (у «Ожидается»
   события предполагают метку до нажатия), не к XGW.
7. `xgw pool pin 12345` отклонён с внятной ошибкой («начало id короче…»), `pin auto`
   идемпотентен: событие снятия одно при кнопке и команде вместе.
8. Возврат меткой: окно дословно, observe в состоянии с +19 с, кнопки «Выбрать»/«Автовыбор»

9. Машина в конце: режим off (как до проверки), HEALTHY с 11:06, «совпадает: да», «ждёт окна:
