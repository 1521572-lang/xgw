# Программа испытаний XGW: честный DEGRADED и «высокий» у лимитированных

**Для исполнителя.** Выполняй шаги строго по порядку. В каждом шаге — команда (копируй
целиком), «Ожидается» и «Если не так». Ничего не придумывай сверх написанного. Не уверен —
остановись и спроси заказчика. Выводы команд сохраняй в файлы, как написано: из них
собирается отчёт (§7). Пути — только абсолютные (`$HOME/xgw-strand-test/…`).

Машина: ThinkCentre, Ubuntu 24.04.5 LTS, шлюз дома, XGW с кодом ветки `tspu-speed-tray`.
Клон репозитория — `~/zcod/xgw`. Версия в ветке — `xgw 0.1.18`; если программа 0.1.18 уже
выполнена, код уже стоит, и повторная установка в шаге установки ничего не меняет.

Что нового (ASSUMPTIONS п. 235). Разбор 24.10 (`docs/TEST-REPORT-REAL-MACHINE-0.1.17-rotation-diag-2026-10-24.md`)
показал: шлюз часами в DEGRADED, потому что мёртвый сервер Турции заменить некем. Все
четыре сервера в работе — «высокий» × x10 одной лимитированной подписки, а все запасные —
«средний». Решение заказчика:

1. **Честный DEGRADED.** Вместо «замена на запасные» — «часть серверов недоступна, а
   заменить их некем: среди запасных нет серверов того же класса (…)». В событиях —
   одна запись «замена» с именем мёртвого и советом. В панели — пояснение под «Серверами».
2. **Предупреждение.** Лимитированные серверы в работе только из-за приоритета, а
   безлимитные живы. Тогда в `xgw status` появляется строка «Внимание: …», в событиях — одна
   запись, в панели — пояснение. Совет: вернуть этим серверам «средний», а при ручном
   выборе — ещё нажать «Автовыбор».

Ставится только код шлюза; приложение на телефоне не меняется. Скрипт `rotcheck.py` — тот
же, что в разборе 24.10 (только чтение, маскирует имена). Время — около 20 минут, с §5 —
около 35.

## 0. Запрещено

- На шлюзе: `xgw net down`, `xgw disable`, `xgw uninstall`, `reboot`, сон машины,
  `install.sh --force` — **никогда**. Службы `xgw*`, `tailscaled`, NetworkManager, `ssh` не
  трогать — их перезапускает только установка (шаг 2.1).
- Команды `xgw` — только `xgw status` и `xgw diag`. **Нельзя**: `xgw priority`, `pin`,
  `unpin`, `probe`, `apply`, `core`, `enable`, `net`, `update-*`.
- Приоритеты и выбор сервера меняет **только заказчик**, сам, в панели, и только в §5.
  Исполнитель в панели ничего не нажимает.
- Править `/etc/xgw/*`, `/var/lib/xgw/*`, код XGW. Коммитить что-либо, кроме отчёта (§7).
- Писать в отчёт имена серверов и подписок, IP-адреса, домены, адреса tailnet, имена
  устройств, ключи. Коды стран — можно. В отчёт идут только выводы `rotcheck.py`, прошедшие
  проверку утечек (шаг 6.1). `labels.json` в отчёт и в Git **не класть**.

Правила стопа:

- Команда спрашивает пароль — **стоп**. Пароль не вводить, сообщить заказчику.
- После установки дома пропал интернет — **стоп**: `sudo xgw status` через `mask` в отчёт,
  сообщить заказчику, ничего не откатывать без него.

## 2. Установка

Шаг 2.1. Код шлюза:

```bash

```

Ожидается: «код 0», в конце — сообщение об успешной установке.
Если код не 0 — **стоп**, сохранить вывод, сообщить заказчику (§6).

Шаг 2.2. Демон заработал. Ждём до 3 минут, потом ещё минуту — на опрос подписок:

```bash
cd "$HOME/xgw-strand-test" && for i in $(seq 18); do sudo xgw status 2>&1 | grep -q '^Состояние: [A-Z]' && break; sleep 10; done; sleep 60; sudo xgw status 2>&1 | python3 rotcheck.py mask | tee out/status.txt | grep -E "^Состояние|^Внимание|^Xray|Перехват:"; sudo xgw diag | tail -1 | tee -a out/status.txt
```

Ожидается (сервер Турции всё ещё мёртв):

- «Состояние: DEGRADED с … — часть серверов недоступна, а заменить их некем: среди запасных
  нет серверов того же класса (лимитированные серверы x10 уровня «высокий»); серверы другого
  класса шлюз ставит в работу, только когда не отвечает ни один из работающих»;
- «Внимание: в работе — лимитированные серверы x10 уровня «высокий», а живые безлимитные
  серверы (N) стоят уровнем ниже, «средний»: приоритет важнее стоимости, и трафик тратит
  квоту подписки (x10). Если так не задумано, верните серверам в работе уровень «средний» и
  нажмите «Автовыбор»: пока сервер выбран вручную, шлюз серверы в работе на другой класс не
  меняет.» — N около 30;
- «Xray 26.10.21: отвечает», «Перехват: включён …», «FAIL — 0».

Если не так:

- «Состояние: HEALTHY» — записать (Турция ожила), строку «Внимание» проверить как выше;
- строки «Внимание» нет — подождать ещё 2 минуты и повторить команду один раз. Нет и тогда
  — записать в отчёт строки «Состояние» и «Класс участников» из шага 1.4 и продолжать;
- FAIL больше 0 или дома нет интернета — **стоп** (§0).

Шаг 2.3. **Попроси заказчика** открыть панель шлюза (на шлюзе или по tailnet) и ответить

## 3. События

Шаг 3.1. События с момента установки:

```bash
cd "$HOME/xgw-strand-test" && python3 rotcheck.py events "$(cat install-time.txt)" "$(date -d '+1 min' '+%Y-%m-%d %H:%M')" | tee out/events.txt | sed -n '1,40p'
```

Ожидается:

- «Переходы состояния»: «HEALTHY → DEGRADED: часть серверов недоступна» — сразу после
  перезапуска демон ещё не знает, есть ли кем заменить; про «замену на запасные» там **нет**;
- «Замены участников (rotation): 1» — строка «rotation: не отвечает сервер в работе «С-…», а
  заменить некем: … Чтобы было из кого менять, поставьте уровень «высокий» ещё нескольким
  серверам (лучше той же страны) или верните серверам в работе уровень «средний».»;
- «Смены класса и уровня (priority): 1» — строка «priority: в работе — лимитированные
  серверы x10 уровня «высокий» …».

Если «rotation» или «priority» — больше 1, записать число и строки: событие должно быть
одно. Если 0 — записать и продолжать.

Шаг 3.2. Повтора нет. Подождать 5 минут, затем повторить команду шага 3.1 с записью в
`out/events-later.txt`:

```bash
sleep 300; cd "$HOME/xgw-strand-test" && python3 rotcheck.py events "$(cat install-time.txt)" "$(date -d '+1 min' '+%Y-%m-%d %H:%M')" | tee out/events-later.txt | grep -E "^(Замены|Смены)"
```

Ожидается: «Замены участников (rotation): 1» и «Смены класса и уровня (priority): 1» — как в
3.1.
