# Наблюдение двух соединений при штатной смене sing-box

**Статус: подготовлено для решения владельца.** В отчёте c600e90 обе загрузки по 2 МиБ
завершились, а происхождение несовпадения прав и одновременность мостов остались открытыми.
Два согласованных повтора G1 использованы. Это отдельное однократное наблюдение только
после явного выбора владельца. Оно добавит два измерения к прежнему отчёту.

Помощник ждёт естественной смены поколения до 180 с после начала первой передачи.
Он отправляет через Xray два GET на уже настроенный speed.youtube_speed_url, который
дал точный диапазон в отчёте. Полезная нагрузка двух полных ответов составляет 4 МиБ,
дополнительно возможны служебный трафик и начальные пробы максимум трёх маршрутов.
HTTP/2 ограничивает выдачу данных сервером до увеличения окна. Для двух уже начатых
ответов помощник посылает разные случайные PING и проверяет ACK по прежним TLS-соединениям.
В обеих выборках, до и после обмена, он проверяет те же сокеты в дескрипторах конкретных
процессов. Несколько новых сокетов на одном мосту дают частичный результат.

## 1. Проверить готовность чтением

Использовать терминал ThinkCentre, браузер, зрение и любые средства чтения по необходимости.
WAN, LAN, Tailscale, пул, pin, подписки и настройки сохраняются. Установку, рестарт и
принудительную смену поколения задание исключает. Сырой вывод оставить на машине.

```sh
cd ~/xgw
git status --short
git fetch origin freepool
git merge --ff-only origin/freepool
CHECK=docs/helpers/singbox_handover_observe.py
printf '%s  %s\n' '19bb0cbbf89b7b8c2a071b192b77425e9806e9d01c12f5e3acff33a0cc8a35da' "$CHECK" | sha256sum -c -
/usr/bin/python3 -I -c 'from h2.connection import H2Connection; print("HTTP/2 готов")'
sudo xgw status
sudo xgw singbox status
```

Ожидаются рабочий on, готовый шлюз, сумма OK и строка «HTTP/2 готов».
Для исполнения нужен hyper-h2 в системном Python. При отсутствии зависимости записать
DEPENDENCY_UNAVAILABLE и закончить. Установка библиотек на шлюз в этот шаг не входит.
Если подготовка или drain уже идут, дождаться завершения чтением статуса. При угрозе
рабочему on остановиться. В штатном режиме деградация отдельного сервера допустима.

## 2. Одно наблюдение после решения владельца

```sh
sudo /usr/bin/python3 -I "$CHECK" --observe
printf 'observe rc=%s\n' "$?"
sudo xgw status
```

Ждать завершения одного запуска. После восстановления связи прочитать вывод исходного
терминала. При NO_NATURAL_SWITCH, NO_HTTP2, неоднозначном сокете или иной неполноте
записать фактический результат и закончить. Запускать rotate или повтор ради результата нельзя.

Для OBSERVED требуются overlap=true, два полных тела по 2 097 152 Б, пустые
permission_observations и vanished_samples=0. Ошибки UID и CapEff сохраняются отдельно
с ролью поколения, номером выборки и этапом. core=true и same_image=true показывают
срез установленного бинарника. Другой образ или сменившийся процесс требуют отдельной
оценки. Права наблюдаются в срезах, в том числе при ожидании смены, а не непрерывно.
Если новый образ уже запустился и его UID/CapEff расходятся с ожидаемыми, сообщить владельцу
категорию, этап и роль из результата. Самостоятельно менять службу или права нельзя.

## 3. Сохранить результат на одной странице

```text
Дата и commit помощника:
Рабочий on до/после, согласие на наблюдение:
Результат, rc, overlap, body_bytes:
samples, vanished_samples, permission_observations (фиксированные поля):
Если частично — причина и какие наблюдения удалось получить:
```

Один файл `docs/TEST-REPORT-REAL-MACHINE-0.2.0-singbox-handover-observe-ДАТА.md`.
В отчёте только числа и фиксированные признаки, без адресов, имён, PID, inode, UUID,
конфигов и снимков экрана. Публиковать только этот файл в freepool. Прежние отчёты
и их критерии сохраняют исходные итоги. Решение о приёмке G1 остаётся за владельцем.
