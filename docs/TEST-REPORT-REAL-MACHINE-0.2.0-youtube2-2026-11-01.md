## Дефекты
1. (шаг 5.2, «ведущий не сменился» — повтор дефекта 1 прошлого отчёта в суженном виде) **При
   пороге 1000 Мбит/с и проверке ведущего раз в 5 минут за 1500 с не было ни одной смены и нет
   паузы** («за 1500 с смен из-за YouTube: 0; паузы нет»). Правка переадресации замера Google
   работает: у 5 из 8 серверов пула скорость Google теперь числом (24–56 Мбит/с) — в прошлый раз
   у 7 из 8 было «—». Но ведущий pool-it-482e оказался из серверов, где файл замера на
   dl.google.com отдаёт HTTP 404: свежая проверка при пороге 1000 — «проходит, Google —; неудач
   подряд 0 (файл замера Google: HTTP 404)» — скорости нет, порогу не к чему применяться,
   вердикт «проходит». У остальных скорость есть, и один сервер дошёл до «неудач подряд 2»
   («тормозит»). Ожидалось (ТЗ 5.2): 3 смены с причинами «тормозит на YouTube» и пауза на
   третьей. Строки: `force.txt` («за 1500 с смен из-за YouTube: 0; паузы нет»; таблица с
   причинами), `events-force.txt` (пуст), `restart-before.txt`. Предположение: при неизвестной
   скорости (файл не получен, причина записана) проверку по YouTube стоит считать неудачей
   ведущего после нескольких попыток подряд — чтобы ведущий с постоянной «скорость не узнать»
   заменялся, как не прошедший проверку.
