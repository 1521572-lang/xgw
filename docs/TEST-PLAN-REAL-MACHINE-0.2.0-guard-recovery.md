# ThinkCentre: независимое восстановление сетевого барьера

Цель — подтвердить PR-1 ТЗ по защите от ТСПУ от 05.11. Когда общая загрузка правил падает,
демон должен вернуть барьер и показать ошибку перехвата. Проверяем на ядре ThinkCentre.
В работающей сети не удалять таблицы, правила или конфиг. Сбой воспроизводится до установки,
в отдельной сети ядра, где есть только тестовый интерфейс. Отдельное устройство не требуется.
Все инструменты Flash разрешены, включая зрение. Проверки выполняются из локального терминала.
Не менять адаптеры, Tailscale, пул, закрепление сервера, подписки, настройки и рабочий on.
Недоступные VPN-серверы допустимы при исправных on и HTTPS. План — один проход.

## 1. Зафиксировать код и исходное состояние

Команды рассчитаны на bash. Вести шаги в одном терминале. Сначала:

```bash
cd ~/xgw && test -z "$(git status --porcelain)" && git switch freepool &&
git fetch origin && git merge --ff-only origin/freepool
```

При конфликте или локальных изменениях — STOP, ничего не сбрасывать. Затем:

```bash
CODE=e3601965fbd703153cb3bf992ca8a948915c60e5
BASE=c7fc6e446f74f821afa50ccc079b80d838dd7278
D=$(mktemp -d "$HOME/xgw-guard-check.XXXXXXXX")
TARGET="$D/new"; PREV="$D/previous"; H="$TARGET/docs/helpers/guard_recovery_check.py"
git worktree add --detach "$TARGET" "$CODE" && git worktree add --detach "$PREV" "$BASE" &&
test "$(git -C "$TARGET" rev-parse HEAD)" = "$CODE" &&
test "$(git -C "$PREV" rev-parse HEAD)" = "$BASE" &&
printf '%s  %s\n' '3e3a2daccf38152efbd1309ac951c98cedd775b0becb6aa704b81c0f731ae531' "$H" | sha256sum -c -
```

Ожидается `OK`, rc0. Иной результат — STOP. Временно сохраните приватно:

```bash
umask 077
sudo python3 -I "$H" health && sudo xgw status --json >"$D/before.json" &&
sudo sha256sum /etc/xgw/config.toml >"$D/config.sha" &&
sudo xgw diag --no-net >"$D/diag-before"
```

Ожидаются `OK on`, `OK https`, отсутствие новых аварий. Записать числа OK/WARN/FAIL,
режим пула и ручной выбор приватно. Если исходный on/HTTPS не подтверждён, STOP.
Не публиковать сырые файлы. Не запускать G1 или старые задания волны 3.

## 2. Один отказ в отдельной сети ядра ThinkCentre

```bash
sudo python3 -I "$H" isolated >"$D/isolated" 2>&1; isolate_rc=$?
cat "$D/isolated"; printf 'isolated_rc=%s\n' "$isolate_rc"
```

Ожидается rc0 и последовательно `OK isolated`, `initial_guard`, `deleted`, `tcp_control`,
`udp_control`, `independent_recovery`, `tcp_dropped`, `udp_dropped`, `already_present`,
`full_recovery`, `open`, `off` (каждая строка начинается с OK).
После удаления таблиц и до попытки ремонта помощник отправляет по одному пакету TCP и UDP.
Поздний счётчик должен зафиксировать каждый пакет: это положительный контроль пути.
Далее nft отклоняет полную транзакцию. Отдельная транзакция должна вернуть только барьер.
Для каждого протокола растёт счётчик drop, а следующий за барьером счётчик стоит.
В конце проверяются обычная загрузка и выбор open/off внутри той же тестовой сети.
Если нет unshare/nft, rc ненулевой, отсутствует этап или истёк таймаут — STOP до установки.
Запишите последний OK и код, включая случай до первого OK. Установка в таком случае NOT_RUN.
Не запускать child вручную, не переносить команды в сеть хоста. При выходе namespace исчезает.

## 3. Согласие и установка с автоматическим возвратом

После полного шага 2 спросить владельца: «Установить проверенный CODE поверх c7fc6e4
штатным установщиком с автоматическим возвратом BASE при ошибке установки, сверки пакета
или on/HTTPS? В CODE входит также уже опубликованная правка ручного замера скорости».
При отказе — INSTALL_NOT_RUN, к отчёту. Перед согласием или при другом BASE ничего не ставить.
Одна локальная команда запускает установку и принимает решение о возврате независимо от связи:

```bash
test "$isolate_rc" = 0 && test -z "$(git -C "$TARGET" status --porcelain)" &&
test -z "$(git -C "$PREV" status --porcelain)" && sudo sh -s -- "$H" "$PREV" <<'SH'
set -eu
umask 077
d=/run/xgw-guard-job
mkdir -m 700 "$d"
cd "$d"
nohup setsid sh -c 'python3 -I "$1" deploy "$2"; echo "$?" >result.tmp; mv result.tmp result' sh "$1" "$2" </dev/null >worker.log 2>&1 &
echo 'Установка запущена'
SH
```

Ожидается «Установка запущена». Работник сначала сверяет установленный пакет с BASE и
проверяет on/HTTPS. При отказе до `OK baseline` — STOP без записи пакета. Затем он фиксирует rc
установщика, сверяет файлы с CODE и проверяет on/HTTPS. Если установка началась и приёмка
пакета не прошла, тот же процесс запускает установщик BASE и проверяет файлы и здоровье.
Каталог уже существует — только прочитать результат. Не удалять каталоги и не повторять старт.

```bash
sudo sh -c 'd=/run/xgw-guard-job; for i in $(seq 120); do test ! -f "$d/result" || break; sleep 5; done; cat "$d/worker.log"; printf "worker_rc="; cat "$d/result"'
```

После восстановления связи читать тот же результат. Норма — `install_rc=0`, `OK installed`,
`worker_rc=0`. Если был возврат — указать `rollback_rc` и `rollback_verified`.
Возврат не подтверждён — сразу связаться с владельцем. Самостоятельно ничего не чинить.
Если ожидание длится больше 10 минут — только чтение журнала и состояния процесса, сообщить
владельцу о зависании. Ни второй установки, ни принудительной остановки.

## 4. Работа шлюза и отчёт

При принятой установке оставить шлюз на обычной нагрузке две минуты. Затем:

```bash
sudo python3 -I "$H" health && sudo sha256sum --status -c "$D/config.sha" &&
sudo xgw status --json >"$D/after.json" && sudo xgw diag --no-net >"$D/diag-after"
```

Норма — `OK on`, `OK https`, rc0, новых FAIL нет. Приватно сравнить пул и закрепление с
исходным срезом. Изменение этих настроек, потеря раздачи со слов владельца либо сбой конечной
проверки — PARTIAL, сообщить владельцу, новых воздействий не выполнять. Хостовый HTTPS и
тестовый TCP/UDP — отдельные результаты. LAN клиента за роутером здесь не измеряем.

Один отчёт в freepool, `docs/TEST-REPORT-REAL-MACHINE-0.2.0-guard-recovery-ДАТА.md`.
При STOP допустим короткий отчёт с фактическим rc и последним успешным этапом.
Проверить diff: только этот файл. Публиковать обычным push без force. Не включать адреса,
домены, имена серверов, устройств, подписок, конфиг, сырой JSON, MAC, логи и скриншоты.

- Дата, CODE/BASE, сумма OK, исходный on/HTTPS, diag (три числа).
- Изолированная сеть: rc, последний OK; обе контрольные пробы, отдельный ремонт,
  drop TCP/UDP, полный ремонт, open/off — прошли / отказ / NOT_RUN.
- Согласие, install_rc, worker_rc, возврат и его проверка либо NOT_RUN.
- Конечный on/HTTPS, совпадение конфига, пул/pin, diag, замечания владельца.
- Итог PASS (шаги 1–4 прошли), PARTIAL либо STOP. Первый непройденный шаг и что осталось.
