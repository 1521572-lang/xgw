## Наблюдения для Codex

1. **Стенд зависит от длины пути базового каталога**: сокет API Xray
   собирается внутри корня стенда, и при basetemp под `$HOME` путь
   превысил лимит unix-сокета (110 > 107) — «bind: invalid argument»
   без явного указания причины. Предлагаю создавать временный каталог
   стенда в `/tmp` (или укорачивать внутренний корень), иначе стенд
   невоспроизводим при длинных домашних путях.
2. После снятия блокировки стенд подтвердил всю связку на реальном
   ядре ThinkCentre: TPROXY-перехват LAN-HTTPS с точной атрибуцией
   сокета клиента в записи `tproxy-in` (group=xray), устойчивость к
   src_valid_mark, корректный прямой выход исключений и fail-closed
   при смерти Xray с возвратом прямого интернета после disable.
3. Связка «запись tproxy-in из stdout реального Xray стенда»
   согласована с прежней проверкой журнала действующей службы на
   локальных входах — анализ маршрута LAN теперь покрыт от ядра до
   анализатора; остаётся живой клиент (отдельное ТЗ).
