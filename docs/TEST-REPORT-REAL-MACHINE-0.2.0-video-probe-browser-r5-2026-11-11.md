marionette_error не появился — контрольный канал не обрывался ни разу (фиксы r3–r5 работают

продвижение времени ≥2 с (`playback=1`) — **браузерный тракт полностью рабочий: страница,
плеер и свежий адрес видеосети получены**. Адрес найден вторым кандидатом из ресурсов, запас
expire ~6 часов (21588 с) — согласуется с оценкой срока видеоссылок в отчёте gui-zapret2.

Отказ — на повторном GET того же адреса через VPN: HTTP 200, **31 байт тела**, video_mime не
видео, verdict=short_body, редиректов нет, фаза body. Критерий видеопробы (2xx + ≥16 КиБ +
video/*) не выполнен. По таблице r2 — смотреть HTTP, объём и MIME; зафиксировано. Прямой путь
zapret2 не проверялся (следующий отдельный эксперимент по плану).

Сверки: `verification=ok`, `xray_config_changed=false`; diag до и после — OK — 32, WARN — 1,
FAIL — 0 (WARN один и тот же до и после — сетевые таймауты проверочных хостов, не от этого
эксперимента); capture on, zapret2 off. Событие ротации пула в 20:55 предшествовало прогону
(проба ~21:19–21:21 по времени проверки адреса) — живой сценарий ротации NOT_RUN. Временный
Firefox завершён помощником, профиль удалён; после прогона временных процессов и профилей нет.

Наблюдение для разработчика: повторный GET без заголовка Range и без выбора кандидата по
объёму передачи может попадать на не-медиа сегмент (страница отдает 200 с крошечным телом).
Варианты следующего шага: выбирать кандидата по наибольшему transferSize из Resource Timing,
добавлять Range: bytes=0- к повторному GET, либо пробовать несколько кандидатов по списку до
выполнения критерия. Ни один из вариантов не требует изменения шлюза.

Итог: **RESULT replay_failed** при полностью пройденном браузерном тракте — до воспроизведения
и получения свежей видеоссылки эксперимент дошёл впервые за пять раундов. Квитанция и сырые
файлы остаются приватно в каталоге прогона.
