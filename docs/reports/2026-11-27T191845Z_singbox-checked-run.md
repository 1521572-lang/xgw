## `CHECKED_RUN` (три сценария на реальных процессах, loopback)

`CHECKED_RUN=0`. В каждом сценарии поднимался настоящий процесс sing-box 1.14.5 в приватном префиксе, мост реально проверялся локальным HTTP-источником (по одному фактическому запросу на проверку), а идентичность проверяемого процесса определялась по дочернему процессу и настоящему procfs.

| Сценарий | Наблюдение |
| --- | --- |
| `CHECKED_RUN_DURING_PROOF=PASS` | Реальный прокси вернул ответ HTTP; кандидат заменён (перезапуск процесса, новый run) до окончания проверки моста. Подготовка отклонена с причиной «во время проверки моста»; старый слот `blue` остался активен (его run не изменился), API-вызовов нет, `pending` пуст |
| `CHECKED_RUN_BEFORE_COMMIT=PASS` | Кандидат проверен и готов, затем его процесс заменён. `finish` отклонён (`mode=rejected`, причина «после проверки моста»); оба исходных конфига (Xray и sing-box) остались на месте, API-вызовов нет, новое поколение не запущено |
| `CHECKED_RUN_STABLE=PASS` | Реальный запрос прошёл через тот же кандидат; переход `blue → green` принят в приватном префиксе (`mode=api`, активен `green`, записи API в тестовом объекте), `draining.slot=blue`; старый процесс остаётся живым на время drain, а run принятого поколения равен проверенному run. Оба исходных конфига не тронуты до коммита |

Для сценариев используется запись API в тестовом объекте; полномочия служебной учётной записи покрыты контрактами, а отслеживание MainPID и времени старта опирается на дочерние процессы и настоящий procfs.
