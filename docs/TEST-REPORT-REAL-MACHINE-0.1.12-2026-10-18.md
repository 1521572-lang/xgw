# Отчёт об испытаниях XGW 0.1.12 на реальной машине

Код: `7a6bcf8`. Установка: 11:07, код 0 (`packaging/install.sh --yes`, sing-box v1.14.3 загружен
при установке; повторно `update-singbox` — «уже нужная версия», код 0).

## Итог

0.1.12 установлена поверх 0.1.11 штатным установщиком, все пять служб (`xgw-net`, `xgw-xray`,
`xgw-singbox`, `xgw`, `xgw-dhcp`) активны, итог diag «FAIL — 0» в течение всего дня. sing-box
принял 113 мостов и ведёт hysteria2/TUIC/WireGuard/Shadowsocks-серверы, которых Xray не умел:
hysteria2 (5 шт.) и ту часть VLESS/Shadowsocks, где Xray не проходит. **Главное: sing-box
помогает у этого провайдера** — 24 сервера из 73 в контрольной пробе на Xray давали
`TIMEOUT`/`CONNECT_FAIL`, а на sing-box — `OK` (13 из них — профиль «sing-box с дроблением TLS»,
ещё часть — обычный sing-box). Обратная цена: 6 серверов хуже через sing-box
(`OK → CONNECT_FAIL`), поэтому режим `auto` с автопереключением профилей — правильная
дефолтная конфигурация; испытание подтвердило, что шлюз в `auto` сам подбирает
ядро/профиль (18 закреплений профиля за час работы). Перебоев с интернетом за время
испытаний не было; состояния — `HEALTHY` с 11:31 до конца дня.

## Дефекты

Не найдено. Наблюдения (не дефекты):

1. После `xgw core <участник> auto` метка участника стала `[xray]`, а была `[xray+frag]`
   до закрепления sing-box — профиль обхода после сброса ядра сначала ставится обычный
   Xray, дробление переучивается само (у участника в момент возврата трафик шёл нормально).
2. При переходе в режим `xray` (шаг 5.5) и после восстановления конфига в журнале
   мелькает предупреждение «серверов, которые умеет только sing-box, отложено: 5 —
   sing-box выключен или не установлен» — фактически 5 hysteria2-серверов; в режиме
   `xray` это ожидаемое поведение (их ведёт только sing-box), после возврата `auto` они
   вернулись (в статусе «серверов через него: 13»).
3. Экспорт журналов (`xgw logs --export`) создаёт файлы с правами root — распаковка
   обычным пользователем требует sudo (мелочь, не дефект).

## Что не проверено и почему

- Ручной ввод `[core] mode = "sing-box"` на постоянной основе — проверен временно (шаг 5),
  после испытания конфиг возвращён как был (`grep '^\[core\]'` → 0).
- Telegram-уведомления при сбое sing-box — не тестировались: никакого сбоя уровня «сервис
  не поднялся» за день не случилось (kill -9 systemd отработал сам за 3 с, до порога
  уведомления демона).
- Лимит устройств/лимиты тарифов подписок — не входят в программу 0.1.12.
- Живые тесты 1069-набора (netns, стенд) в venv чек-аута не исполнялись — скипаются по
  окружению; на машине их роль выполнила сама эта программа испытаний.
