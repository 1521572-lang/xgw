## Отклонения и наблюдения
- Перенос помощника: при первом создании scout.py контрольная сумма не сошлась — в строке чтения кэша escape-последовательность заменила литеральный невидимый символ (BOM); после точного исправления сумма совпала (adb2dc5fdacf2bdc), данные собраны исправленным помощником.
- netcheck вывел имя активного сервера без маскировки (имя не нашлось в базе помощника); в этот отчёт оно перенесено как «<сервер>», адреса помощник маскировал сам.
- Загрузка 100 МБ не состоялась (HTTPError от измерительного эндпойнта); предположение: причина в недоступности этого эндпойнта через текущий активный сервер при DEGRADED, а не в канале как таковом — UDP-проба и HTTPS-проба продукта проходят.
- Из-за неудавшейся загрузки скорость для dae взята из обычного WAN-замера (макс 15.2 Мбит/с < 20) → решение «НЕ ХВАТАЕТ ДАННЫХ»; при успешной 100 МБ загрузке данные могли бы отличаться.
- Предположение: system_pct ~77 % — нагрузка всей машины (десктоп, браузеры владельца), а не только шлюза; Xray занимает 5.4/14.2 % ядра — процессор шлюза не выглядит узким местом при текущих скоростях.
- Бюджет проб: 829.7 из 1024 МБ на месяц (~81 %) при одном лимитированном подписочном пуле — согласуется с решением «C05/C06 НУЖНО».
- Противоречий между решениями помощника и числами шагов 3–5 не найдено.
