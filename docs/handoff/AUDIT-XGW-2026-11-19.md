## Что влияет на ближайшую поставку

1. Расширение общего разрешения в межсетевом экране способно изменить поведение при падении воркера. Два контура XGW уже имеют разные правила для этого исхода. Сначала проверяем фактический путь в обоих контурах.
2. Постоянный секрет в URL и совместное исполнение HTTP и управления сетью подтверждены кодом. Можно начинать проектирование миграции входа. Вынос HTTP в отдельную службу потребует явного контракта полномочий.
3. Ручной перенос числовых позиций в Flowseal на `+1` внёс бы ошибку. Есть другой конкретный вопрос к семейству FAKE TLS AUTO — что реально возвращает модификация короткого литерала и применяется ли затем отдельная стадия с корректным TLS-шаблоном.
4. Основной критерий выпуска остаётся пользовательским. В Standalone проверяем видео без VPN. В Selective одновременно подтверждаем прямой путь медиа, обычный сайт через VPN и возврат нового соединения на VPN. Последний отчёт принял короткий Standalone, механику JOB01–05 и выявил недостаточную проверку бюджета перед стартом. Матрица 18 в этом отчёте не запускалась. ### Семь спорных механизмов из §1.2

1. **Метки и повторный перехват.** У Selected обычная метка `0x10000000`, копия `0x50000000`. В поставленном C/Lua исходная метка сохраняется при добавлении бита генерации. В Engine, например, копия от bypass `0x2` может иметь `0x40000002`. Здесь действует проверка по биту. Запрошенный аудитом `0x20000012` относится к новой схеме слотов. В текущем контракте `ip rule` ищет полную метку. Отдельное пространство `ct mark` уже использует `GUARD_CT`, `SYNACK_CT` и `REPLY_CT`. При будущей миграции потребуются таблица владельцев, пользовательские значения, оба семейства, Tailscale, Docker, проверка старых полных правил и возврат именно правил XGW. `Capture.tidy` сейчас обслуживает ненужный TUN. [Рендер](../../src/xgw/net/nft.py) · [Обработка fwmark в поставке](../../third_party/zapret2/nfq2/desync.c) · [Захват](../../src/xgw/net/capture.py)
2. **Завершение TCP у sing-box.** Служба имеет отдельный UID и пустой bounding set. Выход разрешается по `skuid`. В `jump pass` также допускаются ответное направление, локальные направления и ранее одобренный conntrack. Обычное соединение, открытое UID ядра к внешнему серверу, может завершаться в исходном направлении. Успешное чтение тела до закрытия сокета не проверяет последний ACK. Сопоставить FIN клиента, подтверждение закрытия на приёмнике, пакеты без совпавшего UID и контроль другого UID. Только воспроизведённое расхождение оправдывает суженную правку одобрения соединений. [Правила](../../src/xgw/net/nft.py) · [Служба sing-box](../../packaging/xgw-singbox.service)
3. **Порядок хуков и NAT.** У Selected уже есть output −401 для копии, guard postrouting 10, очередь postrouting 101 и опциональный input −149 только для принадлежащих соединению ответов. У Engine очередь находится в output 90 и использует `bypass`. В Selected очередь без слушателя должна останавливать прямой путь. Для Standalone отчёт подтвердил блокировку после смерти воркера, для Selective требуется отдельный новый сеанс через VPN. Предложение «bypass везде» нарушило бы эту границу. Для новых прямых LAN-пакетов потребовалась бы независимая пара LAN → NAT → приёмник. [Selected](../../src/xgw/zapret2.py) · [Engine](../../src/xgw/net/nft.py) · [Приёмка маршрута](../reports/2026-11-18_desync-t12-selective-wan-control.md)
4. **TUN при старте Xray.** `ExecStartPost=-+… net tun` действительно допускает продолжение при ошибке. Но `restore_tun` проверяет режим/цепочки, под блокировкой вызывает `tun.ensure`, который сам создаёт постоянный интерфейс, поднимает его и задаёт адрес, затем восстанавливает маршруты. «Просто ждать интерфейс Xray» может ухудшить запуск. Проверить отсутствие/состояние down, blackhole и восстановление FIB. Частоту сбоев именно systemd можно установить только по сопоставленным временным меткам реального запуска. [Unit Xray](../../packaging/xgw-xray.service) · [Восстановление](../../src/xgw/net/capture.py) · [Создание TUN](../../src/xgw/net/tun.py)
5. **Аргументы и `wordexp`.** В закреплённом C для режима файла указан `WRDE_NOCMD`. Конфигурационный файл должен быть единственным аргументом; приведённый в аудите вариант смешивает файл с отдельными флагами. Оба адаптера XGW передают список argv, preflight проверяет пути, затем выполняет dry-run и инициализацию Lua без перехвата. `--lua-init=@путь` загружает Lua, для него существенны доверенные каталог и файл. Из проверенного тракта не следует заявленная инъекция команд через конфиг. Для будущего импорта оставить типизированные данные и сборку argv. [Парсер C](../../third_party/zapret2/nfq2/nfqws.c) · [Preflight](../../src/xgw/desync/preflight.py)
6. **Conntrack.** Учёт пакетов `nf_conntrack_acct` нужен опциональному диапазону входящих ответов. В T05 на машине отдельно проверены его выключение и восстановление. `nf_conntrack_tcp_be_liberal` — другой параметр; включение autohostlist с системным изменением выходит за действующую политику. При выключенном учёте фактическую границу первых пакетов Engine нужно проверять отдельно от наличия выражения в nft. [T05](../reports/2026-11-16_desync-t05-replies-autottl.md) · [Системные настройки](../../src/xgw/net/sysctl.py)
7. **Своевременная реакция.** `wake("rules")` прерывает сон, обработка идёт в цикле. Пассивный максимум возраста файла включает штатный сон. Для причинного вывода о задержке нужна привязка к одному поколению демона и к реально произошедшему событию. Данные без такого события пригодны для выбора участка инструментирования. [Watchdog](../../src/xgw/daemon.py)

| Q1/Q5, P1.2 и P0.1 — два класса и слоты | Вести раздельную карту текущих владельцев packet/ct bits. Централизацию констант можно делать с тестом побайтового равенства рендера. Слоты меняют политику маршрутизации; требуется подтверждённая потребность в одновременных профилях, матрица совместимости и обратимая миграция. |
| Q2/Q4, P2.2 — QUIC и обучение списков | Оставить явный выбор режима. Для UDP не существует TCP SYN/ACK для расчёта пути. Полноценный direct QUIC и autohostlist требуют своих endpoints, исключений и контроля объёма. К обновлению фидов вернуться при реальном запросе на другие домены, с пределами, проверкой источника, пользовательскими исключениями и откатом. |
| Q3, P1.3 — реестр TOML | Уже существуют схема политики, закрытые наборы стратегий и закреплённый импорт. Допуск произвольного имени Lua-функции или доверие к regex не заменяют проверку полномочий и смысла действий. При расширении хранить список поддерживаемых полей, порядок стадий, область и несовместимости версионированно. Обязательны валидатор, dry-run, инициализация и отрицательные примеры до переключения. [Схема](../../src/xgw/desync/schema.py) · [Preflight](../../src/xgw/desync/preflight.py) |
| Q6, P1.5 — подбор, импорт blockcheck | Уже есть задания, отмена, журнал результатов и бюджет Selective. Сначала получить матрицу и проверить закрепление только у квалифицированного кандидата. `probe.max_daily_probe_mb` и `zapret2.daily_probe_mb` имеют разных владельцев. Автоприменение внешних команд и отдельную очередь 399 отложить. Успех HTTPS, длительность воспроизведения и маршрут остаются тремя отдельными результатами. [Jobs](../../src/xgw/desync/jobs.py) · [Матрица и видео](COMBINED-ADMISSION-2026-11-19.md) |
| Q7/Q8, P1.1 — установка, systemd, ассеты | XGW уже поставляет закреплённые исходники/комплект, проверяет целостность и запускает временные units `xgw-zapret2`/`xgw-nfqws2` через общий слот. Есть `NoNewPrivileges`, ограничения ФС и capabilities, проверка владельца очереди. Параметр `Restart=no` связан с управляемым возвратом. Реальные EUID/CapEff и работоспособность preflight после возможного снижения прав проверять на машине. Второй установщик и гонку автозапусков исключить из ближайшей поставки. [Комплект](../../src/xgw/zapret2_bundle.py) · [Владение](../../src/xgw/desync/worker.py) · [T06](../reports/2026-11-16_desync-t06-preflight.md) |
| Q10, P1.4 — лестница туннелей | Уже есть `xray:fragment`, `xray:split`, `nfqws2:*` и варианты sing-box; доступность зависит от ядра, конфигурации и узла. `fragment.py` строит выход без дробления для внешнего движка. У одного текущего Engine один эффективный профиль. Вводить новые слоты, профиль на внешнем UDP и автоматическую деэскалацию можно после измеренного выигрыша и теста восстановления. [Профили](../../src/xgw/generator/profiles.py) · [Выход](../../src/xgw/generator/fragment.py) · [Выбор движка](../../src/xgw/nfqws2.py) |
| P2.1 — изоляция панели | Сначала инвентаризация точек чтения, изменения политики, jobs/cancel и операций ядра, с тестом идентичности клиента сокета и версии сообщений. Затем непривилегированный процесс, узкий API действий, откат и реальная приёмка Qt/Web/CLI. Оценка systemd сама по себе не подтверждает изоляцию. |
| Q9, P2.3 — IPv6 | Сохранить структурные проверки off/guard и существующего proxy там, где он поддерживается; текущий Selected допускает IPv4 TCP/443. Живой IPv6 WAN — `NOT_APPLICABLE_ON_THIS_HOST`. Выпуск dual-stack Selected потребует отдельной машины с соответствующей сетью. |
| P2.4 — размер Git | В дереве действительно есть APK 19 353 142 байта. Перенос файла вперёд по истории сам по себе не уменьшит полный клон старых объектов. Цель по размеру сначала привязать к типу клона, проверить пути загрузки и релизные артефакты. Архивы приёмки нужны для продолжения разработки. Отложено до работ по распространению. |
