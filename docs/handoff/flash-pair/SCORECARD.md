# Как сравнить отчёты Flash A и Flash B

Координатор фиксирует эту шкалу до запуска. Проверяющий получает два отчёта без названий моделей, метаданных авторов и переписки, выставляет баллы со ссылками на строки evidence и только затем узнаёт соответствие меток моделям. Передать исполнителям их отдельные карточки. [Карточка A](FLASH-A.md) · [Карточка B](FLASH-B.md) · [Условия запуска](PROTOCOL.md)

## Пригодность пары

Сверить SHA скриптов в карточках, ревизии, версии Ubuntu/Python/pytest/Xray, права, лимиты и порядок. У каждого запуска должен быть свой run ID. Для каждого текстового блока evidence вычислить SHA-256 по строкам в UTF-8 с LF, включая последний LF. Хеш выявляет ошибку переноса. При расхождении вывода и анализа проверить приватный файл на машине. Если испытания пересеклись, один исполнитель видел чужой отчёт, доступ различался или причина отсутствия измерений спорна, зафиксировать наблюдения и повторить сопоставимую пару. Разница случайных H1–H4 и длительности pytest штатна.

## Шкала (100 баллов)

За каждое перечисленное наблюдение дать указанные баллы при точном ответе и ссылке на свой факт. За отсутствующий или противоречащий измерению ответ — 0 по этому подпункту. Очки начисляются и за верно диагностированное падение продукта. Сверять ожидаемое с фактическим выводом конкретного запуска.

| Критерий | Макс. | Начисление |
|---|---:|---|
| Воспроизводимость | 10 | По 2 за идентификаторы слота/раунда/сеанса, SHA карточки, пару SHA исходников, версии ОС/архитектуры, версии Python/pytest/Xray. |
| Разбор двух ревизий | 20 | По 2 за каждый из четырёх верно указанных исходов теста на ревизии. По 2 за каждый rc. Ещё 4 за точную первую проверку в исходном логе и 4 за объяснение, как смена порта затрагивает ключ своего выхода и ключ второго. Ожидаемая регрессия контроля сама по себе не снижает оценку. |
| HTTP Range | 24 | По 6 за каждую из H1–H4. По 1 за каждую позицию — запрошенный интервал, HTTP, Content-Range, прочитанные байты, совпадение тела, вердикт с причиной. Для успеха нужны 206, точный интервал, полная длина и совпавшее тело. |
| Отдельный Xray | 18 | Для каждой из трёх фаз по 2 за привязку к фактической метке и по 4 за смысл. В первой фазе проверить первичный источник и отсутствие запросов ко второму, во второй — учёт байтов и судьбу SQLite/сводки, в третьей — различие контрольного HTTP 503 и пропуска следующей пробы с сохранением закрепления. |
| Шлюз и границы | 12 | 3 за верный итог сравнения полей, 3 за поля/охват и границу причинного вывода. По 2 за обоснованный отдельный статус публичного видео, рабочего WAN и суток M3. |
| Проверяемость отчёта | 10 | По 2 за полный блок evidence, совпадение его SHA-256, трассируемость повторов или указание единственного запуска, публикацию одного обезличенного отчёта нужного слота, следующий проверяемый шаг в пределах вывода. |
| Самостоятельность | 6 | 2 за собственный запуск, 2 за самостоятельный разбор вывода, 2 за самостоятельную публикацию. Обычная выдача запрошенного доступа или объяснение расположения штатного бинарника не считается помощью с анализом. |

Если отсутствующая зависимость, сбой GitHub или дрейф шлюза объективно лишили одного слота возможности выполнить часть, пометить причины и баллы по доступным строкам. Для полного сравнения повторить оба слота с равными исходными условиями. Подмена пропуска на PASS, присвоение чужого вывода или самовольное изменение рабочего шлюза исключают рекомендацию этого исполнителя по данному раунду. Такое решение требует конкретного проверенного факта. Время активной работы и количество подсказок вывести рядом с баллами.

## Решение

1. Заполнить строку на модель: слот, баллы по семи критериям, сумма, активные минуты, помощь, существенные ошибки. Привести по одному примеру, где каждая модель правильно или ошибочно интерпретировала измерение. Раскрыть названия после фиксации таблицы.
2. Разрыв **от 10 баллов** в полной сопоставимой паре даёт предварительный выбор исполнителя для подобных задач. При меньшей разнице результат первого раунда — «близко». Это заранее выбранный практический порог.
3. Для проверки устойчивости провести второй раунд в свежих чатах в обратном порядке и с прежним соответствием слотов. Обоим задать `XGW_FLASH_ROUND=2`. Код тот же, HTTP-наблюдения новые. Подтвердить выбор, только если лидер один в обоих полных раундах и средний разрыв не меньше 10. В остальных случаях сообщить, по каким задачам сильнее каждая модель или что устойчивой разницы не обнаружено. Вывод относится к исполнению и диагностике подобных ТЗ XGW.
