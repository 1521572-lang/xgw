Ubuntu 24.04 LTS amd64, установленная база `08d31ee`, инструменты
`96e3311d6ab90c20a35534b0dc5364705e81194a` из отдельного checkout.

публикует один обезличенный отчёт. При отсутствии нужного доступа сама запрашивает

Предыдущая проверка подтвердила базу 11/11 и 57 тестов. Матрица пересчитана
из одного исходного job. Из 18 строк 13 active, 4 timeout, 1 fallback.

через 38–44 с. В обычном Chrome ролик продолжал играть. Причина разницы
остаётся открытой. Следующий замер использует штатный Chrome без отладчика,
чтение HTML-плеера из расширения и журнал NetLog. [Последний отчёт](../reports/2026-11-20T010300Z_playback-verification.md)

## 2. Контроль плеера и измерения через VPN

Выбери один публичный ролик длительностью больше 35 минут с доступным 720p.
Присвой `VIDEO` его ID из адреса. Используй один тестовый профиль для всех
стадий. Chromium запускается с флагом штатной записи NetLog, ограниченной 96 МБ
и 28 минутами на запуск. Не используй профиль владельца, Playwright, внешний
отладочный порт или DevTools во время записи. [NetLog Chromium](https://www.chromium.org/for-testers/providing-network-details/) · [Изолированный контекст расширения](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts#work_in_isolated_worlds)

```bash
test "${#VIDEO}" -eq 11
EXT="$D/extension"
install -d -m 0700 "$EXT"
cp docs/helpers/playback_extension/* "$EXT/"
cp docs/helpers/youtube_telemetry.js "$EXT/"
open_run() {
  local label=$1
  mkdir "$D/$label"
  "$CHROME" --user-data-dir="$D/chrome-profile" --no-first-run --disable-background-mode \
    --no-proxy-server --disable-quic --log-net-log="$D/$label/netlog.json" \
    --net-log-max-size-mb=96 --net-log-duration=1680 about:blank >"$D/$label/chrome.log" 2>&1 &
  CHROME_PID=$!
}
verify_run() {
  local label=$1 seconds=$2
  shift 2
  "$PY" -m docs.helpers.acceptance_playback_check --capture "$D/$label/player.json" \
    --video "$VIDEO" --minimum-seconds "$seconds" --netlog "$D/$label/netlog.json" \
    --media-output "$D/$label/media.jsonl" "$@" >"$D/$label/verdict.json"
}
vpn_address() {
  curl -4fsS --noproxy '*' --connect-timeout 5 --max-time 15 https://api.ipify.org \
    | "$PY" -c 'import ipaddress,sys; print(ipaddress.IPv4Address(sys.stdin.read().strip()))'
}
vpn_address >"$D/vpn-before.ip"
open_run vpn-clean
```

1. Открой ролик в тестовом Chrome и выставь 720p, скорость 1×. В течение минимум
   120 с проверь через vision, что позиция движется и ошибки нет. Это визуальный
   контроль. Сохрани время начала и конца, затем закрой тестовый Chrome.
2. Выполни `open_run vpn-recorded`. В `chrome://extensions` включи режим
   разработчика и выбери «Загрузить распакованное расширение». Укажи папку
   `$EXT`, закрепи XGW Playback Recorder. В настройках загрузок выставь запрос
   места сохранения. Открой тот же ролик, разреши consent при необходимости,
   выставь 720p и 1×.
3. На вкладке ролика нажми расширение → «Начать», закрой popup и оставь вкладку
   видимой. Для контроля запиши примерно 140 с после появления движения.
   Нажми «Остановить» и «Сохранить запись», сохрани точным именем
   `$D/vpn-recorded/player.json`. Закрой только этот Chrome и дождись записи
   журнала. Для последующих стадий используй тот же профиль. Перед каждым
   `open_run` закрой прежнее окно. Если процесс остался живым, используй выход
   из Chrome в этом профиле. Сохраняй частичные замеры при ошибке плеера.

```bash
if verify_run vpn-recorded 120; then echo VPN_CAPTURE_PASS; else echo VPN_CAPTURE_PARTIAL; fi
cat "$D/vpn-recorded/verdict.json"
```

Для медиатрафика анализатор считает кадры DATA ответов 200/206 на
`googlevideo.com/videoplayback` по HTTP/2. IP берётся из связи с сокетом TCP.
В NetLog остаются приватные данные. Файл `media.jsonl` содержит интервалы,
байты и адреса внутри стенда. Если в логе нет подходящих событий, укажи
`network_source` и ограничение. [Состав событий Chromium](https://github.com/chromium/chromium/blob/main/net/log/net_log_event_type_list.h)

Продолжай при `player_ok=true` даже при неполном сетевом источнике, фиксируя
эти исходы раздельно. Если расширение отказало, одно повторение допускается в
том же варианте запуска. При повторной ошибке один раз проверь тот же ролик с
выключенным расширением. Если численную запись сделать не удалось, сохрани
варианты запуска и точный блокер и переходи к публикации. Трафик этого прохода
отдельно измеряется без pcap. Внешний VPN-сервис можешь заменить на прежний
проверенный endpoint. Используй один и тот же сервис до, во время и после теста.

### Маршрут и возврат на VPN

Сопоставь медиабайты с фоновыми и рабочими парами через готовую команду.
Файл вывода содержит только агрегаты и времена. [Правила сопоставления](T12-SELECTIVE-MEDIA-PAIRS.md)

```bash
"$PY" - "$D" "$PROFILE" <<'PY'
import json, sys
from itertools import pairwise
from pathlib import Path
root, profile = Path(sys.argv[1]), sys.argv[2]
for phase in ("long", "seek"):
    for attempt in (1, 2):
        label = f"{profile}-{phase}-{attempt}"
        net = root / label / "media.jsonl"
        watch = root / f"{label}.jsonl"
        if not (net.is_file() and watch.is_file()):
            continue
        events = [e for line in net.read_text().splitlines()
                  if (e := json.loads(line)).get("kind") == "media_bytes"]
        snapshots = [json.loads(line) for line in watch.read_text().splitlines()]
        matches = accepted = 0
        for left, right in pairwise(snapshots):
            pair = right.get("media_pair", {})
            if pair.get("state") != "accepted":
                continue
            accepted += 1
            if pair["probe_before"] != pair["probe_after"]:
                continue
            old = {s["socket"]: s for s in (left.get("tcp") or {}).get("sockets", [])}
            peers = set()
            for s in (right.get("tcp") or {}).get("sockets", []):
                prior = old.get(s["socket"])
                if prior and prior["peer_ip"] == s["peer_ip"] and all(
                    isinstance(r.get("bytes_received"), int) for r in (prior, s)
                ) and s["bytes_received"] > prior["bytes_received"]:
                    peers.add(s["peer_ip"])
            total = sum(e["encoded_bytes"] for e in events if e.get("remote_ip") in peers and
                        pair["start_unix"] <= e["start_unix"] <= e["end_unix"] <= pair["end_unix"])
            if total:
                matches += 1
                print(label, attempt, pair["start_unix"], pair["end_unix"], total,
                      pair["nft_packets"], pair["queue_sequence_delta"], pair["groups"])
        print(label, attempt, "accepted_pairs", accepted, "time_and_socket_matches", matches)
PY
```


Чтобы подтвердить путь, в обеих фазах нужны свежие медиабайты, рост downlink
Xray и очереди сверх фона, помеченный сокет к тому же CDN и прежний VPN-выход
обычного сайта. Сверь отсутствие служебной HTTPS-пробы в совпавшем интервале.
Если данных не хватает, укажи PARTIAL или UNKNOWN и конкретное поле. При
`remote_ip=null` медиабайты пригодны для проверки загрузки.

После подтверждённых фаз проверь восстановление. Убедись, что MainPID
`xgw-zapret2.service` владеет очередью Selected и действует таймер.
Останови только этот MainPID командой
`sudo systemctl kill --kill-whom=main --signal=SIGKILL xgw-zapret2.service`.
Зафиксируй снятие правила, fallback и новую передачу CDN через VPN.
Если Selective не прошёл, выполни короткий повтор контроля через VPN после возврата.

## 5. Возврат и автоматическая публикация

Если предохранитель был вооружён, отмени **своё** активное задание при наличии,
выбери off. Если панель недоступна, сразу вызови независимый возврат. При
автоматическом срабатывании сначала дождись завершения его service, затем проверяй
результат. Приведи исходный конфиг, VPN, панель и PID воркеров к проверенному
начальному состоянию. Останови свой монитор, если он ещё работает.

```bash
if ! sudo test -f "$BACKUP/restore-completed"; then
  sudo /bin/bash "$BACKUP/restore.sh" "$PY" unused "$BACKUP" "$PANEL" accept
fi
sudo sha256sum -c "$BACKUP/config-before.sha256"
sudo test -f "$BACKUP/restore-completed"
systemctl is-active xgw.service
systemctl show xgw-zapret2.service xgw-nfqws2.service -p ActiveState -p MainPID
"$PY" -m xgw.desync.client status >"$D/final.json"
```

После свежего off/off, рабочего VPN и панели останови именно `"$UNIT.timer"`.
Живой короткий монитор можно завершить командой `kill "$MON_PID"`, предварительно
сверив его командную строку и файл `$D/active.jsonl`. При провале видео повтори
один короткий контроль VPN на том же ролике после возврата.

При любом исходе опубликуй один новый отчёт. Укажи версии, сравнение чистого запуска и записи,
причины пропущенных шагов, для каждой попытки её режим/профиль, тип запуска,
пригодные секунды, прогресс, разрешение, байты и маршрут. Запиши состояние
после возврата. Сырые URL/IP, подписки, профили Chrome, сетевые журналы и куки
оставь на машине. Работай в отдельном checkout публикации.

```bash
git -C "$REPO" fetch origin "$BR"
git -C "$REPO" worktree add --detach "$D/publish" FETCH_HEAD
cd "$D/publish"
REPORT="docs/reports/$(date -u +%Y-%m-%dT%H%M%SZ)_playback-passive.md"
test ! -e "$REPORT"
```

Заполни `$REPORT` и выполни публикацию.

```bash
test -s "$REPORT"
git add -- "$REPORT"
test "$(git diff --cached --name-only)" = "$REPORT"
git diff --cached --check
git commit -m "docs: report passive Chrome playback and gateway route"
if ! git push origin "HEAD:refs/heads/$BR"; then
  git fetch origin "$BR"
  git rebase FETCH_HEAD
  git push origin "HEAD:refs/heads/$BR"
fi
SHA=$(git rev-parse HEAD)
git fetch origin "$BR"
git merge-base --is-ancestor "$SHA" FETCH_HEAD
printf 'https://github.com/1521572-lang/xgw/blob/%s/%s\n' "$SHA" "$REPORT"
```
