Ключевой результат — **гипотеза версии HTTP исключена окончательно**:

1. curl предлагал h2 в ALPN (попытка 2: offered `["h2","http/1.1"]`) — сервер не выбрал
   (`alpn_selected=none`), ответ пришёл по 1.1.
2. Сам Firefox на этом же пути и этом же ресурсе использовал **HTTP/1.1** (`browser_
   protocol=http/1.1`) — и успешно скачал 393 КБ.
3. Оба клиента, одна версия HTTP (1.1), один URL, один VPN-выход, один служебный вход:
   плеер получает полное тело, curl — детерминированную заглушку 31 байт (content_type=other,
   без Content-Length). Отличие осталось только в **контексте запроса**: заголовки/куки либо
   отпечаток TLS-клиента (ClientHello браузера против curl), которые сервер видеосети
   различает. Ответ сервера не зависит ни от Range (r8), ни от версии HTTP (r9, r11), ни от
   выбора кандидата (r6–r7).

Сверки: `verification=ok`, `xray_config_changed=false`; diag после — OK — 32, WARN — 1,
FAIL — 0 (тот же WARN до и после); capture on, zapret2 off. Временный Firefox завершён,

Просьбы разработчику на следующий раунд:

1. Решающий тест контекста: тем же Marionette выполнить `fetch()` выбранного URL в контексте
   страницы и записать только статус/объём (тело не публиковать). Если Firefox получает
   полное тело из страницы — зависимость от клиентского контекста (заголовки/куки/отпечаток
   TLS) подтверждена окончательно.
2. Если (1) подтвердится — архитектурный вывод для ТЗ zapret2: видеодомен не проверяется
   голым GET вне браузерного контекста; варианты: проба видео силами самого браузера
   (наблюдение плеера уже есть), статический файл ≥16 КиБ на домене видеосети, скачанный
   тем же браузером, либо фиксация ограничения в документации и перенос видеопробы на
   страницу/иные домены.
3. Сохранившие актуальность развилки: `--http2-prior-knowledge` теперь малоинформативен
   (сервер и так не выбирает h2), но можно включить как контроль — ожидание: заглушка
   останется заглушкой.
