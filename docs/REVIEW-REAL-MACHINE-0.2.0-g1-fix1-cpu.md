## CPU и квота — приняты в объёме наблюдений

180,1 с, 36 срезов; все три источника маскирования прочитаны. Среднее по четырём CPU —
72,1 %, пик 84,5 %. Демон 11,8 % одного ядра, около 3 % общей мощности машины; пик демона
61,4 % одного ядра. RustDesk и два процесса zcode суммарно дали 188,4 % одного ядра,
около 47,1 % всей машины. В данном окне они составили большую часть наблюдаемой нагрузки.
Это не доказывает, что обрывы вызваны ими, и не исключает отдельные задержки XGW/сети.
Трей 0,0 %, два процесса. Сервер панели разделяет процесс демона; frontend NOT_SEPARABLE.
Фразу отчёта «а не шлюз» следует читать как сравнение средней нагрузки этого окна.
Количество всех наблюдавшихся процессов из top10 не определяется: top10 — только список лидеров.
Новый CPU-прогон для уточнения этих ограничений не назначается.

Суточный прогноз: проверки 893,0 МБ, сквозная 248,9 МБ, вместе 1141,9 МБ, около 34,3 ГБ/30 дней.
Лимит 1024 МБ в существующем расчёте сравнивается с total_mb, без e2e.
Подписка №1: quota_mb=2445,2 МБ квоты/сут с ценовыми множителями;
quota_share=1,1 % полной квоты за 30 дней; warnings пуст.
Это не доля суточного бюджета и не фактическое списание провайдером.
C05/C06 предстоит журнал фактически прочитанных байтов и резерв проверок здоровья;
не приписывать всей подписке общий трафик и не ослаблять обнаружение отказов ради экономии.

## G1 — PARTIAL, непрерывность пока не принята

Install/health/source match rc0; on/HTTPS и связь сохранены, diag 36 OK/1 WARN/0 FAIL.
Настройки и ручной выбор сохранены; истечение прежнего TTL не проверено.
При установке наблюдались legacy→blue→green, два drain завершились.
Однако process_limit=2 — значение политики, не измеренный максимум процессов;
свойства unit не заменяют UID/CapEff работающих процессов.
status_within_25=true до rotate также не доказательство: помощник инициализировал флаг true,
а цикл наблюдения ещё не начался. Приёмка интервалов G1 остаётся NOT_RUN.
Первая загрузка: HTTP 206, BODY_OR_HTTP/0 Б/0 с. Код помощника возвращал этот отказ
при несовпадении диапазона или Content-Length до первого read тела.
Содержимое заголовков не записано: точную причину восстановить по отчёту невозможно.
Нулевые прочитанные байты здесь не доказывают пустое тело, блокировку VPN или действие ТСПУ.
Rotate/вторая загрузка/одновременные мосты NOT_RUN; автоматически наблюдавшиеся drain
не являются приёмкой непрерывности уже установленного TCP-соединения.
