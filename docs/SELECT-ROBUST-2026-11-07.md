# Устойчивый выбор подключения — фактическое состояние и правки (07.11.2026)

Сверено с `freepool` 7faa586 (ссылки ниже — на этот коммит). Принятые отчётами PR-1…PR-3
(п. 315–317) не трогались, G1 и REC-C не возвращались. Одна волна — одно изменение. Волна 1 —
ASSUMPTIONS п. 330, ТЗ scan-pacing, отчёт PASS; волна 1б — п. 332 и 334, ТЗ diag-limit и
r2, PASS; волна 2 — п. 336, ТЗ profile-memory. Правки строк «волна 3–4» подготовлены и
ставятся по одной, каждая после отчёта по предыдущей; их сроки и значения записываются в
свой пункт ASSUMPTIONS вместе с кодом.

Волна 4, зеркала подписок: настроенных владельцем или поставщиком зеркал нет — интеграция
отложена без спящего адаптера; правка — только причина кэша и поля статуса. Что старый набор
не отменяет сроки действия, запреты владельца и исчерпание квоты, проверяется в волне 4.

Сопоставление с прежним ТЗ TS-ANTI-TSPU-HARDENING: PR-4 — волны 1 и 1б, кроме
base_ping и встроенных проб Xray (нужен свой планировщик проб ядра — отдельная задача); PR-5
(матрица транспортов, pcap ClientHello) — не реализован, параллельной матрицы нет: волна 3
берёт только существующую классификацию `_transport`.

Не входят: Stealth, AmneziaWG, NaïveProxy, Mullvad QUIC/LWO, DAITA, zapret, dae — нужен
совместимый сервер; польза — иной вид рукопожатия и потока. Блокировку IP дробление не
снимает: нужен другой доступный адрес. Невидимость для ТСПУ не заявляется.
