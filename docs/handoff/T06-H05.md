# T06/H05 — статический и клонированный ClientHello на ThinkCentre

[Отчёт T06](../reports/2026-11-16_desync-t06-preflight.md) подтвердил запуск обоих воркеров
после хотфикса симлинка и чистый опыт AutoTTL. При SYN/ACK с TTL 58 в прогретом процессе Lua
увидела 62 из кэша. Рабочий режим после отчёта — off/off со штатным VPN, acct=0. На основном
WAN остался процесс захвата из прежнего опыта.

Исполнитель сама выполняет команды, браузер, vision и публикацию на Ubuntu **24.04 LTS**.
При отсутствии доступа к терминалу, sudo или GUI запроси его.

## 1. Завершить старый захват, подготовить лабораторию

Сначала проверь процесс из отчёта, PID 1935908. Сверяй время старта, исполняемый файл
`tcpdump`, интерфейс и открытый файл именно того опыта. Если PID отсутствует или относится к
другой команде, его оставь. Если это прежний захват, проверь рост файла и аккуратно отправь
TERM с консоли хоста. При EPERM проверь, что консоль и процесс в нужном user namespace,
и фактические real/saved UID в `/proc/PID/status`. Если sudo позволяет действовать от
этого UID, отправь `sudo -u "#$CAPTURE_UID" /usr/bin/kill -TERM -- "$PID"` после повторной
сверки личности процесса. Зафиксируй остановку и стабильный размер файла. Если права
по прежнему отсутствуют, запроси доступ к консоли хоста. Содержимое PCAP оставь на стенде.
[Права на сигнал в Linux](https://man7.org/linux/man-pages/man2/kill.2.html).

Зафиксируй исходные PID, пустую очередь, хэши конфигов, штатный VPN, offload и значение
`nf_conntrack_acct`. Используй существующий dev-venv. Код предыдущего хотфикса уже в BASE.

```bash
set -euo pipefail
umask 077
test -z "$(git status --porcelain)"
REPO=$(git rev-parse --show-toplevel)
git fetch origin integration/zapret2-batch1
CODE=$(git rev-parse FETCH_HEAD)
BASE=3e6a655
git merge-base --is-ancestor "$BASE" "$CODE"
D=$(mktemp -d "$HOME/xgw-h05.XXXXXXXX")
git worktree add --detach "$D/source" "$CODE"
cd "$D/source"
. /etc/os-release
test "$ID" = ubuntu && test "$VERSION_ID" = 24.04
python3 -m pytest --portable tests/test_desync_experiment.py tests/test_zapret2.py \
  tests/test_desync_worker.py
sudo timeout --kill-after=20s 240s bash docs/helpers/desync_t05_ttl_lab.sh "$D/h05-lab" h05
```

Лаборатория использует изолированные namespaces и тот же генератор argv, что штатные
профили. Для обоих образцов проверь `--intercept=0`, совпадение тела HTTPS побайтово,
`XGW_H05 … result=sent`, MD5-опцию на fake в PCAP и продолжение TLS. Сравни размеры fake,
число TCP-сегментов и разбиение настоящего ClientHello. Захват содержит до 2048 байт на
пакет и ограничен временем и числом записей. Читай только локально, например через
`tcpdump -nn -vv -r`. Запиши отдельно, была ли `reassembled=0` хотя бы в одном случае.
Если все образцы собраны из нескольких пакетов, отметь проверку однопакетного случая
как неполную. Если есть свободное окно, можно повторить контроль TTL со значением `ttl`
последнего аргумента, отдельным каталогом и таймаутом 480 с. Сверь автоматическое восстановление acct,
отсутствие остатков namespaces/захватов и доступность штатного VPN.

Общий Lua меняет случайные поля и SNI в обоих вариантах, включая ClientHello из одного
пакета. При невозможности собрать и изменить fake отправка fake пропускается.
`result=sent` означает принятие отправки ядром; доставку показывает только наблюдение
на серверном интерфейсе.

## 2. Установка и пары в обычном Chrome

Используй [порядок установки T06](T06-PREFLIGHT.md#3-установка-и-живые-проверки-двух-воркеров)
и [шаблон таймера T05](T05-SYNACK.md#установка-четырёх-файлов-и-независимый-возврат).
Отличающиеся параметры ниже. Из исходной базы архивируй только существующие файлы:

```bash
FILES=(src/xgw/desync/schema.py src/xgw/nfqws2.py src/xgw/zapret2.py)
UNIT=xgw-desync-h05-rollback
PAYLOAD="/opt/xgw/handoff/desync-h05-$CODE"
BACKUP="/var/lib/xgw/handoff/desync-h05-$CODE"
sudo test ! -e "$PAYLOAD"
sudo test ! -e "$BACKUP"
sudo install -d -m 0755 "$PAYLOAD/code" "$PAYLOAD/base"
git archive "$CODE" "${FILES[@]}" src/xgw/desync/h05.py \
  docs/helpers/desync_batch1_install.py | sudo tar --no-same-owner -x -C "$PAYLOAD/code"
git archive "$BASE" "${FILES[@]}" | sudo tar --no-same-owner -x -C "$PAYLOAD/base"
```

В prepare/apply/rollback, включая restore.sh, используй `--h05-profiles`. Сверь все четыре
хэша и восстановимость конфигов. Запусти таймер перед установкой, перезаряди перед сетевой
фазой. До первой пары проверь в Standalone штатный `hostfakesplit_md5` минимум 2 минуты.

Политику меняй штатным `managed.set_desync` по
[set_standalone T04](NEXT_STEP.md#активация-standalone). Во всех фазах оставь те же шесть
доменов YouTube, очередь 201 если свободна, engine=off, `probe_urls=[]`,
`observe_synack=false`, `observe_reply_packets=0`, `retry_seconds=60`. Для очереди используй
`policy["runtime"]["queue_num"]`. Меняется только `policy["selected"]["strategy"]`.

Проведи **A/B/B/A**: A=`fake_static_md5`, B=`fake_clone_md5`. Перед каждым опытом дождись
соответствия политики в API, активного gate и нового владельца очереди; между фазами
проверь остановку предыдущего воркера по протоколу T03. Открывай отдельный тестовый профиль
обычного Chrome с QUIC off, ролик `8plwv25NYRo`, фактическое 720p, скорость 1× и та же сеть.

- Дай до 60 секунд на появление содержимого видео. При старте собери минимум 180 секунд
  полезного просмотра. Ошибку страницы, autoplay, рекламу, login и сетевое ожидание учитывай
  отдельно. Если обе пары не дали устойчивого старта, повтори короткий контроль
  `hostfakesplit_md5` в тех же условиях и закончи.
- Собирай показатели плеера и медиазапросы [сценарием обычного Chrome](YOUTUBE-TELEMETRY.md).
  Подтверди свежий SABR, выход `xgw-zapret2`, очередь и отсутствие VPN-мостов. На рабочем WAN
  используй счётчики и браузерный журнал, без новых tcpdump-процессов.
- Для каждого варианта запиши старт, время в 720p, остановки, буфер, медиабайты, queue drops,
  CDN и протокол. Отметь исходы ограниченных строк `XGW_H05` по каждому поколению, без полного
  журнала. Если условия изменились или запись неполная, пометь соответствующую пару.
- При двух успешных подходах кандидата по возможности проверь его дольше, 15+5 минут.
  Сначала перезаряди таймер. Эффект оценивай на этой линии и в измеренных условиях.

## 3. Восстановление и автоматическая публикация

Вызови restore с `accept`, если слой исправен, или `rollback` при регрессии. Сверь
off/off, исходные хэши, VPN, acct, очередь и offload. Затем останови таймер. Если кандидат
слабее штатного, это результат сравнения; источник fake не назначай новым профилем по умолчанию.

```bash
cd "$REPO"
git fetch origin integration/zapret2-batch1
git switch -c "glm/desync-h05-$(date -u +%Y%m%dT%H%M%SZ)" FETCH_HEAD
REPORT="docs/reports/$(date +%F)_desync-t06-h05.md"
# Сама создай REPORT с итогом каждого этапа, SHA и оставленным состоянием.
git add "$REPORT"
git diff --cached --check
git diff --cached
git commit -m "docs: measure static and cloned ClientHello on Ubuntu 24.04"
git push origin HEAD:integration/zapret2-batch1
git ls-remote origin refs/heads/integration/zapret2-batch1
```

При гонке сделай fetch/rebase и обычный push. Публикуй и частичный результат. Укажи,
остановлен ли старый захват, а полный журнал и PCAP оставь на стенде.
