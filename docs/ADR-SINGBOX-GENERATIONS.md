# ADR: два поколения только для sing-box

## Решение

SIGHUP sing-box не используется для смены рабочего состава. Новый процесс получает свой
конфиг, порты мостов и Clash API. Генератор сохраняет пароль и протокол существующих мостов;
новое поколение использует mixed-входы с теми же SOCKS-учётными данными и HTTP для проверки.
Проверка — полный GET настроенной probe.url через хотя бы один используемый новый мост.
Недоступные отдельные серверы допустимы; это не приёмка всех серверов или новых профилей.

Подготовка, запуск и запрос идут в фоне рядом с уже существующей фоновой сборкой.
Перед переключением шаг демона заново проверяет актуальность настроек, инвентаря, ручного
выбора и исходных конфигов. Устаревший кандидат прекращается. CLI использует тот же путь.
Только шаг демона либо явная команда CLI меняют Xray через API; Xray не получает своих поколений.

Теги SOCKS-outbound сохраняются. В их обработчиках меняется порт назначения, поэтому новые
соединения и новые GET-пробы burstObservatory идут в новое поколение. Уже начавшиеся запросы
могут закончиться в старом. Старый процесс живёт ещё 300 секунд, затем останавливается.
Это ограниченное ожидание: соединение длиннее drain может оборваться на его конце.

Одновременно допускаются два процесса: рабочий и кандидат/уходящий. Новое переключение
ждёт освобождения второго места. Запрос stop выполняется без ожидания в шаге; место считается
свободным только после MainPID=0 и inactive/failed либо исчезновения unit, а не по одному
is-active. Проверка процесса, остановка и запуск — конкретные операции sing-box.

Процессы blue/green — transient systemd units, без новых постоянных шаблонов или таймеров.
Ограничения берутся из установленного обычного unit по явному списку свойств; обязательны
xgw-singbox, пустые capabilities, NoNewPrivileges и ProtectSystem=strict. Конфиги root:группа
ядра, 640. UID-обход Netfilter остаётся прежним, метка сокетов для мостов не добавляется.

Короткое состояние перехода хранится в /run/xgw, конфиги поколений — рядом с основным.
Перезапуск демона сохраняет состояние и процессы. ExecCondition обычного unit предотвращает
дубликат, когда main service снова запрашивает Wants=xgw-singbox. После reboot transient
units и /run исчезают: обычная служба запускает последний основной конфиг с выбранными портами.

## Отказы и возврат

Не прошли check/реальный GET/свежесть — кандидат прекращается до API, старое остаётся.
План с изменением статических секций Xray отклоняется: G1 не вызывает restart ради переключения.
Перед первой API-записью ставится существующая отметка api-dirty. Ошибка API вызывает
восстановление только затронутых обработчиков и маршрутов. Если исход не доказан, оба ядра
сохраняются, отметка остаётся и третье поколение запрещено. Статус прямо просит восстановление.
Падение после принятого API-конфига распознаётся по его отпечатку и завершает публикацию
конфига sing-box; неподключённый кандидат умершего процесса убирается отдельно.

Для возврата ПО сначала используется штатная команда `xgw singbox legacy --yes`, затем
обычный install.sh предыдущего коммита. Прежний код не управляет transient поколениями.
Команда возврата прерывает соединения sing-box и при api-dirty восстанавливает Xray его
штатным перезапуском. Это явный шаг с согласием владельца, не автоматический фоновой rescue.

## Граница доказательств

Стандартный [mixed inbound](https://sing-box.sagernet.org/configuration/inbound/mixed/)
совмещает SOCKS и HTTP. [systemd-run](https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html)
управляет отдельным transient service; Type=exec не заменяет прикладную проверку запроса.
В [Xray Handler.Close](https://github.com/XTLS/Xray-core/blob/main/app/proxyman/outbound/handler.go)
закрываются mux и proxy; [SOCKS-клиент](https://github.com/XTLS/Xray-core/blob/main/proxy/socks/client.go)
держит TCP-соединение в обработке запроса. У мостов XGW нет mux Xray. Это основание решения,
а сохранение длинного соединения на установленном бинарнике требует приёмки ThinkCentre.
Короткий GET подготовки не доказывает скорость, регион или пригодность нового профиля:
C05/C06 и следующие транспортные изменения остаются отдельными пунктами.
