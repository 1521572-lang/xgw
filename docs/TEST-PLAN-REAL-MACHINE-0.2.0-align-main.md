# Обычная установка main и измерение loaded

Цель: заменить смешанную установку целой main, сохранить рабочий on, измерить проверку правил.
Версия остаётся 0.2.0. Это пункт 0; поколения sing-box здесь не внедряются.
Критерии до прогона: штатный установщик rc0; весь установленный пакет и packaging совпадают
с выбранным main; демон active, перехват on без blocked, Xray отвечает, HTTPS 2xx/3xx;
loaded в отдельном процессе true; барьер имеет output в POSTROUTING, счётчики читаются;
эффективные настройки и ручной выбор сохранены. Все FAIL/WARN diag разобраны по смыслу.
Недоступность отдельных серверов и DEGRADED сами по себе не провал. Длительность loaded —
справочная, включая значения больше 5, 8 и 60 с. Не менять критерии после прогона.

Разрешены любые инструменты: терминал, панель, браузер, машинное зрение, API для чтения.
Можно повторять чтение, ждать дольше, менять пути/кавычки/sudo под окружение; записать отклонение.
Для диагностики читать status/diag/logs, journalctl, nft list, ip rule/route; сырьё приватно.
STOP только если продолжение угрожает on или выходит за согласованные действия.
Не менять вручную WAN/LAN/Tailscale, подписки, пул, pin и настройки. Не выполнять off,
uninstall, --force, старые fault-тесты или установку отдельных файлов. Коммитить только отчёт.
На пункт один прогон, максимум два повтора только после конкретной правки разработчика.
Повтор чтения и расчёт из сохранённых данных не являются новым прогоном установки.

## 1. Подготовить обычные Git-исходники — без установки

В существующем клоне выбери freepool; сохрани незакоммиченную работу, не делай reset/clean.
Ниже предполагается `~/xgw`; другой путь разрешён. Команды выполнять в одном shell-сеансе.
```sh
cd ~/xgw
git status --short
git switch freepool
git fetch origin
git merge --ff-only origin/freepool
MAIN=57756aa223633be528a75cf35973c9d8e0b15ca8
PREVIOUS=351fb54e074f4a7b497a8a4244fc74c6088788d7
test "$(git rev-parse origin/main)" = "$MAIN"
git cat-file -e "$PREVIOUS^{commit}" || git fetch origin "$PREVIOUS"
TARGET="$HOME/xgw-main-57756aa"
ROLLBACK="$HOME/xgw-before-background-351fb54"
git worktree add --detach "$TARGET" "$MAIN"
git worktree add --detach "$ROLLBACK" "$PREVIOUS"
HELPER="$PWD/docs/helpers/align_main.py"
printf '%s  %s\n' 'f29a7dae46c5523afa0ca78fcb6f7bda0d9d32713c32025b3b6ecc4f03c125da' "$HELPER" | sha256sum -c -
```
Ожидается: чистый клон, main совпадает, две detached worktree, сумма OK. Если каталоги уже
есть — проверить `git -C "$TARGET" rev-parse HEAD` и аналогично ROLLBACK, а не пересоздавать.
Если main уже другой или рабочие файлы изменены — прочитать различия и уточнить базу у владельца.
Откат 351fb54 — прежняя целая рабочая база, а не точная копия смешанной установки.
От main её отличают только daemon.py и watch/status.py; установщик, сеть и барьер одинаковы.

## 2. Исходное состояние — только чтение

Выделить приватный каталог. Если он уже есть — прочитать прежний результат и продолжить
соответствующий шаг; не запускать вторую установку и не удалять следы ради prepare.
```sh
sudo install -d -m 700 /run/xgw-align-main
sudo python3 "$HELPER" health before
sudo python3 "$HELPER" snapshot before "$TARGET"
sudo python3 "$HELPER" report
```
Ожидается «Рабочий on и HTTPS подтверждены» и «Сводка сохранена; отдельные неизвестные
результаты не скрыты». before_snapshot.source может быть false: сейчас смешанная установка.
Изучить приватные `/run/xgw-align-main/before-*.json`; JSON status/diag — данные продукта.
До установки должны читаться настройки и подтверждаться on/HTTPS; иначе диагностировать
чтением, продолжить независимые измерения шага 5, установку пока не начинать.
diag rc1 сам по себе не STOP: отличить недоступные серверы от отсутствия сети/барьера/демона.
Счётчики накопительные; это не новый десятиминутный тест их неизменности.

## 3. Получить согласие владельца на конкретную установку и условный откат

Спросить: «Разрешаете штатную установку main 57756aa и, если она завершится ошибкой или
рабочий on/HTTPS после неё не подтвердится, штатный откат на 351fb54 через install.sh?»
Объяснить: установщик останавливает/запускает демон, переписывает код и units, повторно
применяет прежний LAN-профиль и правила; при необходимости обновляет/перезапускает ядра.
Рабочий установленный WAN-профиль сохраняется. Возможен краткий разрыв VPN/связи.
Настройки сети вручную не менять. Согласие на прошлую подмену двух файлов сюда не переносится.
Если согласия нет — INSTALL_NOT_RUN, только чтение и отчёт. Принятой установку не объявлять.

## 4. Выполнить установку; откат заранее находится в той же локальной команде

Запустить целиком в локальном терминале ThinkCentre или доступной устойчивой сессии.
Дать не менее 30 минут, при работе установщика ждать дольше. Не обрывать его таймаутом UI.
Не нужны новый systemd unit, таймер, guardian или приватная копия исходников.
Даже при потере связи следующий шаг выполняет уже запущенный shell, а не новая команда модели.
```sh
sudo -v
sudo sh -s -- "$TARGET" "$ROLLBACK" "$HELPER" <<'SH'
umask 077
dir=/run/xgw-align-main
sh "$1/packaging/install.sh" --yes >"$dir/install.log" 2>&1
install_rc=$?
printf '%s\n' "$install_rc" >"$dir/install.rc"
python3 "$3" health after >"$dir/health-after.log" 2>&1
health_rc=$?
printf '%s\n' "$health_rc" >"$dir/health-after.rc"
if [ "$install_rc" -ne 0 ] || [ "$health_rc" -ne 0 ]; then
    sh "$2/packaging/install.sh" --yes >"$dir/rollback.log" 2>&1
    printf '%s\n' "$?" >"$dir/rollback.rc"
    python3 "$3" health rollback >"$dir/health-rollback.log" 2>&1
    printf '%s\n' "$?" >"$dir/health-rollback.rc"
fi
printf '%s\n' 'Локальная последовательность завершена; прочитайте сохранённые результаты'
SH
```
Ожидается install.rc=0, health-after.rc=0, rollback.rc отсутствует. Возврат внешнего shell
не заменяет эти rc. Полные install.log/rollback.log приватны: установщик печатает токен панели.
Если связь пропала — после возврата сначала проверить локальный терминал, файлы rc и status;
дождаться работающей последовательности. Затем продолжить шаг 5, не повторять установку.
Если последовательность была прервана, она уже не работает и on сломан — разрешённый возврат:
```sh
sudo sh -c 'umask 077; exec sh "$1/packaging/install.sh" --yes > /run/xgw-align-main/rollback-recovery.log 2>&1' sh "$ROLLBACK"
sudo python3 "$HELPER" health rollback
```
Не показывать установочный лог в отчёте.
Если штатный возврат тоже не восстановил on — не продолжать изменения; сообщить владельцу
состояние без секретов и разобрать приватные логи. Не запускать uninstall/off.

## 5. Сводка и первый loaded в отдельном процессе

После успешной main установить label=after и source=TARGET; после отката — rollback/ROLLBACK.
Установка не удалась — это partial, даже если возврат прошёл. Независимые измерения сохранить.
```sh
LABEL=after
SOURCE="$TARGET"
sudo python3 "$HELPER" snapshot "$LABEL" "$SOURCE"
sudo python3 "$HELPER" loaded
sudo python3 "$HELPER" report
```
Ожидается source=true, settings_unchanged=true, postrouting=true и численные счётчики;
loaded=true с seconds. Первая loaded внутри этого Python-процесса не прогревается describe.
Команда loaded не имеет внешнего обрыва через 8 с: ждать минимум 60 с и дольше, пока работает;
время само по себе не причина отказа. Ошибка loaded не скрывает status/diag/барьер.
Если loaded=false/unknown, прочитать правила/маршруты и логи, можно повторить только чтение;
не чинить сеть без отдельного согласованного действия. Разделить первый и повторный замер.
Если settings_unchanged=false — приватно сравнить настройки и pin; естественное истечение
ранее заданного TTL описать отдельно, ручной выбор не сбрасывать и срок не продлевать.
Если loaded больше 5 с, один дополнительный профиль, тоже в новом процессе:
```sh
sudo python3 "$HELPER" profile
```
Это чтение; профилировщик добавляет накладные расходы. Функции вложены: их времена не складывать.
Если нужна дешёвая правка — разработчик сделает отдельный коммит по этому профилю;
исполнитель исходники помощника/продукта не подменяет. Результат не означает проверку LAN-клиента.

## 6. Один отчёт и публикация

Свободно использовать зрение и другие инструменты для проверки панели/терминала приватно.
Не публиковать сырой JSON, логи, конфиги, скриншоты, хеши настроек, адреса и имена.
Шаблон на одну страницу — заполнить фактами, неизвестное явно обозначить:
```text
# Обычная установка main — ДАТА
- База main 57756aa; прежняя база 351fb54; helper SHA; согласие: да/нет.
- Установка rc: ...; health после rc: ...; откат rc: NOT_RUN/...; итоговая база: ...
- До/после: HEALTHY или DEGRADED/другое; daemon active, on, Xray, HTTPS: ...
- Совпадение всего пакета и packaging: ...; эффективные настройки и ручной выбор: ...
- diag до/после: OK/WARN/FAIL количества; смысл оставшихся замечаний без имён: ...
- Барьер до/после: POSTROUTING ..., счётчиков ..., пакетов ..., байтов ... (накопительно).
- Первый loaded: true/false/unknown, ... с; повтор: NOT_RUN/...; профиль: NOT_RUN/... .
- Отклонения, восстановление связи и оставшиеся неизвестные: ...
- Итог: PASS / PARTIAL / INSTALL_NOT_RUN; LAN/UDP/IPv6, faults и PR-G1 здесь NOT_RUN.
```
При partial/failure отчёт тоже разрешён: не скрывать завершившуюся неудачную установку.
Записать `docs/TEST-REPORT-REAL-MACHINE-0.2.0-align-main-ДАТА.md` в исходном клоне freepool.
Перед коммитом проверить приватность и `git diff --cached --name-only`: только этот отчёт.
```sh
git add -- docs/TEST-REPORT-REAL-MACHINE-0.2.0-align-main-ДАТА.md
git diff --cached --check
git commit -m "Отчёт обычной установки main на шлюзе"
git fetch origin
git rebase origin/freepool
git push origin HEAD:freepool
```
Конфликт rebase — не менять код/старые отчёты ради push; сохранить новый отчёт и сообщить.
После приёмки пункта 0 разработчик предложит слияние документов; дальше минимальный PR-G1.
