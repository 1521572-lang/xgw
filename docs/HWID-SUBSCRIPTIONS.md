# Подписки с привязкой к устройству (HWID)

Некоторые провайдеры отдают полный список серверов только клиентам, которые
представились идентификатором устройства — заголовком `X-HWID`. Остальным в ответ
приходит заглушка: одна «ссылка» вида `vless://000…@0.0.0.0:1` с именем
«Приложение не поддерживается!». Наблюдение на подписке `subs.vpber.store`
(октябрь 2026): без заголовка — заглушка, с чужим идентификатором — сообщение о
лимите устройств, с известным провайдеру — полная подписка из 16 серверов.

XGW умеет отправлять заголовки вместе с запросом подписки.

**Подписка из панели**: панель → «Подписки» → «Изменить подписку» → «Заголовки» —
по одному заголовку в строке:

```
X-HWID: <идентификатор устройства>
```

**Подписка из `config.toml`** (её панель изменить не может):

```toml
[[subscriptions]]
name = "main"
url = "https://subs.example.org/TOKEN"
headers = { X-HWID = "<идентификатор устройства>" }
```

## Где взять идентификатор

- **Linux** — это содержимое `/etc/machine-id` (Happ использует то же значение,
  его видно в «О программе»):

  ```bash
  cat /etc/machine-id
  ```

- **Другие системы** — Happ → «О программе», строка `HWID`; в других клиентах —
  экран «О программе» или настройки подписки.

Берите идентификатор **уже известного провайдеру устройства** — например, этого
компьютера из Happ. С незнакомым идентификатором провайдер может ответить
сообщением о лимите устройств, пока в тарифе не освободится слот: новый слот
занимает именно идентификатор, а не программа. XGW с тем же идентификатором, что
и Happ на этой же машине, лишнего слота не расходует.

## Что видно в ответе

Формат ответа провайдер может выбирать по User-Agent: клиенту Happ — JSON-конфиги
Xray, остальным — обычную base64-подписку (XGW разбирает оба формата, менять что-то
не нужно).

Ответ, в котором нет ни одного сервера, кроме служебных (`0.0.0.0`, loopback),
XGW считает сбоем подписки: причина видна в панели и на карточке подписки, а
серверы берутся из последней удачной версии в кэше (если она есть). Такой ответ
кэш не затирает.

## Проверка вручную

```bash
curl -sS -D - -o /dev/null --header 'X-HWID: <идентификатор>' 'https://subs.example.org/TOKEN' | grep -i x-hwid
```

`X-Hwid-Active: true` — устройство принято, `X-Hwid-Max-Devices-Reached: true` —
слоты закончились (устройствами управляют у провайдера, обычно через бота).

## Приватность

Идентификатор — не ключ шифрования, но постоянная метка устройства. В панели он
хранится в `panel.json` (права 600 root), значения заголовков подписок XGW считает
секретами: журналы и `xgw logs` маскируют их так же, как токены в адресах подписок.
