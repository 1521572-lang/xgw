## Наблюдения для Codex

1. **Причина прошлых SYN-SENT найдена на уровне сети, не Selective**: старый CDN-IP
   B не отвечает на SYN по прямому WAN (bypass-метка, timeout 5 с) при идентичных
   решениях ядра для обеих меток — маршрутизация не различает пути; доступность B
   только через VPN. Новый endpoint C доступен direct — Selective прошёл все пробы
   с первой попытки. Следствие: зависимость «проба флапает» из r4/r5/TCP-раунда —
   это свойство конкретных CDN-endpoint'ов (доступность direct), а не состояния
   очереди. Рекомендация: при fallback по youtube_cdn_probe_failed предлагать
   обновление адреса (свежий endpoint от плеера) — как это уже разрешено ТЗ ветвлением.
2. Quick-probes (page 871→405→692 мс, CDN 193→223→234 мс) — стабильные значения на
   новом endpoint; перепроверки на одной ревизии работают как задумано.
3. Пара route_evidence в active-фазе по-прежнему отвергается toggle-ом applied-config
   Xray (probe-inbound на каждом check-цикле); прибор честен, но для приёмки пути
   медиа нужен способ сериализации без смысловых изменений (см. r3/TLS наблюдения).
4. NFQUEUE-счётчик (queue 200) растёт при реальной передаче (47→91), но в коротком
   окне после seek окна буферизации медиа-сегменты не качаются — для приёмки роста
   «у того же владельца» окно надо снимать сразу после исчерпания буфера либо на
   низком буфере.
