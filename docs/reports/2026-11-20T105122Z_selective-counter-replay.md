## §3 Объяснение

- В сопоставленных окнах, где счётчик zapret2 не вырос, счётчик группы
  xray (VPN) рос положительно — то есть в этих интервалах трафик группы
  VPN присутствовал, а исчисляемый outbound zapret2 держался ровно в нуле
  при нулевом фоне. Это выбор «нулевой счётчик»: счётчик работал, но не
  учитывал ни байта, тогда как очередь NFQUEUE в тех же окнах имела
  положительные дельты сверх фона (queue_above_background=true).
- Возможное объяснение (гипотеза, для потоковой проверки): медиасокет
  initial был к другому CDN-peer (по сэмплам плеера initial — peer
  `172.217.x.x`, seek — `77.37.252.211`, тот, что подтверден pin-пробой);
  если адрес initial не попал в набор выбранного пути zapret2, байты
  пошли через counted-аутбаунд группы xray, а очередь наблюдала только
  служебный/фоновой поток. Для привязки «peer → счётчик» нужны отдельные
  наблюдения по потоку (как отмечено в ТЗ), в объём этого прохода они не
  входят. Статусы маршрута переносятся из пересчёта без переклассификации:
  initial=PARTIAL, seek=SUPPORTED.
- Качество видео, fallback и VPN-сайт — из живого отчёта
  `2026-11-20T103848Z_selective-media-proof-r2.md` без изменений.
