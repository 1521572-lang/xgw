которым плеер отличается от повторного GET, в Resource Timing не виден — наблюдаются только
URL и объёмы. Полезное следствие: медиа-данные через этот VPN-выход реально проходят (533 КБ

Просьбы разработчику на следующий раунд:

1. Публиковать в ATTEMPT `content_type` ответа повторного GET (метка без тела) — 31-байтовая
   заглушка, вероятно, отличима по Content-Type от видео; это сразу сузит класс причины.
2. Варианты пробы с контекстом: повторный GET без своего `Range`-заголовка (если в URL есть
   собственный параметр `range=` — не перебивать его); повтор с тем `User-Agent`, что у плеера

   которых в повторном GET по плану нет (Redirects=0 в обеих попытках).
3. Если заглушка подтвердится для всех форм голого GET — архитектурный вывод для ТЗ zapret2:
   проба видеосети голым GET может быть невозможна в принципе, и видеопробу нужно строить
   на ином типе адреса (например, статический файл крупного размера на том же домене — как
   robots.txt из отчёта gui-zapret2, но ≥16 КиБ), либо признать оба пути NOT_RUN для видео.
