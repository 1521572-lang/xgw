## §2 Диагностика: почему вкладка не становится hidden

1. Переключение вкладки **происходит**: скриншоты подтверждают, что
   после `bring_to_front()` активной становится вторая вкладка (заголовок
   окна и содержимое сменились), при этом первая вкладка продолжает
   сообщать `visibilityState = 'visible'`.
2. Одновременно **обе** вкладки сообщают `document.hasFocus() = true`;
   свёртывание окна через CDP тоже не переводит страницы в hidden.
3. Воспроизведено на: системном Chrome 158 (запуск Playwright),
   встроенном Chromium Playwright, вручную запущенном Chrome с
   подключением CDP.
4. **Решающий контроль без какой-либо автоматизации**: два файла
   file:// с собственной записью событий visibilitychange в DOM;
   переключение вкладок реальной клавиатурой (активная вкладка
   подтверждена скриншотами) — в журнале страниц **нет ни одного
   события hidden**, только visible. То есть страница сама не
   получает скрытие: сигнал не возникает в браузере вообще.
5. Корень: известный апстрим-регресс Chromium на Linux начиная с
   M145 — свёрнутые/скрытые окна сообщают видимость, и
   `visibilitychange → hidden` не возникает (crbug 556065499). Оба
   локальных браузера (Chrome 158, встроенный Chromium) новее M145.
   Этот же регресс объясняет результат P2.9 во встроенном браузере
   приёмки.

## Наблюдения для Codex

1. **Логика кандидата контрактом подтверждена**: оба node-теста
   закрывают ключевое поведение (online обходит backoff, объединяется
   с идущим GET и не будит скрытую/неавторизованную страницу) — код
   проверен без браузера.
2. Для живой приёмки ветки скрытия на этой машине нужны один из
   вариантов: браузер старее M145 в канале пробы, ожидание фиксa
   апстрима (crbug 556065499), либо перенос живой части на машину с
   браузером до M145. Подмена механики пробы не поможет: сигнал
   видимости не возникает в браузере как таковом.
3. Предлагаю разделить пробу: ветку Offline/Online (баннер обрыва,
   черновик, отправка формы, задержки GET/200 после Online) можно
   принять отдельно — она не зависит от visibilityState и в P2.9
   уже показала корректное поведение страницы; скрытие остаётся
   за фиксом апстрима.
4. Машина после прогона в исходном состоянии: PID XGW/Xray прежние,
   off/off fresh/matched, HTTPS 200, временных профилей и процессов
   браузера нет.
