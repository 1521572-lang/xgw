# ThinkCentre. standalone r4: запуск обработчика ждёт очередь, затем видео

CODE `59a59cba39a65cb8ff95a8a78e44ae2191581208`. Версия 0.2.0, freepool, GLM-5.3-Flash.
Исправляет отчёт r3 (25a6a4a): nfqws2 останавливали в секунду запуска, до появления очереди.
Теперь демон до 20 с ждёт очередь (статус «Обработчик запускается · без VPN», домены закрыты),
а каждое решение пишет в журнал строкой `zapret2: …` (ASSUMPTIONS п. 385). Здесь проверены
только узкие тесты. Главная приёмка — на ThinkCentre: настоящий ролик без VPN.

## 1. Исполнитель и подготовка

Исполнитель сам выполняет команды и управляет окнами через Vision. Нет терминала, root/sudo или
графического доступа — запросить доступ, дождаться и продолжить самому. Не просить владельца
запускать команды. Отчёт публикуется автоматически при любом исходе. Прочитать отчёт r3.
Разрешены установка исходников, смена режима, штатный откат, таймер возврата, перезапуск демона.
Не менять чужие службы, WAN/LAN/Tailscale, sysctl, подписки; не скачивать пакеты, не
перезагружать ПК. Git и GUI — от пользователя графической сессии (при root-инструменте —
runuser). Файлы с настройками, адресами и журналами остаются приватными. Записать UTC.

```bash
set -euo pipefail
cd "${XGW_REPO:-$HOME/xgw}"
test -z "$(git status --porcelain)"

sudo nft -j list tables >/dev/null
git fetch origin freepool
CODE=59a59cba39a65cb8ff95a8a78e44ae2191581208
BASE=1e80fc10c421533725ce9567b34dbca01aad9f03
git merge-base --is-ancestor "$CODE" origin/freepool

sudo xgw status --json >"$D/status-before.json"
sudo python3 -I "$H" snapshot "$D/baseline.json"

```

В diff — ровно четыре файла: `daemon.py`, `zapret2.py`, `watch/standalone.py`,
`watch/zapret2_control.py`. Нужны работающий VPN, zapret2 off, capture on. Установленный пакет
сверить с BASE (143 файла, как в r3): другой — остановиться, неизвестную версию не перетирать.
Backup r2/r3 сохранить. Проверить nfqws2/Lua, свободную очередь, block_quic=true,
fail_mode=closed. Пул в DEGRADED не мешает, если VPN работает; записать состояние.
Watch-адрес взять из приватного файла прежнего прогона, probe_urls не восстанавливать.

## 2. Проверки на машине перед переключением

Выполнить §3 `docs/TEST-PLAN-REAL-MACHINE-0.2.0-zapret2-standalone.md`: блок с HostIndependent

## 3. Установка исходников

Самому закрыть окно XGW. Выполнить установочный bash-блок §4 первого ТЗ с текущим D: он
сохраняет пакет и настройки, ставит все исходники CODE и сравнивает каждый файл. Дождаться
свежего статуса с прежним VPN; PID Xray от установки не меняется. Записать службу демона:

```bash
systemctl show xgw.service -p MainPID -p NRestarts -p ActiveEnterTimestamp >"$D/daemon-before.txt"
```

Открыть окно, проверить статус. Не нажимать standalone до таймера из §4.

## 4. Таймер возврата, одно переключение, журнал решений

Создать `return-vpn.sh` и таймер блоком §4 ТЗ r3, но срок — **240 с** (`--on-active=240s`), имя
`xgw-standalone-rescue-<время>`. Только `active` у таймера разрешает продолжить.
В окне: multidisorder, probe_urls пустые. Записать `T0=$(date -u +%FT%TZ)` и нажать
«zapret2 без VPN», самому подтвердить диалог. Одна попытка. Ждать готовность до 100 с,
каждые 10 с смотреть статус; в окне ожидается «Обработчик запускается · без VPN», затем
«Обработчик готов · без VPN». Сразу после готовности или по истечении 100 с:

```bash
sudo python3 -I "$H" snapshot "$D/ready.json"
systemctl show xgw.service -p MainPID -p NRestarts -p ActiveEnterTimestamp >"$D/daemon-after.txt"
cmp "$D/daemon-before.txt" "$D/daemon-after.txt" && echo "daemon: тот же процесс"
sudo journalctl -u xgw.service --since "$T0" -o short-iso --no-pager >"$D/journal-switch.txt"
grep -E 'zapret2: |настройки изменены|демон XGW запущен|применено' "$D/journal-switch.txt" \
  | sed -E 's/^([^ ]+) [^:]+: /\1 /' | tail -25
```

В отчёт — выведенные строки целиком: в них только время, слова состояний и числа. Ожидаются:
«настройки изменены: … служба не перезапускается», «применено с перезапуском Xray»,
«zapret2: обработчик запущен, очередь ожидается до 20 с», «zapret2: обработчик готов, очередь
занята через N с»; строк «отказ обработчика» и «остановлен демоном» нет. Записать N, время от T0
до «настройки изменены» и до готовности, совпал ли MainPID демона (NRestarts не вырос).
Нужны ready=true, without_vpn_config=true, vpn_bridges=0, queue=true, lease=true, worker_pid>0.
Vision: заголовок «без VPN», обычная страница вне выбранных доменов открывается.
Готовность подтверждена — остановить свой таймер и убедиться, что его служба не запускалась
(три команды `systemctl` из §4 ТЗ r3). Возврат уже начался — дождаться VPN, итог с причиной.

Если готовности нет: по строкам журнала назвать ветку — `start_timeout` (unit жив, очереди нет:
записать ActiveState/SubState из строки), `worker_exited` (записать Result/ExecMainStatus),
`queue_busy`, `runtime_failed`, либо строк `zapret2:` нет вовсе (тогда — последнее состояние
и reason из статуса). Дополнительно приватно: `sudo journalctl -u xgw-zapret2.service --since
"$T0" --no-pager | tail -20`; в отчёт — только число строк и есть ли слова error/denied/
permission, без аргументов запуска. Затем §6. Повторно не нажимать.

## 5. Главная приёмка: ролик без VPN, затем отказы и кнопки

Выполнить §5 первого ТЗ целиком с нынешними D/H: новый видимый профиль Firefox обычного
пользователя (snap — в `~/snap/firefox/common/`), снимки до и после, не меньше 60 с ролика, три
позиции плеера, качество, перемотка. Никаких повторных GET/fetch/curl видеосегментов.
PASS VIDEO: видимое воспроизведение, direct_data_confirmed=true, downlink ≥ 2 МиБ, uplink вырос,
vpn_delta=0, PID Xray/nfqws2 и конфиг прежние. Страница и работающий процесс видео не заменяют.
Ролик не играет при готовом обработчике — это уже вопрос стратегии, а не запуска: записать
ошибку плеера и счётчики, один другой публичный ролик, без серий GET; итог VIDEO=FAIL.

Перед отказами — новый таймер 240 с по §4. Выполнить §6 первого ТЗ: остановка только nfqws2 →
в пределах двух шагов выбранные домены закрыты, обычная страница работает, VPN не включился;
в журнале должна появиться пара строк «zapret2: отказ обработчика: worker_down (…)» и
«zapret2: обработчик остановлен демоном: worker_down» — записать их. Рестарт демона →
готовность вернулась (строки «запущен» и «готов»). Питание off → «остановлен демоном:
capture_off»; on → снова готов. «Вернуться к VPN» → «остановлен демоном: settings_changed»
или «mode_change», затем исправный VPN с прежними настройками. Итог каждой проверки — отдельно.
При всех PASS последним защищённым таймером включить standalone, подтвердить готовность,
снять таймер и оставить standalone работающим по поручению владельца.

## 6. Первый отказ: остановка попыток и восстановление

Как §6 ТЗ r3: UTC, состояние и причина — приватно; связь есть — самому запустить
`sudo /bin/bash "$D/backup/return-vpn.sh"` и остановить свой таймер; связи нет — команд не
слать, таймер вернёт VPN сам. После возврата проверить режим off и работающий VPN. Новая версия
не работает и с VPN — восстановить пакет из backup и перезапустить демон. Таблицы nft вручную
не удалять, ядра не подменять. Указать финальное состояние, исходники и активные таймеры.
