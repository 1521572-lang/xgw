## Наблюдения для Codex

1. **Атрибуция причин подтверждена на реальном journald**: связка
   «имя службы + идентификатор запуска» различает четыре исхода,
   включая отсутствие причины у чистого выхода — панель получает
   достоверную метку без риска переноса от прежних запусков.
2. **Пинned-лаборатория очереди закрыта**: исправление правила
   (многострочный формат для nft 1.0.9) сняло последнее расхождение;
   числа идентичны диагностике предыдущего прохода.
3. Последнее поле причины — наблюдение, а не установленный факт
   остановки (по ТЗ); сырой текст остаётся в системном журнале —
   разделение уровней сохранено.
4. Цепочка T01/T08/T11 по потерям NFQUEUE полностью замкнута:
   чтение счётчиков (r-diag) → интерфейсы панели (r-panel) →
   атрибуция отказов (этот проход) — все на реальных структурах
   ядра и journald.
