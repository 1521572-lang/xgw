## Точная причина сбоя системной фазы

Сбой произошёл до первой метки: `systemd-run` для первого временного юнита вернул код 1, в журнале менеджера — `Main process exited, code=exited, status=203/EXEC` (исполняемый файл недоступен внутри юнита). Проверено по шагам:

1. Прямой запуск того же бинарника из подготовленного дерева от имени рабочей учётной записи `xgw-singbox` проходит (`version` отвечает, код 0); права на бинарник `755`, на все каталоги пути — `711`, так что доступ на исполнение по правам есть.
2. Тот же `systemd-run` с тем же пользователем, но **без** `PrivateTmp=true` стартует успешно (код 0).
3. Тот же `systemd-run` **с** `PrivateTmp=true` даёт код 1 и `203/EXEC`; остальные свойства песочницы (`ProtectSystem=strict`, `ProtectHome`, `ReadOnlyPaths=/run`, ограничения возможностей, `RestrictAddressFamilies`, `IPAddress*`) по отдельности запуск не ломают.

Механизм: помощник стенда по своему же условию требует размещать дерево в новом каталоге под `/var/tmp`, а временный юнит получает `PrivateTmp=true` из шаблона рабочей службы — systemd подменяет `/tmp` и `/var/tmp` приватными tmpfs, и бинарник стенда, лежащий в `/var/tmp/...`, внутри юнита становится недостижим. У рабочей службы этой проблемы нет: её `ExecStart` указывает на `/opt/...`, вне приватного tmp.

Технический повтор только этой фазы с корнем вне `/var/tmp` (`/opt/...`) отклонён самим помощником: он проверяет, что родитель корня равен `/var/tmp`, и завершился с `error: systemd lab requires delegated root access and a new directory in /var/tmp` (код 2). Таким образом, системная фаза в текущем виде воспроизводимо не запускается: это расхождение между местом размещения стенда и `PrivateTmp=true` в песочнице юнита, а не отказ продукта.

## Вывод по проходу

Контракты, регрессии, applier, настоящий API Xray и контрольный переход на дочерних процессах проходят. Системная часть — единственная незакрытая: сам стенд размещает исполняемый файл в `/var/tmp`, который скрыт от юнита его же `PrivateTmp=true`, поэтому `SYSTEMD_*` остаются не подтверждёнными, а не отрицательными. Для приёмки нужно либо размещать лабораторный бинарник вне приватного tmp (например, отдельный каталог в `/opt`), либо запускать временные юниты с `PrivateTmp=false`; после этого системную фазу можно выполнить без изменения кода продукта.
