CODE `13f2682d1fea5f1e2c6823144c181c4629f5fbd1`, отчёт r5 `835381c`. Исполнитель GLM-5.3-Flash.
В r5 Firefox подтвердил продвижение плеера. Единственный повторный GET с Range
вернул HTTP 200 и 31 байт. Проверяем, даст ли другой свежий кандидат видеотело.
Запуск из исходников с временным профилем. Службы, маршруты, настройки и sysctl сохраняются.
В отчёт включать числа и признаки. Адреса, порты, профили, токены и журналы оставить приватно.

## 2. Живой прогон

Исполнитель сам проводит один согласованный запуск с публичной страницей владельца.
Для Firefox прежние 120 с и до 16 МиБ через прокси. После воспроизведения помощник
выбирает до трёх уникальных свежих кандидатов. На все повторные GET один срок 8 с.
Каждый запрашивает `Range: bytes=0-16383` и читает до 16 КиБ тела, суммарно до 48 КиБ тела.
Заголовки и TLS добавляют сетевой трафик. После первого успешного
HTTP 200/206 с video/* и минимум 16 КиБ дальнейшие GET не выполняются.

Используется youtube_sign_url или watch-адрес из zapret2.probe_urls. Если адреса нет,
владелец предоставляет одну строку в приватном `$D/page.txt` (0600). Настройки не править.

```bash
rc=0
if test -f "$D/page.txt"; then
  sudo python3 -I "$H" --state "$D/result.json" --page-file "$D/page.txt" || rc=$?
else
  sudo python3 -I "$H" --state "$D/result.json" || rc=$?
fi
printf 'helper_rc=%s\n' "$rc"
sudo xgw diag --no-net >"$D/diag-after"
```

Исполнитель читает STAGE, MARIONETTE_ERROR, BROWSER, ATTEMPT, VIDEO, CHECK и RESULT/STOP.
Сверить число кандидатов в BROWSER, номера завершённых попыток и сохранённые replay_attempts.
Для каждой попытки записать итог, HTTP, байты, признак video_mime и verdict, если они есть.
При STOP прочитать квитанцию и сохранить уже записанные результаты. Проверить завершение
временного Firefox и удаление профиля. При доступной панели сверить конечные статусы с Vision.

## 3. Чтение результатов

- `browser_video_verified` — выбранная попытка получила видео через VPN. Сохранить её номер
  и итоги предшествующих попыток. Прямой путь zapret2 проверяется отдельным экспериментом.
- `replay_failed` или `replay_not_video` — показать результаты всех завершённых попыток.
  При единственном кандидате отметить, что сравнение кандидатов в живом прогоне не состоялось.
- `replay_time_budget` — оставшиеся кандидаты не проверялись после истечения общего срока.
  Уже завершённые попытки остаются в квитанции. Ради следующего кандидата прогон не повторять.
- Для STAGE, MARIONETTE_ERROR и сверки пути действуют условия r2–r5. При STOP после повторных
  GET полученные ответы остаются наблюдениями. При отсутствии естественной ротации её живой
  сценарий остаётся NOT_RUN.

Сопоставить capture, zapret2 и диагностику до и после. При отсутствии условий для запуска
оформить NOT_RUN. После любого исхода переходить к публикации.

## 4. Автоматическая публикация отчёта

Исполнитель сам оформляет `docs/TEST-REPORT-REAL-MACHINE-0.2.0-video-probe-browser-r6-ДАТА.md`.
Указать CODE, суммы, тесты, согласованный объём прогона, наблюдения Firefox, число кандидатов,
все ATTEMPT, итог и конечную диагностику.
Проверить отчёт на секреты, использовать отдельное рабочее дерево от свежей `origin/freepool`,
закоммитить только отчёт, проверить diff, сделать обычный push в `freepool` и сверить файл на GitHub.
При гонке перенести свой коммит на свежую ветку и повторить push без force. Подтверждение
публикации не требуется. Сообщить хеш и ссылку. При сбое push сохранить файл и указать причину.
