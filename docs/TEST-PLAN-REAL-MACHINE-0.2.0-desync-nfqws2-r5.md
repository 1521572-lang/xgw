# ThinkCentre. Возврат зависимого флага TSO

Ветка `gui-light`, версия XGW 0.2.0. CODE = `c7500f6f40bdfbc9d16b1b23056063813a71a839`.
BASE = `d395628ff1d6b5c55fa14435eacce325c93ca748`, установлен по [отчёту r4](TEST-REPORT-REAL-MACHINE-0.2.0-desync-nfqws2-r4-2026-11-14.md).
Испытывать указанный CODE. Цель прогона — сохранить `tx-tcp-mangleid-segmentation`
после цикла TSO при смене профиля и выключении движка. Успешные этапы r4 остаются принятыми.

## 1. Доступ и исходный снимок

Исполнитель сам запускает команды, просматривает результаты и публикует отчёт. При отсутствии
терминала или root запрашивает доступ и сам продолжает работу. Владельцу остаётся подтверждение
системных диалогов. Отсутствующий доступ обозначить NOT_RUN с причиной.

Сверить область действующих согласий на замену модуля, перезапуск демона, профили и offload.
Для временного изменения mangleid отдельно проверить, покрывает ли его действующее согласие.
Если нужно, запросить согласие только на изменение этого флага и возврат исходного значения.
Работать в приватном каталоге и сохранять сырые логи и конфиги под umask 077.

```bash
set -eu
umask 077
git fetch origin gui-light
CODE=c7500f6f40bdfbc9d16b1b23056063813a71a839
BASE=d395628ff1d6b5c55fa14435eacce325c93ca748
git cat-file -e "$CODE^{commit}"
git merge-base --is-ancestor "$CODE" FETCH_HEAD
D=$(mktemp -d "$HOME/xgw-nfq-r5.XXXXXXXX")
TARGET="$D/new"
git worktree add --detach "$TARGET" "$CODE"
test "$(git -C "$TARGET" rev-parse HEAD)" = "$CODE"
```

Записать исходный статус `HEALTHY`, HTTPS, PID Xray, отсутствие активного nfqws2 и очереди,
текущее `nf_conntrack_acct`. Сохранить конфиги, установленный `nfqws2.py` с правами и полный
`ethtool -k` фактического WAN. Сверить хеш модуля с BASE. При различии выяснить причину до замены.
Эта копия `ethtool` фиксирует состояние **до прогона**. В r4 в конце mangleid был on.

## 2. Входная проверка и установка

В уже имеющемся окружении с pytest, без sudo, выполнить один набор:

```bash
cd "$TARGET"
PYTHONPATH=src:. python3 -m pytest -p no:cacheprovider -o addopts= -q tests/test_nfqws2.py
```

Ожидается 25 PASS, subtests могут считаться отдельно. При FAIL опубликовать STOP до установки.
При выключенном движке заменить только `src/xgw/nfqws2.py` в каталоге установленных модулей.
Сохранить root:root и штатный режим файла. Сверить SHA-256 с CODE. Перезапустить только
`xgw.service`. Проверить HEALTHY, HTTPS и PID Xray. При сбое вернуть резервную копию модуля.

## 3. Цикл выключения и возврата TSO

1. Проверить, что `tcp-segmentation-offload` включён и изменяем, а `tx-tcp-mangleid-segmentation`
   присутствует. При исходном mangleid=on и разрешённом изменении временно выполнить
   `ethtool -K <WAN> tx-tcp-mangleid-segmentation off` при выключенном движке. Проверить чтением,
   что TSO остался on, mangleid стал off. Сохранить этот второй снимок как **состояние для теста**.
   Если TSO или mangleid отсутствует, либо исходное on невозможно изменить, отметить сценарий
   NOT_RUN с конкретной причиной. Фиксированный off можно проверить и описать отдельно.
2. Временно включить `nf_conntrack_acct=1` и выбрать свободную очередь в рамках согласованного
   прогона. При selective off включить `engine=auto`, `engine_offload=true` и `disorder-badseq`.
   Подтвердить активный worker, очередь, фактический TSO off и HTTPS. Дать пройти двум шагам
   watchdog. Записать время, статус и PID Xray. Повторные старты или fallback фиксировать как FAIL.
3. Перейти на `seqovl`. После готовности нового worker перечитать полный `ethtool -k`.
   Четыре основные функции и mangleid должны совпасть со вторым снимком, включая mangleid off.
   Проверить HTTPS и сохранение PID Xray. Любое отличие `ethtool` описать отдельно.
4. Повторить переход в `disorder-badseq`, затем установить `engine=off`. Сверить те же пять
   значений. Ожидаются пустая тестовая очередь, остановленный worker и рабочий HTTPS.
   При необходимости обновить правила штатным `xgw enable` и проверить отсутствие `nfq_output`.

Если XGW сообщает `offload_restore`, сохранить диагностический вывод, дождаться следующего
шага восстановления и сверить фактические значения. При устойчивом отказе восстановить
состояние по сохранённым снимкам, записать FAIL и вернуть BASE.

## 4. Возврат машины и отчёт

Вернуть содержимое конфигов и `nf_conntrack_acct`. Если mangleid временно менялся на шаге 3.1,
вернуть его значение из снимка **до прогона** после остановки движка и восстановления TSO.
Сверить фактическое `ethtool -k`, HTTPS, HEALTHY, PID Xray и отсутствие тестовой очереди/worker.
При PASS оставить исправленный модуль. При FAIL вернуть резервную копию и перезапустить только
демон. Зафиксировать фактический итог и установленный код. Закрыть root-канал после восстановления.

Сохранить `docs/TEST-REPORT-REAL-MACHINE-0.2.0-desync-nfqws2-r5-ДАТА.md`.
Указать CODE, тесты, применимость, состояния TSO/mangleid до прогона и контрольного цикла,
результат смены профиля и `engine=off`, возврат машины, итог PASS/PARTIAL/FAIL/STOP/NOT_RUN.
Публиковать автоматически при любом исходе, включая ранний STOP. В чистом дереве от свежей
`origin/gui-light` добавить только обезличенный отчёт, проверить `git diff --check`, сделать
коммит и обычный push. При конкурентном обновлении перенести отчёт на свежую ветку.
Сверить публикацию с удалённой веткой и дать владельцу ссылку. В отчёт включать лишь результаты,
версии и значения флагов. Конфиги, адреса, имена, сырые журналы и снимки сохранить приватно.
