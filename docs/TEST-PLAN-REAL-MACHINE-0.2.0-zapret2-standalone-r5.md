## 4. Охват адресов: что отвечает напрямую, что через zapret2

`U` — пользователь графической сессии (определить, не угадывать). Сначала как есть:

```bash
sudo install -m 644 "$S" /tmp/xgw-strategy-check.py   # пользователю каталог D закрыт
sudo python3 -I "$S" listed /tmp/xgw-listed.json
sudo -u "$U" python3 -I /tmp/xgw-strategy-check.py hosts --listed /tmp/xgw-listed.json   | tee "$D/hosts-before.txt"
```

Затем расширить список доменов до списка по умолчанию (стратегия та же) и повторить:

```bash
sudo python3 -I "$S" use multidisorder --domains-default
sudo python3 -I "$S" listed /tmp/xgw-listed.json
sudo -u "$U" python3 -I /tmp/xgw-strategy-check.py hosts --listed /tmp/xgw-listed.json   | tee "$D/hosts-after.txt"
```

`use` должен вернуть ready=true, domains=10 (Xray при смене доменов перезапускается — это
ожидаемо). В отчёт — таблица из 11 строк: имя адреса (это общеизвестные служебные имена
YouTube, не секрет), in_list до/после, ok до/после, phase при отказе. Главный вопрос шага:
есть ли адреса, которые напрямую не отвечали (in_list=false, ok=false), а через zapret2
отвечают. Контроль: www.google.com и www.gstatic.com — напрямую в обоих замерах.

## 5. Ролик и перебор стратегий

Профиль Firefox — новый, обычного пользователя (snap — в `~/snap/firefox/common/`), без
расширений и прокси. Одна проба стратегии:

1. закрыть **все** окна Firefox этого профиля (старые соединения не должны дожить до пробы);
2. открыть watch-адрес, при необходимости нажать Play;
3. сразу `sudo python3 -I "$S" measure 40 | tee -a "$D/measure.txt"`;
4. по Vision: шло ли воспроизведение, позиция плеера в конце, качество (шестерёнка или
   «Статистика для сисадминов»), был ли спиннер.

Проба **годна**, если позиция ушла вперёд не меньше чем на 25 с, down_mib ≥ 3,
stalled_steps ≤ 2, worker_stable=true. Строку measure и наблюдение — в таблицу отчёта.

Первая проба — текущая multidisorder с расширенным списком. Не годна — по порядку, пропуская
стратегии с FAIL из §2: `fake_md5`, `fake_seq`, `fake_ts`, `hostfakesplit_md5`,
`fakedsplit_md5`, `seqovl`, `multisplit`. Перед каждой пробой:

```bash
sudo python3 -I "$S" use ИМЯ
```

ready=false (state blocked) — записать reason и перейти к следующей. Если после `use` страница
YouTube вообще не открывается — проба не годна, дальше. Остановиться на первой годной; больше
одной пробы на стратегию не делать, порядок не менять.

Нашлась годная — заменить таймер новым на 1800 с и подтвердить на ней же блоком §5 первого
ТЗ с D/H: snapshot до, тот же ролик 60 с с перемоткой вперёд, затем второй современный
ролик 60 с, snapshot после, delta.
PASS VIDEO: оба ролика видимо играют, direct_data_confirmed=true, download ≥ 2 МиБ, vpn_delta=0,
PID и конфиг прежние. Затем отказы и кнопки (§6 первого ТЗ): остановка только nfqws2 → домены
закрыты, VPN не включился; рестарт демона → готов; **выключатель перехвата в окне XGW**
(кнопка питания в окне программы, не кнопка компьютера) выкл → прямой интернет, обработчик
остановлен; вкл → снова готов. При всех PASS: остановить таймер, оставить режим без VPN
с найденной стратегией включённым по поручению владельца; записать её имя.

Ни одна не годна — VIDEO=FAIL: таблица всех проб, затем `sudo python3 -I "$S" use
multidisorder` и §6.
