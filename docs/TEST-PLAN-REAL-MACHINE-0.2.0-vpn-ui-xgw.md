Это рабочий запуск `vpn_ui/main_xgw.py`, а не `main_demo.py`. Данные из локальной панели.

## 1. Доступ и границы

Исполнитель сам запускает команды, читает файлы/журналы и работает Vision. При отсутствии
терминала, нужных прав или графического доступа запрашивает доступ и после получения
продолжает сам. Владельца запускать скрипты не просить; секрет/пароль в системном диалоге
может ввести владелец. Отчёт автоматически публикуется при любом исходе.

Git и GUI — пользователь графической сессии. Root нужен только для приватного baseline
и аварийного снятия созданного в §5 pin. При root-инструменте самому использовать runuser
для GUI с окружением пользователя. Не устанавливать пакет XGW, не менять ярлык, службы,
ядра, WAN/LAN/Tailscale/DNS, системные правила и подписки. Ничего не скачивать.
Разрешено закрыть старое окно через Vision, открыть новое, читать и фильтровать данные,
выполнить ровно ограниченный сценарий §5. VPN/zapret2 и питание в этом ТЗ не переключать.
Закрытие окна не останавливает шлюз. Не выполнять systemctl stop/restart для «проверки stale».

Прочитать последний отчёт vpn-ui и README vpn_ui. В r6 zapret2 оставлен off, VPN восстановлен;
состояние сейчас определить заново. Имена/адреса/квоты подписок, cookie, IP, скриншоты и
сырые журналы остаются приватными. В отчёте — S1/S2, N1/N2, числа и исходы без идентификаторов.

## 3. Живой вход и каталог

Через Vision закрыть прежнее окно XGW, если открыто; трей и службы оставить.
Новый файл сеанса ниже изолирует проверку входа от сохранённого сеанса прежнего окна.

```bash
XGW_GUI_SESSION="$D/gui-session.json" "$PY" vpn_ui/main_xgw.py --theme dark \
  >"$D/gui.log" 2>&1 &
GUI_PID=$!
```

1. Дождаться «Войти в панель». Нажать, сначала отменить системный диалог: никакого
   «VPN подключён» из самого факта отмены, кнопка входа остаётся. Нажать снова, завершить
   обычный вход. Исполнитель сам открывает/читает диалог, при требовании секрета зовёт владельца.
2. Сверить фактический режим с прежней панелью/приватным статусом. Устаревших сообщений
   «Нужен вход» после успешного входа быть не должно. При ошибке доступа сеть не чинить.
3. Слева сверху настоящий список подписок; ниже серверы выбранной. Для каждой подписки
   сравнить имена и принадлежность с «Настройки → Серверы»/«Подписки». Пустая подписка,
   если есть, остаётся видна с причиной. Квота относится к выбранной подписке.
4. Последовательно выбрать две подписки и «Отдельные ссылки», если есть. Список меняется,
   текущий VPN-сервер и pin — нет. Отсутствие второго источника — NOT_RUN этого случая,
   фиктивную подписку ради теста не добавлять.
5. Поиск внутри источника, очистка, фильтр доступных/выбранного вручную, сортировка скорости
   и задержки. Неизмеренные строки не получают нули или выдуманную скорость. Отключённые
   и служебные записи явно подписаны, их нельзя выбрать как рабочий сервер.
6. Щелчок по имени и Enter открывают сведения, но не переключают сервер. Закрыть, проверить
   отдельную кнопку выбора. Подождать два опроса: источник, прокрутка и выбранная строка сохраняются.
7. Открыть «Бесплатный пул»: прочитать реальные состояния допуска либо честное отсутствие
   данных/ошибку. Возврат к подписке не смешивает каталоги. Бесплатный сервер не выбирать.

## 5. Одно настоящее действие и восстановление

Только если baseline: VPN работает, запущен автовыбор (ручного pin нет), free_pool не ведёт
весь дом, текущий основной сервер достоверно определён и доступен. Иначе SELECT=NOT_RUN
с конкретной причиной: не менять исходный ручной выбор/маршрут ради теста.

Выбрать **тот же основной сервер**, который уже обслуживает трафик, отдельной кнопкой.
Не выбирать другую страну или недоступный запасной. Проверить отметку «выбран вручную»
после ответа демона и краткую блокировку повторной команды. Сверить pin в панели.
Затем «Автовыбор XGW» → убедиться, что ручной pin снят и VPN работает. Выбор подписки
никогда не должен сам назначать её ограничением алгоритма автовыбора.

Если окно отказало после создания pin: исполнитель сам открывает прежний `xgw gui` и
возвращает «Автовыбор». При недоступности окон сам выполняет `sudo xgw unpin` (только если
до прогона pin отсутствовал и создан именно этим сценарием). Не перезапускать службы.
При первом непредвиденном сетевом сбое прекратить клики, восстановить исходный выбор,
сохранить журнал приватно. Не повторять сценарий и не пытаться чинить сам VPN этим ТЗ.
