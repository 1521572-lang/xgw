# ThinkCentre: реальный ethtool, disorder-badseq и восстановление offload

Дата подготовки: 2026-11-14. Ветка `gui-light`, версия 0.2.0.
CODE = `d395628ff1d6b5c55fa14435eacce325c93ca748` — разбор ethtool и восстановление offload.
BASE = `9b58725354799a6b91c7341c41a311371bdfa4d8` — установлен после отката r3 (`b2b820f`).
Испытывать именно этот CODE. HEAD вместо CODE не использовать.

Цель — закрыть IndexError на заголовке ethtool и оставшиеся RELOAD_SAME/OFFLOAD/WORKER_RECOVERY.
Успешные этапы r2 и PATH_ACCESS из r3 не повторять. Полный pytest, сборка дистрибутива не нужны.

## 1. Исполнитель и доступ

Модель сама читает, выполняет команды, открывает и осматривает GUI через vision, анализирует
результаты и публикует отчёт. Не просить владельца запускать скрипты, вставлять команды, читать
журналы или делать снимки. При недоступности терминала/root/браузера запросить доступ и продолжить
самостоятельно. Пароль и системный диалог подтверждает владелец. Нет доступа — NOT_RUN с причиной.

Действующие согласия r2/r3 на nfqws2, offload, установку трёх модулей и перезапуск демона сохраняются.
Повторно их не запрашивать; новое действие вне этих согласий согласовать конкретно.
Не менять WAN/LAN, Tailscale, подписки, пул, pin, маршруты дома, ядра и пакеты. Не выполнять nft flush,
удаление таблиц, перезагрузку, общий unit zapret2, force push или reset --hard. Чужие процессы не трогать.
Временные команды ethtool — только штатным кодом XGW и при восстановлении сохранённого состояния.

Отчёт публикуется автоматически при любом исходе, без отдельного подтверждения commit/push.
Конфиги, сырые журналы, ethtool, снимки, адреса/домены, имена, URL подписок, ключи — только приватно.
В отчёт допускаются имена четырёх флагов, on/off/fixed, числа, коды причин и версии.

## 2. Исходники и снимок настоящей машины

Найти существующий checkout XGW и выполнить:

```bash
set -eu
umask 077
git fetch origin gui-light
CODE=d395628ff1d6b5c55fa14435eacce325c93ca748
BASE=9b58725354799a6b91c7341c41a311371bdfa4d8
git cat-file -e "$CODE^{commit}"
git merge-base --is-ancestor "$CODE" FETCH_HEAD
D=$(mktemp -d "$HOME/xgw-nfq-r4.XXXXXXXX")
TARGET="$D/new"
git worktree add --detach "$TARGET" "$CODE"
test "$(git -C "$TARGET" rev-parse HEAD)" = "$CODE"
test -z "$(git -C "$TARGET" status --porcelain)"
```

Не удалять чужие изменения и прежние каталоги. Сохранить приватно status --json, diag --no-net,
PID демона/Xray/sing-box, очереди, состав nft-таблиц, nf_conntrack_acct, config.toml/panel.json.
Начало: HEALTHY, capture on, engine off/нет ключа, selective off, чужого listener нет.
Неожиданное исходное состояние — STOP baseline_changed, без исправлений вслепую.
Уточнить каталог установленного XGW (ранее `/opt/xgw/lib/xgw`), сохранить с правами/владельцами
cli.py, daemon.py, nfqws2.py и сверить с BASE. При несовпадении выяснить причину до замены.

Определить фактический WAN штатным способом XGW: явный network.wan_if либо default route.
Модель сама запускает `ethtool -k` на этом интерфейсе через root-канал и сохраняет **полный** вывод
в `$D/ethtool-before.txt`. Заголовок/пустые/вложенные строки не удалять. Не менять offload на этом шаге.
До установки проверить парсер CODE на этом файле (sudo означает доступный root-канал):

```bash
sudo env PYTHONPATH="$TARGET/src" python3 - "$D/ethtool-before.txt" <<'PY'
import sys
from pathlib import Path
from xgw.nfqws2 import OFFLOADS, Offload
flags = Offload.parse(Path(sys.argv[1]).read_text())
for name in OFFLOADS:
    flag = flags.get(name)
    print(name, "absent" if flag is None else
          ("on" if flag.enabled else "off") + (" fixed" if flag.fixed else ""))
print("ETHTOOL_PARSE=PASS")
PY
```

Если sudo недоступен, выполнить эквивалент через предоставленный root-канал, не отдавать команду владельцу.
Сверить четыре результата с исходным выводом. Любое исключение/расхождение — STOP до установки.
Отсутствующий флаг не выдавать за off. Если есть on [fixed], отметить ограничение оборудования:
disorder должен дать offload_fixed без попыток изменения. Остальные независимые проверки продолжить.
Не обходить отказ выставлением engine_offload=false ради PASS.

## 4. Установка и независимые проверки

При engine=off заменить только `src/xgw/{cli.py,daemon.py,nfqws2.py}` из TARGET в проверенном
каталоге установленных модулей, root:root 0644; сверить SHA-256 с CODE. Нужны все три модуля,
поскольку r3 был откатан к BASE. Перезапустить только xgw.service один раз, сохранить PID Xray.
Норма: HEALTHY, HTTPS работает, новых FAIL нет, nfqws2 выключен. При сбое восстановить резервные копии.

Существующие nfqws2 1.0.7 и Lua не заменять. Блобы встроены. Сохранить и временно включить
nf_conntrack_acct=1. Выбрать свободную очередь, задать mode=off, engine=auto, engine_profile=seqovl,
engine_offload=true. Дождаться active/правильного профиля/listener не дольше 90 с, опрашивая каждые 2 с.
Правила при необходимости обновить через xgw enable. Проверить HTTPS и рост счётчика NFQUEUE.

Сначала закрыть независимые от disorder сценарии:

1. Наблюдать seqovl не менее 60 с и двух шагов watchdog. Затем touch config.toml без изменения
   содержимого; по журналу подтвердить перечитывание. Worker/PID и PID Xray сохраняются ещё 60 с.
2. Один раз остановить только xgw-nfqws2.service. Новые соединения продолжают работать через bypass;
   демон возвращает active в пределах 90 с. Затем 60 с стабильного PID и отсутствие перезапусков.
   Этот WORKER_RECOVERY выполняется на seqovl, поэтому его нельзя пропускать из-за будущего отказа disorder.

## 5. disorder-badseq и полный цикл offload

Поменять только профиль на disorder-badseq. Не стирать память сканера, если она перекрывает профиль:
в таком случае показать фактический профиль и отметить ограничение проверки.
Норма при изменяемых флагах: ровно один запуск worker с аргументами disorder, active/очередь,
все присутствующие управляемые флаги фактически off, PID Xray сохранён, HTTPS работает.
Проверить новым ethtool -k, а не только rc команды и названием профиля. Наблюдать 60 с и два шага.

При on [fixed] ожидается fallback/offload_fixed без изменения интерфейса и без падения watchdog.
Это CONTROLLED_REFUSAL=PASS, DISORDER=NOT_RUN, итог не выше PARTIAL. При offload_apply/read/state —
зафиксировать FAIL с точной причиной, проверить откат флагов; не продолжать зависимые этапы.

При активном disorder выполнить последовательно:

- touch TOML без изменения содержимого: подтверждённый reload, тот же worker/PID, флаги остаются off;
- возврат к seqovl: каждый из четырёх присутствующих флагов совпадает с исходным on/off/fixed;
- снова disorder, затем один перезапуск только xgw.service в рамках действующего согласия:
  worker восстановился, выключенные флаги удерживаются, PID Xray сохранён;
- engine=off: worker и очередь исчезли, все исходные флаги вернулись. При необходимости xgw enable
  убирает nfq_output. Проверить offload новым чтением, включая изначально выключенные флаги.

Если offload_restore — XGW обязан показывать fallback, сохранять снимок и повторять восстановление.
Не выдавать это за off/PASS, не перезапускать демон до сохранения исходного снимка и разбора причины.
Не подменять ethtool и не создавать искусственный отказ драйвера на рабочей машине: ошибки отката
проверены целевыми тестами, здесь проверяется настоящий цикл отключения/восстановления.
