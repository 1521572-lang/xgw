# Программа испытаний XGW на реальной машине: бот Telegram не задерживает остановку демона

**Для исполнителя.** Выполняй шаги строго по порядку. В каждом шаге — команда (копируй
целиком), «Ожидается» и «Если не так». Ничего не придумывай сверх написанного. Не уверен —
остановись и спроси заказчика. Выводы команд сохраняй в файлы, как написано: из них
собирается отчёт (§6).

Машина: ThinkCentre, Ubuntu 24.04.5 LTS, шлюз дома (LAN `enp4s0`). Стоит XGW **0.1.15**.
Клон репозитория — `~/zcod/xgw`. Номер версии не меняется: и после обновления
`xgw --version` пишет `xgw 0.1.15`. Новый код узнаётся по строке «прерывание опроса бота: есть»
(шаги 2.1 и 2.3).

Что нового (ASSUMPTIONS п. 217). В прошлом отчёте (наблюдение 2) `systemctl restart xgw`
занимал 2,26–2,81 с, хотя сам демон останавливался за ~0,5 с. Почти всё остальное время
процесс ждал поток бота Telegram: тот висел в запросе к Telegram (ожидание новых сообщений
до 25 с), а остановка ждала его 2 с. Теперь остановка прерывает этот запрос за доли секунды.
Заодно панель и страница статуса закрываются быстрее (до 0,1 с вместо 0,5 с). Отправка
ответов бота не прерывается.

Цели:

1. Поставить новый код (шаг 2).
2. Трижды перезапустить демон и измерить остановку; убедиться, что бот после перезапуска
   снова работает (шаг 3).
3. Итоговое состояние (шаг 4), отчёт (§6).

- Останавливать или перезапускать `xgw-xray`, `xgw-singbox`, `xgw-net`, `xgw-dhcp`. Демон `xgw`

- Менять что-либо в панели: выбирать сервер, нажимать кнопки, отключать или подключать бота.
- Писать боту в Telegram (это делает только заказчик, если сам захочет).
- Править код XGW. Коммитить что-либо, кроме отчёта (§6). Файлы из `~/xgw-botstop-test` в Git
  **не класть**.
- Писать в отчёт: токен бота, номер чата, адреса подписок, UUID, пароли, ключи, IP и домены
  серверов, свой внешний IP.

## 3. Перезапуск демона

Скрипт шага 3.1 спрашивает у панели, в каком состоянии бот, перезапускает демон, меряет, сколько
длился перезапуск, через 15 с снова спрашивает состояние бота и показывает журнал вокруг
перезапуска. Токен и чат бота панель наружу не отдаёт: печатаются только режим бота и текст
ошибки.

Шаг 3.1. Создать скрипт (копируй блок целиком):

```bash
cat > restart.sh <<'EOF'
#!/bin/bash
# restart.sh N — попытка N: перезапустить демон, измерить, проверить бота.
J=~/xgw-botstop-test/panel.jar
bot() {
  curl -s -o /dev/null -c $J "http://127.0.0.1:8781/?token=$(sudo cat /var/lib/xgw/panel-token)"
  curl -s -b $J http://127.0.0.1:8781/api/state | python3 -c 'import json,sys; t=json.load(sys.stdin).get("telegram") or {}; print("бот:", t.get("mode"), "| ошибка:", t.get("error") or "нет")'
}
echo -n "до: "; bot
SINCE=$(date '+%F %T')
T0=$(date +%s.%N); sudo systemctl restart xgw; T1=$(date +%s.%N)
echo "попытка $1: restart занял $(python3 -c "print(f'{$T1 - $T0:.2f}')") с"
sleep 15
echo -n "после: "; bot
sudo journalctl -u xgw --since "$SINCE" -o short-precise --no-pager | grep -E 'Stopping|Stopped|Started|остановлен|запущен|Telegram|Traceback' | sed -E 's#https?://[^ )]*#(адрес скрыт)#g'
EOF
chmod +x restart.sh; echo "скрипт создан"
```

Ожидается: «скрипт создан».

Шаг 3.2. Попытка 1:

```bash
./restart.sh 1 2>&1 | tee after/restart-1.txt
```

Ожидается:
- строка «до: бот: …». Режим `connected` — бот опрашивает Telegram, это главный случай.
  Режим `off`, `notify` или `no_chat` — бот Telegram не опрашивает, и задержки от него не было
  бы и раньше: записать режим в отчёт, проверка остановки всё равно проводится;
- «restart занял» — **меньше 1,5 с** (раньше было 2,26–2,81 с);
- «после: бот: …» — тот же режим, что «до», и «ошибка: нет»;
- в журнале есть `Stopping`, `Stopped` и `Started`/«демон XGW запущен»; нет `Traceback` и нет
  строк «бот Telegram: …» с ошибкой.

Если «restart занял» 1,5 с или больше: записать в отчёт время и журнал попытки, продолжать.
Если «после» режим другой или есть ошибка бота (демон перезапускать не нужно), выполни:

```bash
sleep 60; J=~/xgw-botstop-test/panel.jar; curl -s -b $J http://127.0.0.1:8781/api/state | python3 -c 'import json,sys; t=json.load(sys.stdin).get("telegram") or {}; print("бот:", t.get("mode"), "| ошибка:", t.get("error") or "нет")'
```

и записать ответ. Ошибка осталась — это дефект: записать в отчёт и перейти к шагу 4.
