# ThinkCentre. YouTube через zapret2 без VPN

CODE `4a0e3eb70dffeae8274b80f71aad421fffe7e33d`. Версия 0.2.0, freepool. Исполнитель GLM-5.3-Flash.
Проверить самостоятельный режим в утилите: настоящий ролик идёт через домашний выход
с обработкой zapret2, VPN-серверов в рабочем маршруте нет. Дистрибутив не собирается.
HTTP 200 страницы, запущенный процесс или standalone в настройке сами по себе не дают PASS.

## 1. Исполнитель, доступ и границы

Исполнитель сам открывает терминал ThinkCentre, выполняет команды, использует Vision
для окна XGW и браузера, читает результаты и публикует отчёт. При отсутствии терминала,
sudo или управления окном запрашивает соответствующий доступ и продолжает после выдачи.
Владельцу не передавать команды для ручного запуска. Если получить доступ невозможно,
опубликовать NOT_RUN с точной причиной и указать, какие части не выполнялись.
В отчёте записать инструмент запуска, UTC начала/конца и увиденный результат.

Владелец поручил этот режим и проверку на машине. В рамках ТЗ разрешены обновление
исходников XGW, перезапуск xgw.service, переключение между VPN и standalone, остановка
только xgw-zapret2.service для проверки отказа. При переключении XGW сам перезапускает
свой Xray и останавливает свои VPN-мосты sing-box. Соединения при этом прервутся.
Новые программы не скачивать и не устанавливать. Не менять WAN/LAN/Tailscale, sysctl,
подписки, серверы, маршруты вручную, чужие службы. Не перезагружать машину.
Все приватные файлы оставлять на машине; адреса, конфиги, заголовки и журналы не публиковать.

## 2. Подготовка и исходное состояние

Все блоки запускает исполнитель из одной bash-сессии. При ошибке не продолжать вслепую.

```bash
set -euo pipefail
cd "${XGW_REPO:-$HOME/xgw}"
test -z "$(git status --porcelain)"
sudo -v
git fetch origin freepool
CODE=4a0e3eb70dffeae8274b80f71aad421fffe7e33d
git merge-base --is-ancestor "$CODE" origin/freepool
umask 077
D=$(mktemp -d "$HOME/xgw-zapret2-standalone.XXXXXXXX")
git worktree add --detach "$D/new" "$CODE"
H="$D/new/docs/helpers/zapret2_standalone_check.py"
printf '%s  %s\n' 7ef6f6c839951bd5322dd36febcaa94f6a0eafca230e9f044e0c512b4735c99e "$H" | sha256sum -c -
date -u +%FT%TZ
sudo xgw status --json >"$D/status-before.json"
sudo xgw diag --no-net >"$D/diag-before.txt"
sudo python3 -I "$H" snapshot "$D/baseline.json"
```

Прочитать приватный статус, увидеть исходное окно через Vision. Записать исходные
режимы zapret2, capture, пула и ручного выбора, PID своих служб, ошибки/WARN.
Для данного прогона нужен исходный исправный VPN и zapret2 off, чтобы проверить возврат.
Другой исходный режим сначала разобрать и отразить в отчёте, не сбрасывать его молча.
Проверить наличие настроенных nfqws2 и Lua с безопасными правами, свободную NFQUEUE,
block_quic=true и fail_mode=closed. Несоответствие — STOP с конкретной причиной.

## 3. Проверки кода и установка исходников

Основная приёмка ниже — живая. Здесь выполнить затронутые тесты на машине, без установки пакетов:

```bash
(cd "$D/new" && PYTHONPATH=src python3 -m pytest -o addopts= -q \
 tests/test_zapret2_standalone.py tests/test_zapret2.py tests/test_zapret2_panel.py \
 tests/test_generator.py tests/test_nft.py tests/test_net.py)
(cd "$D/new" && PYTHONPATH=src QT_QPA_PLATFORM=offscreen python3 -m pytest \
 -o addopts= -q tests/test_gui_qt.py -k zapret2)
```

Пропуск/отсутствие инструмента указать отдельно. Новый FAIL — не ставить код до разбора.
Закрыть окно XGW самому через интерфейс. Обновляется весь пакет исходников одной версии,
чтобы не смешивать файлы разных этапов. Ядра, библиотеки Python и nfqws2 не заменяются.
Резервные копии содержат секреты, каталог backup доступен только root.

```bash
sudo bash -s -- "$D" <<'SH'
set -euo pipefail
D=$1
G=/opt/xgw/lib/xgw
test -f "$G/daemon.py"
install -d -m 0700 "$D/backup"
cp -a "$G" "$D/backup/xgw"
cp -a /etc/xgw "$D/backup/etc-xgw"
if test -f /var/lib/xgw/capture.json; then
  cp -a /var/lib/xgw/capture.json "$D/backup/capture.json"
fi
trap 'cp -a "$D/backup/xgw/." "$G/"; systemctl start xgw.service' ERR
systemctl stop xgw.service
while IFS= read -r -d '' f; do
  install -D -o root -g root -m 0644 "$D/new/$f" "$G/${f#src/xgw/}"
done < <(git -c safe.directory="$D/new" -C "$D/new" ls-files -z src/xgw)
systemctl start xgw.service
trap - ERR
SH
```

Сверить SHA-256 каждого установленного исходника с worktree, дождаться свежего статуса.
VPN пока прежний, PID Xray не должен измениться только от установки исходников.
Новая ошибка или неполная сверка — STOP, восстановить пакет из backup и запустить демон.

## 4. Включить самостоятельный режим через настоящее окно

Открыть xgw gui самому. На обзоре открыть zapret2. Проверить Vision наличие кнопки
«zapret2 без VPN», читаемость текста и отсутствие обрезания на разрешении машины.
В настройках выбрать multidisorder, удалить адреса проверок, сохранить. Остальные настройки
не менять. Это намеренная проверка работы без временной ссылки на видео и HTTP-проб.
Нажать «zapret2 без VPN», прочитать и подтвердить штатный диалог. Повторное согласие владельца
на этот предусмотренный ТЗ шаг не запрашивать. Дождаться свежего состояния, не более 120 с.
Ожидаются «Обработчик готов · без VPN», соответствующий главный заголовок и активный nfqws2.
VPN-правила устройств и пула приостановлены; их сохранённые настройки не должны исчезнуть.

```bash
sudo python3 -I "$H" snapshot "$D/ready.json"
```

Нужны ready=true, without_vpn_config=true, vpn_bridges=0, lease=true, queue=true.
Самому прочитать установленный конфиг приватно: нет VPN-протоколов, балансировщиков,
burstObservatory, служебных входов VPN-проб. Не публиковать содержимое.
Проверить обычную страницу вне выбранных доменов: открывается напрямую.
Если ready=false, разобрать причину по статусу/журналу, не переходить к сравнениям curl.

## 5. Главный критерий: видео и обе стороны прямого маршрута

Закрыть прежние вкладки YouTube. Создать новый отдельный профиль Firefox внутри D
и открыть видимый браузер от обычного пользователя, не root. Исполнитель сам запускает
браузер и управляет им. Проверить отсутствие расширений VPN, стороннего прокси и отдельного
туннеля на клиенте. Старый профиль/куки владельца не менять. Пока открыть about:blank.
Взять обычный публичный watch-адрес из ранее согласованных настроек/тестов приватно.
Подписанные ссылки на видеосегменты не извлекать, не повторять fetch/GET/curl.

```bash
sudo python3 -I "$H" snapshot "$D/video-before.json"
```

Открыть ролик именно после этого снимка, нажать Play. Через Vision увидеть кадры,
позицию плеера и выбранное качество. Наблюдать не менее 60 секунд, записать 3 позиции
в разные моменты, качество, длительность остановок/буферизации. Желательно 720p, если доступно.
Выполнить одну перемотку вперёд и убедиться, что изображение и время снова движутся.
Не открывать параллельно другие ролики и не делать сетевых проб.

```bash
sudo python3 -I "$H" snapshot "$D/video-after.json"
sudo python3 -I "$H" delta "$D/video-before.json" "$D/video-after.json"
```

PASS видео: видимое воспроизведение/перемотка, direct_data_confirmed=true, uplink вырос,
downlink вырос минимум на 2 МиБ, vpn_delta=0, конфиг и PID Xray/nfqws2 прежние.
Если объём меньше, продолжить тот же ролик до 120 с и снять новый after-файл, не новый GET.
Если плеер не играет, зафиксировать наблюдаемую ошибку и счётчики. HTTP 200 не заменяет видео.
Отказ входа/доступа к конкретному ролику отделить от сетевого таймаута. Максимум один другой
публичный ролик для такого отказа. Не начинать серию исследований протоколов и видеоссылок.

## 6. Отказ, восстановление и управление

Остановить только обработчик: `sudo systemctl stop xgw-zapret2.service`.
В пределах двух шагов watchdog увидеть блокировку выбранных доменов, without_vpn_config=true,
worker_pid=0 и отсутствие VPN-мостов. Открыть ролик в ещё одном чистом профиле/новой сессии,
чтобы старый буфер не выдавать за работающее соединение. Новый поток не должен проходить.
Обычная страница вне выбранных доменов остаётся доступна. Автовключение VPN — FAIL.
Не ждать таймера повторного запуска: `sudo systemctl restart xgw.service`.
Дождаться ready=true, снова воспроизвести ролик, проверить отсутствие VPN и свежие статусы.
Это одновременно проверка сохранения режима после перезапуска демона. Машину не перезагружать.

Кнопкой питания снять перехват: обычный прямой интернет, обработчик остановлен,
VPN не включился. Включить питание обратно: режим zapret2 без VPN восстановился.
Нажать «Вернуться к VPN»: дождаться обычного конфига с серверами и исправного VPN,
проверить прежние настройки пула/устройств/ручного выбора. Смена PID Xray здесь ожидаема.
Если всё прошло, снова выбрать standalone и оставить его работающим по поручению владельца.
При FAIL вернуть исходный VPN через интерфейс новой версии. Не маскировать отказ повторными
запусками. Если штатный возврат не работает, сохранить журнал приватно и сообщить STOP;
не удалять таблицы и не подменять вручную конфиги ядер с неизвестными поколениями.
После успешного возврата при необходимости откатить исходники из backup, затем перезапустить
только демон. При недоступной панели восстановить исходный panel.json из backup, выполнить
`sudo xgw apply --now`, дождаться VPN и лишь затем откатывать исходники.

## 7. Отчёт и автоматическая публикация

Отчёт до одной страницы: CODE, время UTC, инструмент самостоятельного запуска, установка,
Vision окна/видео, позиции плеера, качество, счётчики upload/download/vpn, неизменность PID
во время ролика, отказ обработчика, восстановление, кнопки питания/возврата, конечный режим.
Отдельные вердикты: MODE, VIDEO, FAILURE, RESTORE, GUI; общий PASS только при успехе всех.
Иначе FAIL/PARTIAL/NOT_RUN с фактической причиной. Состояние процесса не называть обходом.
Не утверждать невозможность zapret2 вообще по неудаче одной стратегии у одного провайдера.

При любом исходе исполнитель сам публикует отчёт в freepool без повторного подтверждения:
`docs/TEST-REPORT-REAL-MACHINE-0.2.0-zapret2-standalone-ДАТА.md`.
Проверить отсутствие секретов, коммитить только отчёт, обычный push, сверить файл в удалённой
ветке. Если ветка обновилась — перенести свой коммит на свежую origin/freepool без force.
Сообщить хеш и ссылку. Если публикация недоступна — сохранить отчёт и назвать причину.
