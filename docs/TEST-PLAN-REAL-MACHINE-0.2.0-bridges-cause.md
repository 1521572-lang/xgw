# ThinkCentre: почему мосты sing-box не отвечают и с каких пор падают общие сборки

Исполнитель — GLM-5.3-Flash. В отчёте youtube-direct все 5 мостов работающего поколения sing-box
вернули код curl 97, а в журнале youtube-journal все 13 сборок окна упали на проверке мостов нового
поколения. Один код не отделяет неверный пароль от недоступного сервера, а длительность сбоя не
измерялась. Здесь один помощник собирает точный вид отказа по каждому мосту и историю сборок за 14 дней.

**Только чтение.** Установка не нужна, режим `best` не включается, согласие владельца не требуется.
На каждый мост (не больше 8) — один малый запрос через него и одно TCP-соединение с сервером без
передачи данных. Это не замер скорости.

Можно: только команды этого ТЗ. **Машинное зрение на шлюзе по окну не кликает.**
Нельзя: менять config.toml, подписки, пул, ручной выбор, «Обновить», замеры, WAN, LAN, Tailscale и
сетевые правила; перезапускать службы; `xgw net down`, перезагрузка, `--force`. Журнал не очищать и не
поворачивать. Конфиги и журналы руками не читать.

В отчёт — только вывод помощника: метки и числа. Без исходных строк журнала, имён серверов и подписок,
адресов, доменов, тегов, отпечатков, SNI, short_id, паролей и путей.

## 2. Сбор (только чтение, до 10 минут)

```bash
umask 077
sudo python3 -I "$H" 2>&1 | tee "$D/out.txt"
```

Норма — строки по порядку: `INFO now=…`, `INFO generation …`, `INFO candidate …`, `INFO bridges …`,
строки `B1 …` по числу мостов, `LOG B1 …`, `LOG test_window_all …`, `LOG active_24h …`, при наличии
`LOG candidate_24h …`, `INFO journal_lines=…`, строки `DAY …`, `INFO fail_kinds …`, `INFO last …`,
`INFO streak …`, `helper_rc=0`.

- `STOP …`, `helper_rc=3` — записать строку как есть, повторов не делать, итог FAIL, к шагу 3;
- `INFO bridges total=0` — допустимый результат: мостов сейчас нет. Записать, итог DONE;
- любые значения `curl=`, `px=`, `tcp=`, `LOG …` — **не FAIL**: это данные, а не проверка;
- `px=other` или `px=-` при `curl=` не 0 — допустимо, переписать как есть.

Смысл меток не толковать и причину не придумывать: разбор делает разработчик. Состояние `DEGRADED` не
называть «обычной волной». Если вывод длиннее страницы — всё равно привести целиком.
