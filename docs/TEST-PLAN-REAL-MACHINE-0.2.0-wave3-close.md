# Закрытие волны 3 на ThinkCentre

После STOP на шаге 4 выполняется только [однократное уточнение](TEST-PLAN-REAL-MACHINE-0.2.0-wave3-close-readonly.md).
Не повторять prepare или baseline в уже созданном каталоге. Следующие шаги пока остановлены.
Для нового запуска помощник теперь сохраняет шесть отдельных результатов baseline.

Исполнитель — GLM-5.3-Flash, обычный терминал владельца. Прочитать всё до начала.
Шлюз работает: XGW → Wi-Fi-роутер → устройства. On сохраняем. Установку не выполнять.
WAN, LAN, Tailscale, пул и ручной выбор сервера не менять. Версия остаётся 0.2.0.
REC-C удалён и сохранён в archive/rec-c. Его прежние задания больше не выполнять.
Помощник — только `docs/helpers/wave3_close.py`, SHA-256: `65af212bf4c4501876842b165d708abfca075ee8b4242766cb79caaf0d0a22f3`.
Весь прогон занимает около 15 минут. Только IPv4 TCP с самого шлюза; не проверка LAN/UDP/IPv6.

```bash

'
```
Ожидается `Исходники обновлены`, код 0. Если не так: STOP, не reset/rebase/force.
Не сливать main. Обновился клон, а не установленный продукт.

printf '%s  %s

от Xray: чтение конфига sing-box. Не печатаются конфиги, таблицы и сообщения ядра.
Если отказов меньше шести или код не 0: STOP правок, прочитать report.
При неожиданном успехе помощник сразу убирает только созданный им тестовый файл/правило.

## Правило согласия для шагов 6–8

Перед КАЖДОЙ правкой спросить владельца: «Разрешаете эту правку с автоматическим возвратом?».
В вопросе назвать конкретно цепочку, таблицу или pref 100. Записать ответ в сообщении прогона.
Если именно эта правка в этом ТЗ уже явно разрешена в сессии, не спрашивать повторно.
Общее «продолжай» и разрешение другого шага согласием не являются. Без ответа cut не запускать.
Если владелец отказал всем трём, выполнить следующую команду и перейти к шагу 9:

```bash
sudo -n python3 -I -B /run/xgw-wave3-close/helper.py skip output table rule
```
Ожидается `Отказ владельца записан: правки не выполнялись`. В отчёте — NOT_RUN.
При отказе только одному шагу использовать `skip output`, `skip table` или `skip rule` соответственно.

Помощник ДО правки запускает собственный таймер в отделённом процессе.
Правило возвращает работающий демон. Если возврат не подтверждён за 60 секунд,
этот же помощник вызывает `sudo -n xgw net up`; следующая команда Flash не нужна.
Никаких off, перезапуска служб, перенастройки адаптеров, ручного восстановления или новых правок.
Резервная команда не равна успешному тесту: если потребовалась, результат не пройден.

## 6. С разрешения владельца опустошить output

```bash
sudo -n python3 -I -B /run/xgw-wave3-close/helper.py cut output --approved
```
Ожидается строка `цепочка output: пройдено`; TCP — `нет ответа за 3 с`, счётчик >0,
возврат ≤10 с, резерв не вызывался, после возврата loaded/HTTPS/on исправны.
Код 2 означает, что работа ещё идёт: выполнять только wait ниже. Код 3 — STOP следующих правок.

## 7. С отдельного разрешения владельца удалить ip xgw

```bash
sudo -n python3 -I -B /run/xgw-wave3-close/helper.py cut table --approved
```
Ожидается строка `таблица ip xgw: пройдено`, те же TCP/счётчик/конечные проверки; возврат ≤10 с.
Если не так — STOP следующих правок; не повторять шаг, не ждать TCP reset.

## 8. С отдельного разрешения владельца удалить pref 100

```bash
sudo -n python3 -I -B /run/xgw-wave3-close/helper.py cut rule --approved
```
Ожидается строка `правило pref 100: пройдено`, те же проверки; возврат ≤40 с.
С host TUN этот шаг не проверяет pref 100: помощник откажет до правки, настройки не менять.
Пул должен уже быть выключен для правок; включённый пул не выключать ради теста.

## Если команда вернула 2 или связь модели прервалась

```bash
sudo -n python3 -I -B /run/xgw-wave3-close/helper.py wait
```
Ожидается готовый короткий отчёт. Если `Проверка ещё выполняется. Повторите только wait`,
код 2: повторять только эту команду. Она ждёт не более 50 с; работу не перезапускает.
Потеря связи не отменяет таймер. После возвращения связи сначала wait, а не новая правка.
Итог неоднозначен — одна уточняющая волна разработчика, далее вопрос владельцу; не серия опытов.

## 9. Наблюдать счётчики 10 минут в рабочем on

```bash
sudo -n python3 -I -B /run/xgw-wave3-close/helper.py watch
```
Ожидается код 2, пока идёт наблюдение; использовать wait до готового отчёта.
Успех: наблюдение ≥600 с, прирост счётчиков 0, тот же состав правил/поколение,
конечные on/loaded/HTTPS исправны; настройки, пул и ручной выбор без изменений.
Рост счётчика — не пройдено. Смена правил/сброс счётчика — неопределённо, не «прирост 0».
При неисправной базе помощник откажет; не поднимать сеть вручную ради завершения наблюдения.

## 10. Прочитать весь одностраничный отчёт

```bash

```
Ожидается `# Закрытие волны 3` и не более одной страницы фактов; работающий помощник отмечен.
Не публиковать незавершённый итог. Числа/результаты не исправлять; NOT_RUN не заменять PASS.
Если владелец отказал в правках, закрываем волну по рабочему on и локальным тестам,
а три правки остаются NOT_RUN. Это не доказательство отсутствия пакетов на внешнем интерфейсе.
Отказ отдельного REALITY-сервера уже отнесён к серверу; новых переключений/диагностик здесь нет.
