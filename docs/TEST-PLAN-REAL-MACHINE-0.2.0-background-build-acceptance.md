# Приёмка фоновой сборки и записи статуса на ThinkCentre

Владелец после отчёта a7c7497 выбрал исходный критерий: запись статуса не реже раза в 25 с.
Возраст и интервалы обязательных проверок сохраняются как справочные показатели, без порога отказа.
On/HTTPS, сохранность настроек, сборка, десять минут и остальные проверки остаются обязательными.
В прошлом фрагменте запись укладывалась в 23,138 с; это ещё не полный десятиминутный PASS.
Один полный прогон, новые каталог и имя отчёта. Прежние материалы не трогать.

Все доступные инструменты исполнителя разрешены: терминал, браузер, мышь, клавиатура,
машинное зрение, локальные API и чтение журналов. Ограничены действия и публикация данных, не инструменты.
Снимки экрана можно использовать для работы, но не включать в публичный отчёт.
Отсутствие конкретного инструмента не означает STOP, если доступен другой способ выполнить то же действие.

Исполнитель: GLM-5.3-Flash. Только эта машина; отдельного клиента за роутером нет.
Волна 3 закрыта владельцем без трёх правок. Старые cut/isolation/watch/clarify не выполнять.
Цель: рабочий on сохраняется, сборка не задерживает шаг демона, статус обновляется до 25 с.
Проверка loaded, сетевые повреждения, смена серверов/региона/пула и установка целиком не входят.
Здесь один помощник, один запуск, десять минут наблюдения, один отчёт, включая неуспех.
Не менять WAN/LAN/Tailscale, конфиги, подписки, выбор сервера, службы ядер и версию.
Не запускать старые стенды, install, off, reset, rebase, force и ручную починку сети.
Закрыть редакторы настроек; во время прогона никто не меняет настройки или версии ядер.

Ожидается `Подготовлено. Установленный XGW не изменён`, код 0.
Помощник сверяет старые и новые суммы daemon.py и watch/status.py, права, неизменный unit
xgw.service без drop-in, состояние HEALTHY или DEGRADED, on/HTTPS, работающий демон и статус до 120 с.
Loaded не вызывается. DEGRADED и переходы HEALTHY ↔ DEGRADED не являются отказом.

каталог не удалять, другую установленную версию не подгонять под ожидаемые суммы.

## 5. Запустить один раз

```bash
sudo -n python3 -I -B /run/xgw-status-acceptance/helper.py start --owner-approved
```
Ожидается `Прогон запущен. Помощник сам завершит проверку или вернёт прежний код`, код 0.
Он работает отдельным процессом и не зависит от следующей команды модели или связи.
Файлы заменяются каждый атомарно; перезапуск демона — после замены обоих файлов.
Ошибку второй замены тоже обрабатывает возврат обоих файлов. Unit только сохранён, не заменён.

полный возврат отмечается неподтверждённым отдельно от связи. При непроверенном/нерабочем on — net up.
Старые конфиги ядер и настройки не перезаписываются. Успех возврата проверяется отдельно.
Повторный start запрещён даже при обрыве терминала; повторного рабочего потока не будет.
При тайм-ауте инструмента читать report, а не повторять start или запускать _worker/_sample.

## 6. Дождаться наблюдения и один раз обновить подписки

```bash
sudo -n python3 -I -B /run/xgw-status-acceptance/helper.py report --ready
```
Команда возвращается при начале наблюдения, не ждёт 45 с после его начала.
Код 2 и `Прогон продолжается: наблюдение` — выполнить обновление подписок ОДИН раз.
Выбрать удобный доступный инструмент. Через интерфейс: на вкладке подписок нажать «Обновить»;
ожидается «Обновляю подписки…». Через терминал — следующая готовая команда, без необходимости GUI:

```bash
sudo -n python3 -I -B /run/xgw-status-acceptance/helper.py refresh
```
Ожидается `Обновление подписок запрошено один раз`, код 0. Это штатный POST /api/refresh той же панели.
Помощник читает существующий локальный токен внутри процесса и не печатает его, не создаёт новый.
Не выполнять оба варианта: если уже нажали кнопку, команду refresh не вызывать.
Если ответ неизвестен, не повторять действие другим инструментом: запрос уже мог быть принят.
Модель сама использует доступные средства; ждать физического нажатия владельцем не нужно.
Если всё ещё `запущен`, читать report --ready; если `возврат`/конечный отчёт — обновление не запускать.
Если действие объективно недоступно всеми имеющимися способами — NOT_RUN, дать помощнику закончить.
Разрешено локально читать состояние, конфиги и логи для разрешённых действий; не публиковать секреты.
Другие действия панели, правки настроек, сети или служб этим не разрешены.

## 7. Дождаться конечного результата чтением, без новых действий

```bash
bash <<'BASH'
for n in $(seq 1 16); do
  sudo -n python3 -I -B /run/xgw-status-acceptance/helper.py report --wait
  rc=$?
  case "$rc" in 0) exit 0;; 2) continue;; *) exit "$rc";; esac
done
printf 'Срок ожидания исчерпан; start не повторять\n'
exit 3
BASH
```
Ожидается короткий отчёт и `Сбор данных: завершён`, код 0. «Не прошло» также завершённый факт.
Код 2 внутри цикла — только продолжающееся наблюдение, не ошибка и не разрешение повторить старт.
Код 3/пропажа прогресса: STOP, без kill/retry/prepare/старых ТЗ. Сообщить владельцу.
Если связь пропадала, после возврата разрешено только report; следующая команда не является rescue.
Помощник принимает HEALTHY и DEGRADED, включая переходы между ними, проверяет on/HTTPS,
прежние настройки, пул, выбор и процессы ядер;
считает промежутки обновления статуса и строки журнала о шагах от 60 с, без публикации журнала.
Статус читается отдельно, каждые 0,2 с, в том числе во время HTTPS. JSON и mtime — из одного файла.
Отдельно видны интервалы записей, время без изменения и паузы самого чтения. Порог остаётся 25 с.
Если при интервале больше 25 с чтение прерывалось больше чем на 1 с — это неизвестный результат,
а не доказанная задержка демона; помощник вернёт код с отдельной причиной и сохранит последние факты.
Время обязательных проверок изменяется только после новых ответов ядра, провайдера и сквозной пробы.
Повторная запись файла в конце шага не сбрасывает возраст этих проверок.
Критерии: завершена сборка, шагов от 60 с — 0, запись статуса не реже раза в 25 с,
возраст и интервалы обязательных проверок — справочно, сами по себе не вызывают возврат;
неудачных HTTPS-проб — 0. Медленная сборка сама по себе не означает медленный шаг.
Сам факт позднего возврата HTTPS-пробы не считается задержкой записи статуса.
В отчёте отдельно видны работа/ожидание цикла, прошлый шаг, настроенный период и остаток ожидания.
Это отдельная запись watchdog-step.json: она не освежает status.json и не скрывает его задержку.
Если предел нарушен — сохранить конкретную фазу и показатели. Не повторять старт или живые изменения. Чтение доступными инструментами разрешено.
Неоднозначность после выполненного уточнения — вопрос владельцу, а не новая серия стендов.
