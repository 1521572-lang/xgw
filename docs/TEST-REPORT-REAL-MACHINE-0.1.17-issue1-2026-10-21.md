## Итог

Исправление «интернет в LAN» работает: маршрут `throw 192.168.60.0/24` в таблице TPROXY
загружается установкой, путь пакета устройства сети остаётся `local (dev lo)` при
`src_valid_mark = 1` (раньше — EINVAL и тихая гибель пакетов), а после принудительного
удаления маршрута демон вернул его сам за 14 с (лимит 60 с), зафиксировав событие
«правила сети не были загружены — загружены заново»; состояние HEALTHY, «НЕТ ИНТЕРНЕТА»
не появлялось. Замеры скорости: кнопка «Замерить скорость» принята панелью (HTTP 200,
ok=True) и замерила 47 живых серверов за ~5 минут с прогрессом; после кнопки у всех
живых участников (4 из 4) и 43 из 61 живых запасных есть цифры, у каждого сервера без
цифры указана причина (без причины — 0), заказчик подтвердил картину в панели («Да, так»).
Через час фоновые замеры прошли сами: 42 из 42 живых безлимитных замерены заново, занятость
канала ни разу не отложила замер. Дефектов не обнаружено.

## Наблюдения

1. Шаги 3.1 и 4.2 (открыть сайт на телефоне в домашнем Wi-Fi) не проверялись: заказчик
   во время испытания не рядом с роутером и разрешил продолжать без телефона. Путь пакета
   LAN при обоих значениях флага проверен программно (`local (dev lo)`), самовосстановление
   маршрута — шагом 4.3.
2. Основной сервер сменился в 12:08 (до установки, при прежнем коде): «ОАЭ быстрее Польши» —
   новая логика выбора основного по замерам уже проявилась на живой машине.
3. После кнопки у 18 живых запасных «ждёт замера» — это лимитированные серверы (замеряются
   раз в 6 ч загрузкой меньше), у 7 — «скорость не замеряется» (x100, для LTE); у каждого
   без цифры показана причина.
4. diag выдаёт WARN — 2: прежние строки Telegram в config.toml (4 предупреждения в статусе),
   к issue #1 отношения не имеют.
5. Каталога /var/log/xgw нет — журналы служб в systemd-journal; Traceback в журналах с
   момента установки — 0.
6. Оценка трафика замеров — 3468 МБ/сутки (панель, «бюджет»): для сведения заказчика при
   лимитированном домашнем интернете.
7. Обходной файл /etc/sysctl.d/99-xgw-lan-tproxy.conf из инцидента 20.10 не тронут: теперь
   он не нужен (маршрут throw защищает путь LAN при любом значении флага), удалит сам
   заказчик, когда решит.
