# ThinkCentre — обновление открытого окна XGW, P2.9

**Ubuntu 24.04 LTS.** Flash сама запускает подготовленный сценарий
и выполняет проверку в браузере, затем автоматически публикует один
обезличенный отчёт при любом исходе. При недоступности терминала,
sudo, графического сеанса или GitHub запроси доступ и продолжи сама.
Код и команды подготовил Codex. Задача Flash ограничена проверкой.

В P2.8 прошли все 32 этапа и 24 контракта. Четыре параллельных
авторизованных GET вернули одинаковый короткий статус. Холодная
активация заняла 616 мс. Откат сохранил настройки и PID Xray.
[Отчёт P2.8](../reports/2026-11-21T182623Z_panel-read-parallel.md)

P2.9 закрывает конкретный случай UI04. Когда запрос состояния уже
идёт, возврат окна, F5 и завершение команды сохраняют один общий
запрос на немедленное обновление. После ответа 401 окно ждёт
повторного входа.

## 1. Временная проверка установленного Qt

В окно перезапуска панели запусти сценарий в терминале рабочей
графической сессии XGW. Сначала обнови допуск командой `sudo -v`.
Если pytest установлен отдельно, задай абсолютный `XGW_TEST_PYTHON`
к окружению, которое видит системный PyQt6. Изолированный таймер
отката на 20 минут вооружается до замены файлов. Сценарий временно
перезапускает `xgw.service` и сам восстанавливает файлы, права и
установленную панель.

~~~bash
bash <<'BASH'
set -euo pipefail
BR=integration/zapret2-batch1
CODE=5e856e0cf31110114cc85388610e980d53b31556
REPO=$(git rev-parse --show-toplevel)
cd "$REPO"
git fetch origin "$BR"
git merge-base --is-ancestor "$CODE" FETCH_HEAD
git show "$CODE:docs/helpers/run_panel_installed_trial.sh" | bash -s -- "$CODE"
BASH
~~~

## 2. UI04 в свежей вкладке

После возврата базы открой одноразовый вход командой
`xgw panel --login` из графического сеанса. Перейди на страницу
zapret2 в только что авторизованной вкладке. Запиши отдельно
результат на восстановленной установленной версии.

1. Включи запись запросов в DevTools на этой вкладке. Открой настройки
   zapret2, введи другое допустимое значение интервала проверки и
   оставь черновик открытым. Сохрани значение в частной заметке.
2. Переключись на другую вкладку на 30 секунд. После возврата проверь
   журнал запросов. Во время скрытия периодических GET обзора нет.
   После показа приходит свежий 200, черновик сохраняет введённое значение.
3. В DevTools переведи эту вкладку в Offline. Дождись сообщения об
   обрыве связи. Верни Online и дождись следующего штатного опроса
   по журналу, до 75 секунд. Черновик сохраняется, запросов POST нет.
   Отмени черновик через «Отмена». Зафиксируй числа GET/POST и итог
   визуальной проверки. Публикуй обезличенную сводку.

Если браузерный шаг не пройден, укажи состояние интерфейса и последний
успешный шаг. Для недоступной рабочей сессии запроси доступ.

## 3. Автоматическая публикация

Укажи абсолютный путь к обезличенному отчёту в `REPORT_SRC`, сама
выполни блок и верни ссылку на опубликованный коммит.

~~~bash
bash -s -- "$REPORT_SRC" <<'BASH'
set -euo pipefail
umask 077
REPORT_SRC=$1
BR=integration/zapret2-batch1
[[ $REPORT_SRC == /* && -s $REPORT_SRC ]]
REPO=$(git rev-parse --show-toplevel)
PUB=$(mktemp -d "$HOME/xgw-panel-qt-resume-publish.XXXXXXXX")
git -C "$REPO" fetch origin "$BR"
git -C "$REPO" worktree add --detach "$PUB/repo" FETCH_HEAD
trap 'git -C "$REPO" worktree remove "$PUB/repo" && rmdir -- "$PUB"' EXIT
cd "$PUB/repo"
REPORT="docs/reports/$(date -u +%Y-%m-%dT%H%M%SZ)_panel-qt-resume.md"
test ! -e "$REPORT"
cp -- "$REPORT_SRC" "$REPORT"
git add -- "$REPORT"
git diff --cached --check
git commit -m 'Report ThinkCentre Qt poll resume acceptance'
if ! git push origin "HEAD:refs/heads/$BR"; then
  git fetch origin "$BR"
  git rebase FETCH_HEAD
  git push origin "HEAD:refs/heads/$BR"
fi
git fetch origin "$BR"
git merge-base --is-ancestor HEAD FETCH_HEAD
printf 'PUBLISHED %s %s\n' "$(git rev-parse HEAD)" "$REPORT"
BASH
~~~
