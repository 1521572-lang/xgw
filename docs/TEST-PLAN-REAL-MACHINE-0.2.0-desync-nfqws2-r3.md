# ThinkCentre: устойчивый nfqws2, смена профилей и недоступные пути

Дата подготовки: 2026-11-14. Ветка `gui-light`, версия XGW 0.2.0.
CODE = `a99cd41ae606be0d6907151885779b911cfd9e01` — готовность очереди и сохранение контроллера.
BASE = `9b58725354799a6b91c7341c41a311371bdfa4d8` — установленный код по отчёту `b6421a5`.
Испытывать именно этот CODE. HEAD вместо CODE не использовать.

Это самостоятельный повтор неуспешной части r2. Генерацию обоих ядер, QUIC/noise, CIDR и
восстановление nftables из r2 не повторять. Основная приёмка — на реальном шлюзе, без полного pytest.

## 1. Кто выполняет и что разрешено

Модель сама находит checkout, читает файлы, запускает команды, открывает и осматривает GUI через
vision, анализирует результаты и публикует отчёт. Не просить владельца запускать/копировать команды,
читать журналы или делать снимки. Недоступен терминал, root или браузер — запросить доступ и затем
действовать самостоятельно. Пароль/системное подтверждение вводит владелец. Без доступа — NOT_RUN.

Использовать действующие согласия из r2 на испытание nfqws2, профили/offload и установку исправления;
новое согласие запрашивать только для действий, которые ими не покрыты. Не менять WAN/LAN, Tailscale,
подписки, пул, pin и маршруты дома. Не выполнять nft flush, удаление таблиц, обновление ядер/пакетов,
перезагрузку, установку стороннего zapret2, force push или reset --hard. Чужие worker не останавливать.
Из установленного кода обновить только три Python-модуля ниже, не весь пакет и не GUI.

Публикация отчёта автоматическая при PASS/PARTIAL/FAIL/STOP/NOT_RUN, без повторного подтверждения.
Все конфиги, журналы, снимки, IP/домены, имена серверов/устройств, URL подписок и ключи — приватно.
В GitHub только обезличенный итог, числа, версии, коды состояний и причин.

## 2. Исходники, доступ и резервная копия

В существующем checkout XGW выполнить:

```bash
set -eu
umask 077
git fetch origin gui-light
CODE=a99cd41ae606be0d6907151885779b911cfd9e01
BASE=9b58725354799a6b91c7341c41a311371bdfa4d8
git cat-file -e "$CODE^{commit}"
git merge-base --is-ancestor "$CODE" FETCH_HEAD
D=$(mktemp -d "$HOME/xgw-nfq-r3.XXXXXXXX")
TARGET="$D/new"
git worktree add --detach "$TARGET" "$CODE"
test "$(git -C "$TARGET" rev-parse HEAD)" = "$CODE"
test -z "$(git -C "$TARGET" status --porcelain)"
```

Не сбрасывать неизвестные изменения и не удалять прежние каталоги прогона. Сохранить приватно
status --json, diag --no-net, журнал текущего запуска, PID демона/Xray/sing-box, nft tables,
NFQUEUE, nf_conntrack_acct, ethtool -k WAN, config.toml и panel.json. Команды выполняет модель
через доступный root-канал. Под set -e ожидаемый ненулевой rc сохранять через if, не обрывая отчёт.
Начало: HEALTHY, capture on, selective off, engine off/отсутствует, чужой очереди нет.
Иначе STOP baseline_changed с описанием факта, ничего не исправлять вслепую.

Уточнить реальный каталог Python-модулей установленного XGW (по r2 — `/opt/xgw/lib/xgw`).
Сохранить с владельцами и режимами `cli.py`, `daemon.py`, `nfqws2.py`, сверить их с BASE.
При несовпадении сначала выяснить установленную версию; чужую доработку не перезаписывать.
Сохранить root-копии TOML/panel и трёх модулей для отката. Откат проверить до установки.

## 3. Один короткий входной набор

Обычным пользователем, без sudo, использовать уже имеющийся Python/pytest:

```bash
cd "$TARGET"
if PYTHONPATH=src:. python3 -m pytest -p no:cacheprovider -o addopts= -q \
  tests/test_nfqws2.py \
  tests/test_daemon.py::test_nfqws2_survives_reload_and_closes_on_shutdown \
  tests/test_daemon.py::test_run_returns_when_the_config_file_changes \
  tests/test_daemon.py::test_stop_during_a_subscription_poll_ends_it_at_once \
  tests/test_cli_commands.py::test_failed_reload_closes_preserved_nfqws2 \
  tests/test_cli_commands.py::test_run_once --durations=5 >"$D/tests.txt" 2>&1; then
  rc=0
else
  rc=$?
fi
printf 'tests_rc=%s\n' "$rc"
```

Ожидание — 23 PASS, возможен отдельный счётчик unittest subtests. Любой FAIL — STOP до установки,
модель читает журнал и автоматически публикует отчёт. Порог остановки <2 с не увеличивать.
Не запускать полный pytest или повторный BASE-набор. Если pytest нет, запросить доступ к имеющемуся
окружению; отсутствие возможности проверки обозначить STOP tests_unavailable.

## 4. Установка трёх модулей и запуск

Сохранить engine=off. Скопировать из TARGET только `src/xgw/{cli.py,daemon.py,nfqws2.py}` в проверенный
каталог установленных модулей, сохранив штатные права root:root 0644. Сверить SHA-256 каждого файла
с CODE. Один раз перезапустить только xgw.service. Не перезапускать Xray и sing-box вручную.
Норма: HEALTHY, HTTPS шлюза/LAN работает, новых FAIL нет, nfqws2 не запущен.
При сбое вернуть сохранённые три модуля и настройки, запустить демон, проверить восстановление.

Использовать существующий комплект nfqws2 1.0.7 и Lua; права root 0755/0644 проверить без изменения.
TLS/QUIC fake-блобы встроены; ничего скачивать не нужно. Временно включить nf_conntrack_acct=1
в рамках согласованного прогона и сохранить исходное значение. Выбрать свободную очередь.
В существующей секции zapret2 задать mode=off, engine=auto, engine_profile=seqovl и эту очередь.
Дождаться active не дольше 90 с, опрашивая статус/очередь каждые 2 с. Если правила требуют обновления,
использовать штатный xgw enable. Успех — одновременно active unit, правильный профиль и listener очереди.
При FAIL сохранить только собственный журнал worker и коды причин, восстановить off и опубликовать отчёт.

## 5. Профили и перечитывание настроек

Последовательность: seqovl → hostfakesplit → disorder-badseq → seqovl. Менять только engine_profile,
сохраняя остальные поля. Для каждого профиля дождаться active и наблюдать минимум два шага watchdog
(не менее 60 с). Записать число стартов/остановок unit, время готовности, PID worker и Xray.
Ожидание: один новый worker на смену профиля, затем стабильный PID, без worker_down/worker_start_timeout.
В cmdline приватно проверить точные аргументы профиля. Одного названия в status недостаточно.
Если профиль из памяти сканера перекрывает настройку, указать фактические applied profiles; память не стирать.

На каждом профиле модель создаёт новые HTTPS-соединения, проверяет рост счётчика NFQUEUE и доступность
VPN/direct/LAN для реально существующих путей. Проверку direct не заменять VPN fallback.
PID Xray при смене только профиля сохраняется. Сбой профиля/цикл перезапусков — FAIL, дальнейшие
зависимые этапы остановить. Разрыв связи — восстановить off и исходные настройки.

При disorder-badseq сверить offload с исходным снимком: поддерживаемые включённые ранее флаги отключены.
Не меняя содержимое TOML, обновить его mtime (`touch`) для перечитывания настроек. Подтвердить reload
по журналу. Worker/PID должны сохраниться, offload оставаться отключённым. Наблюдать ещё два шага.
После возврата к seqovl все четыре управляемых offload-флага обязаны совпасть с исходным снимком,
включая изначально выключенные. Повторить touch в seqovl: лишнего перезапуска worker не должно быть.

## 6. Остановка, восстановление и недоступные пути

При устойчивом active один раз остановить только xgw-nfqws2.service, открыть новые соединения.
Трафик продолжает идти благодаря queue bypass. Демон должен восстановить worker в пределах 90 с,
с тем же профилем и без рестарта Xray. Наблюдать 60 с после восстановления. Иначе FAIL recovery.

Отдельно проверить PermissionError из r2, не ослабляя sandbox и права настоящего комплекта.
При engine=off создать собственную копию бинарника в отдельном root-каталоге `/var/lib/xgw/` с правами
0755 и без соседних lua/blobs. В качестве lua_dir указать приватный каталог исполнителя 0700,
реально недоступный демону (как в r2); бинарник должен оставаться доступен. Перечитать с engine=auto.
Ожидание: off/not_found, нет traceback и сбоя шага watchdog, HTTPS/HEALTHY сохраняются. Если найден
другой доступный комплект Lua, это не проверка отказа: установить фактический путь и исправить только
расположение своей тестовой копии, не прятать системные файлы. Недоступность должна быть подтверждена.
Вернуть исходные binary/lua_dir, дождаться active и стабильной работы. Затем engine=off: worker/очередь
исчезли, offload восстановлен; при необходимости штатным enable убрать nfq_output.

## 7. Полезный результат и завершение

При наличии уже настроенного direct-пути YouTube модель сама запускает браузер и один и тот же ролик
при engine=off/auto. Через vision проверяет воспроизведение, по маршруту/счётчикам исключает VPN fallback.
HTTP 200 не считается видео. Нет direct-пути — VIDEO_DIRECT=NOT_RUN, не утверждать обход YouTube без VPN.
Этот прогон прежде всего закрывает стабильность worker; его PASS не доказывает эффективность против ТСПУ.

Вернуть config.toml/panel.json и nf_conntrack_acct в исходное состояние. Сверить offload, таблицы,
службы, capture/lifecycle, diag и HTTPS. Новые три модуля можно оставить только при успешной приёмке;
при FAIL вернуть сохранённые исходные модули и перезапустить только демон. Записать оставшийся код.
Удалять только свои тестовые файлы после проверки абсолютных путей; закрыть root-канал после восстановления.

## 8. Автоматическая публикация

Отчёт на одну страницу: `docs/TEST-REPORT-REAL-MACHINE-0.2.0-desync-nfqws2-r3-ДАТА.md`.
Указать CODE, ОС/версии, 23 теста, INSTALL, START, PROFILE_SWITCH, RELOAD_SAME, OFFLOAD,
WORKER_RECOVERY, PATH_ACCESS, VIDEO_DIRECT, RESTORE, первый FAIL и оставшийся код.
Для профилей — времена, стабильность PID, счётчики без адресов. PARTIAL/NOT_RUN не заменять PASS.

Модель автоматически публикует отчёт при любом исходе: чистое дерево от свежей origin/gui-light,
только обезличенный отчёт, git diff --check, commit и обычный push в gui-light. При конкурентном
обновлении перенести только свой отчёт поверх новой ветки, без force и сброса чужих изменений.
Проверить удалённый коммит через git ls-remote и дать ссылку. Нет доступа — запросить его;
если доступ не предоставлен, сохранить отчёт локально и указать PUBLISH=NOT_RUN.
