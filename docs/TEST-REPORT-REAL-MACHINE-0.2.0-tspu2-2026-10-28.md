## Наблюдения

1. **Остановка команды установки заказчиком.** Посреди шага 2.2 заказчик остановил команду и
   попросил при тестировании использовать механизмы защиты, чтобы не упало соединение на
   сетевом интерфейсе, через который машина ходит в интернет. Сценарий установки к этому
   моменту завершился полностью. Защитные механизмы соблюдены и дальше: установщик XGW не
   трогает WAN-интерфейс, его соединение NetworkManager и DHCP-клиент внешней сети (правится
   только LAN-профиль enp4s0, свои таблицы nftables одной атомарной транзакцией, свои службы);
   перезапуски служб идут в fail-closed (трафик блокируется на секунды, линк жив);
   NetworkManager/`ip`/`nft` руками не запускались и не перезапускались. Соединение WAN
   (enp3s0f0, адрес из домашней сети) за всю программу не прерывалось.
2. **Перезапуск tailscaled в момент установки.** 13:13:06–13:13:08 tailscaled был остановлен и
   запущен снова (в журнале рядом — активность packagekit; похоже, обновился пакет и его сценарий
   перезапустил службу; установщик XGW tailscaled не трогает — в install.py таких операций нет).
   Минут 15 BackendState был NoState, затем самостоятельно вернулся в Running (13:22). На
   проверки программы не влияло (Tailscale в этой программе только фиксируется).
3. Сумма помощника совпала с первого выполнения команды шага 1.2 — heredoc в ТЗ переносится
   целиком (как и в ТЗ audit5).
4. «правила загружены заново: 1» — единственная загрузка правил самой установкой (допустимо
   0 или 1); повторных загрузок и «загрузок по кругу» нет.
5. Число серверов через sing-box: 29 до установки → 28 в итоговом статусе (конфиг sing-box
   ждёт окна перезапуска, состав обновился при пересборке) — информационно, критерия в ТЗ нет.
6. «серверов с вердиктом „отказ/таймаут“: 12» — стабильно до и после: у отказавшихся запасных
   адреса напрямую открываются, их режет не адрес; срабатываний кейса «адрес закрыт» в живой
   сети за время проверки не было.
