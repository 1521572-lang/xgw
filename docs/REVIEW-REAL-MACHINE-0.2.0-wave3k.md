## Новое прямое указание владельца имеет приоритет

После отчёта владелец уточнил: этот шлюз использовался для раздачи интернета через
подключённый к XGW роутер до наших доработок; он включит его обратно, и нужно исходить
из работающей схемы. Принимаем её как эксплуатационный baseline.

Теперь исходное состояние — рабочий **on**, не off. Модель не должна повторно выключать
его ради подготовки, добиваться off/preflight или требовать SSH-инвентаризацию как
предусловие обычной работы. Прежние короткие on→off испытания — исторические результаты,
а не постоянный способ эксплуатации. Старый always_off guardian запрещён для этого baseline:
его срабатывание само выключило бы рабочий VPN.

Проверка свойств доработок и признание существующей работы — разные результаты:
из прежнего короткого запроса нельзя вывести полный E4/fault PASS; из отсутствия такого
PASS нельзя вывести, что шлюз/домашняя LAN не работают. Полная волна3 остаётся открытой,
эксплуатацию продолжаем. Для будущего разрушительного теста сначала нужен отдельный
дизайн локального восстановления исходного on, совместимый с ограничением входящего
обрыва >1 минуты. Здесь таких тестов не планируется.
