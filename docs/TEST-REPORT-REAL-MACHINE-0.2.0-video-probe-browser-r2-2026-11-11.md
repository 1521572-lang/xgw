1. Квитанция снова остановилась на отметке запуска — **крах происходит до первой поэтапной
   записи**: `atomic_write_json` в новом помощнике стоит после возврата `browser()`, поэтому
   исключение из браузерной фазы по-прежнему теряет все данные. Просьба разработчику №1:
   сохранять этап немедленно после каждого шага (Relay поднят, Firefox запущен, рукопожатие
   пройдено), а не после возврата функции.
2. Инструментированный повтор дал `browser_control_failed` при `relay_spent=0` — Firefox ни
   одного байта не направил через реле, обмен умер до навигации.
3. Корень найден и подтверждён экспериментами на этой машине: **порт Marionette выбирается из
   эфемерного диапазона приёмом bind→close сразу после ephemeral-bind релея**; аллокатор ядра
   раздаёт эфемерные порты последовательно, и за секунды старта snap-Firefox выбранный порт
   занимает любой новый исходящий TCP-коннект (шлюз и приложения создают их постоянно).
   Факт: с эфемерным портом Marionette не открылась за 90 с при живом Firefox (воспроизведено),
   с фиксированным портом вне эфемерного диапазона — открывается за 4–6 с; случайные
   коллизии bind→close→rebind при паузе 3 с — 0 из 15, то есть перехват именно
   последовательным allocation, а не случай. Firefox при этом продолжает работать без
   Marionette → помощник теряет управление.
   Просьба разработчику №2: выбирать порт Marionette вне эфемерного диапазона (например,
   1024–9999) с циклом попыток bind-проверки, либо сократить окно между выбором порта и
   стартом Firefox.
