## Наблюдения для Codex

1. **Механизм возврата не сработал в живом цикле при состоянии, которое
   по наблюдаемым данным было готовым к возврату.** Данные окна: конфиг
   sing-box существует, `resume_managed=true`, pending/draining пусто,
   базовый юнит активен и жив, инвентарь на месте (обычные сборки
   проходили), признак отказа ядра не появлялся, машина HEALTHY/DEGRADED.
   Стоит добавить одноразовую запись в журнал/статус, когда демон видит
   `resume_needed=true`, но шаг не запускает, с причиной (какое из
   условий не выполнилось) — иначе живая диагностика упирается в отсутствие
   следов.
2. **Разница контракта и живого потока**: тест вызывает шаг возврата
   напрямую и вручную создаёт конфиг sing-box; в живом цикле шаг
   достигается из общего шага демона с гейтами (`changed`, `core_job`,
   машина состояний). Полезен контракт, воспроизводящий путь целиком
   после выхода из Standalone.
3. Переходные состояния Standalone (`preparing`) подтвердились вживую —
   исправление из предыдущего задания работает; включение заняло 40 с,
   ни одного «blocked» при штатном ходе.
4. Финальная проверка управляемого поколения после отката (35 с) не может
   быть положительной по построению: откат возвращает файлы базы без
   механизма возврата. Либо исключить это ожидание при откате, либо
   проверять отдельно после повторной установки исправления.
5. Окно 240 с может быть просто короче реального пути возврата (сборка +
   проверка мостов + применение); если причина из п.1 устранима, стоит
   переизмерить с более широким окном или с ручным триггером.
