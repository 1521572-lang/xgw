# T11 — интеграция Web UI Zapret-Manager в XGW

Согласовано владельцем 2026-11-17. Первый экран обзора принят на Ubuntu.
Базовое управление принято. В 2b78617 добавлены задания, отмена, pin/reset
профиля и локальный проверенный импорт ALT9 в обоих UI; новая
[объединённая приёмка на ThinkCentre](COMBINED-ACCEPTANCE-2026-11-18.md)
охватывает их вместе с видео и суточным наблюдением.
Документ расширяет [единый план T01–T12](DESYNC-ROADMAP.md).
Текущее задание реальной машины остаётся в [NEXT_STEP](NEXT_STEP.md).

## Результат для пользователя

Добавить в XGW веб-панель на основе интерфейса Zapret-Manager для управления zapret2
и наблюдения за его работой. Сохранить настольный Proton GUI, подписки над серверами,
страны по IP, сортировку и анимацию карты. Обе UI используют один API, одну политику
и один контроллер XGW. Пользователь видит одинаковое фактическое состояние в обеих.
Удаление или замена существующих пользовательских элементов требует подтверждения владельца.

## Источник и границы переноса

- Репозиторий — [StressOzz/Zapret-Manager](https://github.com/StressOzz/Zapret-Manager).
  Проверенная база исходников — `1ff3f5aa01e85125548eccc0a1dd6229a99123fb`.
- [ZapretManager_LuCI.sh](https://github.com/StressOzz/Zapret-Manager/blob/1ff3f5aa01e85125548eccc0a1dd6229a99123fb/ZapretManager_LuCI.sh)
  содержит Web UI (`zm-webui.html`, `zm/app.js`, `zm/app.css`), общие модули страниц
  и backend. Извлекать выбранные ресурсы как данные, не запускать upstream-установщик.
- Сохранить Apache-2.0 LICENSE, NOTICE и применимые уведомления об авторстве.
  Зафиксировать исходные пути, SHA, хэши и изменения в манифесте заимствований;
  отдельно проверить лицензии включаемых иконок, шрифтов и сторонних ресурсов.
- Перенести оболочку, навигацию, карточки, темы и подходящие страницы. Удалить из
  переносимого набора зависимости от ubus/rpcd, UCI, procd и установки пакетов OpenWrt.
  Авторизацию и команды перевести на API XGW. Включать только необходимые ресурсы.
- OpenWrt-настройки, сторонние установщики, радио, реклама, веб-терминал и менеджеры
  других VPN не входят в этот этап. Их наличие в upstream не создаёт функции XGW.
  Штатный сетевой контроллер XGW остаётся единственным владельцем изменений маршрутов.

## Состав экранов и зависимости

| Экран | Отображение и действия | Основание / готовность |
|---|---|---|
| Обзор | Режим, движок, применённая ревизия, актуальность, ошибки, фактический путь и состояние VPN | T01–T04; неизвестное значение показывать явно |
| zapret2 | Выбор режима, допустимого профиля, предварительная проверка, применение и результат | T02/T03/T06; использовать существующую транзакцию |
| Домены и исключения | Просмотр и редактирование области действия с проверкой перед применением | Схема XGW; явно показывать смысл Standalone и Selective |
| Стратегии | Каталог, параметры, происхождение, совместимость и результаты на этой линии | T06; импорт Flowseal только после T10 |
| Проверки | Ход задания, бюджет, результаты, запуск/остановка и отмена | T09; CLI-журнал сам по себе не означает готовность фонового управления |
| Кэш и события | История, свежесть измерений, курсор, пропуски и перезапуск worker | T07/T08; pin/reset после реализации и приёмки команд |
| YouTube | Прогресс видео, качество, буфер, остановки, протокол и подтверждение маршрута | Существующая телеметрия; запуск процесса и HTTP 200 не доказывают воспроизведение |

Кнопки доступны по возможностям установленного backend. Для отсутствующей возможности
показать понятное объяснение; не имитировать её успех. Применение настроек, транспортная
проверка и успешное видео отображаются раздельно. Результат стратегии привязан к дате,
сетевому контексту и условиям опыта; отсутствие измерения не означает ноль или FAIL.

Для Selective карточка использует текущие поля `mode`, `state`, `fresh`,
`policy_matched` и `evidence.vpn_control` из `/api/state`. В обзоре покажи, какие
домены включены в обход и что происходит при fallback. Подтверждение просмотра
берётся из измерения плеера, а дельты выходов Xray служат отдельным источником
свидетельства маршрута в [приёмке Selective](T04-SELECTIVE-YOUTUBE.md).
Отсутствующий счётчик отображай как «нет данных».
Для опции `youtube_transport_probe` статус `evidence.transport=https_reachable`
означает доступность HTTPS до страницы и CDN. `evidence.playback` остаётся
`not_tested` до независимого замера плеера. При истечении состояния HTTPS
снова показывается как неизвестный.

## Порядок реализации

Первый экран `/zapret2` использует сессию XGW. `GET /api/zapret2/overview`
возвращает ту же карточку, что и основной API, и последние 16 событий очереди.
Передаются только время, вид события, служба, очередь и поколение. Журнал
заменяется при смене эпохи. [Источники стилей](T11-ZAPRET-MANAGER-SOURCES.md),
[ТЗ приёмки](T11-ZAPRET2-WEB-ACCEPTANCE.md),
[отчёт](../reports/2026-11-17_desync-zapret2-web.md).

1. **T11.1 — контракт и происхождение.** Составить карту переносимых страниц и ресурсов,
   проверить лицензии, закрепить upstream SHA. Сопоставить поля и действия с фактическими
   API XGW, документировать недостающие методы, ошибки и capability-флаги. Существующие
   `/api/state` и операции GUI использовать как исходную точку. Контракт новых методов
   определяется по backend, не по OpenWrt RPC. Выделить статический UI из shell-кода.
2. **T11.2 — оболочка и наблюдение.** Подключить извлечённые ресурсы к существующему
   серверу панели XGW. Адаптировать навигацию, светлую/тёмную темы, мобильную ширину,
   обзор, каталог и журнал. Начать с чтения состояния. Обеспечить ограниченный опрос,
   восстановление связи, индикаторы устаревания и защиту от ответов старой ревизии.
3. **T11.3 — управление.** Подключить подтверждённые команды режима, профиля и доменов,
   затем задания, импорт и pin/reset по готовности зависимостей. Проверять входные
   данные, ожидаемую ревизию, конфликт двух UI и повторный клик. Не повторять неизвестно
   завершившуюся мутацию вслепую после таймаута; перечитать результат операции.
   Один запуск задания имеет один идентификатор и ограниченный бюджет; после закрытия
   страницы его состояние доступно при повторном входе. Отмена имеет явный результат.
4. **T11.4 — установка и приёмка.** После реализации опубликовать отдельное пошаговое
   ТЗ с SHA, установочным helper, резервной копией, обратимым обновлением и проверкой
   отката. Приёмку выполнять на работающем XGW в Ubuntu 24.04 LTS. Включать новые
   возможности пользователю после подтверждения фактического результата в отчёте.

Статические экраны и контракт можно готовить до завершения T09/T10. Команды включать
по готовности соответствующего этапа. Это позволяет развивать UI без объявления
непринятых сетевых возможностей реализованными.

## Доступ и целостность управления

Использовать текущую модель доступа XGW — loopback и настроенный Tailscale Serve,
сессию панели, Host-проверки и защиту изменяющих запросов. Не открывать новый порт
в LAN/WAN автоматически и не переносить вход паролем root из OpenWrt.
Строки подписок, доменов и событий выводить безопасным текстом. Секреты и подписанные
видеоссылки не включать в ответы UI, журналы для публикации и скриншоты отчёта.
Страницы не исполняют произвольные shell-команды и не меняют nftables напрямую.

## Проверка и критерии приёмки

Локально — минимальные целевые проверки API-контракта, валидации, конфликтов ревизий
и доступа плюс линтер для изменённого кода. Основная приёмка — на ThinkCentre.
Codex публикует реализацию, целевые тесты и команды установки с откатом. Flash
сама запускает опубликованный helper и проверки на закреплённом SHA, проверяет
экран через vision и публикует только отчёт. При отсутствии доступа запрашивает
его.

- Проверить установку, запуск и откат на действующем приложении. До изменений снять
  рабочее состояние и подготовить возврат; после каждого сетевого опыта проверить
  действительный маршрут и восстановление исходной политики.
- Сравнить веб-панель и Proton GUI с backend при смене режима/профиля, ошибке применения,
  недоступности worker, разрыве связи и одновременном редактировании из двух UI.
- Проверить обе темы, узкое окно, клавиатуру и читаемость ошибок. В Proton GUI проверить
  подписки, реальные страны, сортировку и анимацию активного сервера по IP.
- Проверить неавторизованный и чужой запрос, истечение сессии, безопасный вывод строк,
  отсутствие секретов и недействующих кнопок. Обновление страницы не повторяет команду.
- Для готовых заданий проверить запуск, отмену, перезаход, бюджет, единственность
  выполнения и согласованность журнала. Курсор событий переживает разрыв соединения;
  смена эпохи и потерянные события явно обозначаются.
- Для управления zapret2 выполнить реальный YouTube-прогон по принятой методике
  телеметрии с доказательством маршрута без VPN и 15+5 минутами на проверенном профиле.
  Сравнить показания UI с первичными измерениями. Сетевой FAIL отделять от дефекта UI;
  смена интерфейса сама по себе не считается улучшением обхода.
- Автоматически опубликовать обезличенный отчёт в `docs/reports/` даже при частичном
  выполнении или блокере. Указать SHA, фактическое состояние установки, проверки,
  скриншоты, ограничения и возврат. NEXT_STEP и roadmap по результату обновляет
  Codex. Flash публикует только отчёт по [действующему объединённому ТЗ](COMBINED-ACCEPTANCE-2026-11-18.md).

Планирование UI не означает её готовность. Задание на установку выпускается вместе
с проверяемой реализацией, без требования запускать upstream shell-установщик на Ubuntu.
