# XGW: реализация волны 3 и локальная проверка

Дата: 1 ноября 2026. Baseline `freepool@8155f7760cf8398315335fcddea2e6783f3a93e2`. В опубликованном baseline были README,
ASSUMPTIONS285 и программа проверки, а реализация PR-N4/N5 отсутствовала. Этот кандидат
заполняет разрыв. Изменения публикуются в ветке freepool вместе с ТЗ. Установка на реальной машине не выполнялась.

## Реализовано

- Отдельная таблица `inet xgw_guard` на защищённых OUTPUT/FORWARD путях. Capture-approved
  bypass получает бит conntrack, guard сам разрешения не создаёт. Общий ruleset flush и
  неуправляемые forwarding interfaces не входят в гарантии этой волны.
- Атомарный apply включает guard; ошибка guard не допускает fallback без него.
  Baseline/manifest/digest/monitor охватывают третью таблицу; counter ticks не меняют digest.
- Постоянный sing-box работает как `xgw-singbox` без capabilities. Его конфиги имеют свою
  группу/setgid-каталог; `routing_mark` удалён из постоянного генератора. Временная проверка
  FreePool сохраняет прежний mark. Служба использует высокие порты.
- UID bypass применяется до запуска немаркированного worker. Изменённый unit требует restart,
  а не SIGHUP старому процессу. При отказе миграции возвращаются прежние unit/config/DAC;
  перезапущенный worker восстанавливается со старой службой. Установка возвращает ошибку.
- Уже существующий пользователь с UID root/xray либо группами root/xray отвергается;
  чужой аккаунт удаление не присваивает себе. Loopback block учитывает original/reply:
  новые соединения sing-box к loopback запрещены, ответы его SOCKS/API listener разрешены.
- `xgw diag` проверяет guard и фактические UID/capability sets процесса; `net show` включает
  барьер. Flash-план получает локальный проверяемый patch вместо недостающего remote-кода.

## Что остаётся проверить Flash

Реальная ThinkCentre Ubuntu24.04/systemd255, настоящий SB1.14.4, миграция живых служб и
пользователей, рабочая подписка, Tailscale/время, scoped faults и наблюдение — **NOT_RUN**.
Физический WAN sentinel, LAN/Docker/tailnet/IPv6/UDP packet paths не получили PASS из IPv4
veth fixture. Полная VM-install и длительные stress/перезагрузка не выполнялись.

Для проверки используется опубликованный `docs/TEST-PLAN-REAL-MACHINE-0.2.0-wave3.md`.
Он получает код из origin/freepool и сверяет его с конкретным commit реализации перед
установкой. Старый локальный ZIP остаётся отдельным историческим артефактом; смешивать его
patch с опубликованным Git-кодом не требуется. Реальные результаты заполняет Flash по
шаблону и сохраняет отчёт, который затем проверяет разработчик. Wave4/DAE/G1 не активированы.
