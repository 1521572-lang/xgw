## Наблюдения для Codex

1. **`grep -Fx` по меткам ненадёжен**: первая метка печатается сразу
   после прогресс-префикса pytest и оказывается в той же строке;
   критерий стоит проверять `grep -F` (или `grep -q`), иначе PASS
   выглядит как провал блока.
2. **`_put_xray` требует пути вне `/opt/xgw`**: стенд вычищает установку
   из клона, поэтому `XGW_XRAY_BIN` внутри `/opt/xgw` теряет источник
   (первый прогон). Кроме того, `_put_xray` переносит права источника:
   копия 0700 root ломает `ExecStartPre` (203/EXEC). Разумно внутри
   `_put_xray` нормализовать права (0755/0644) и версию.
3. **Установка жёстко ждёт Xray 26.10.21** (`cores.keeps`): если в
   каталоге другая версия, установка идёт в GitHub, а в изолированной
   сети стенда падает. Для стенда полезен шаг «положить проверенную
   версию самому» с проверкой версии — сейчас это делает только ТЗ
   вручную.
4. **Остановка машины**: `systemd-nspawn` stop может затянуться, и
   запись `machinectl` остаётся, пока в PID-пространстве есть процессы
   (в нашем случае — отладочный наблюдатель). Сам тест такого не
   создаёт, но destroy() не переживает посторонние процессы в
   пространстве имён; после их снятия всё закрывается.
5. Сборка релиза на этой машине воспроизводима: nfqws2 собран из
   поставляемых исходников, хэш архива сверен; для повторного прогона
   достаточно тех же пяти dev-пакетов и Xray 26.10.21.
