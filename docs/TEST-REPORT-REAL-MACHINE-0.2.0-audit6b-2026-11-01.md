## Наблюдения
1. **Ответ на главный вопрос ТЗ:** видимые поля единственной группы «близнецов»
   (vless/xhttp/tls, 2 записи) не меняются при скачиваниях — во всех трёх сравнениях «новых 0»
   по всем полям (значения повторяются из набора из 1–2), сама группа стабильна («исчезло 0»).
   Ротация «пропало 21, появилось 21» при этом идёт по **вариантным отпечаткам вне видимой
   группы**: эти записи не образуют группу из двух и более записей в момент снимка, поэтому
   helper не показывает их поля. Предположение: у ротируемых записей меняется поле, которое у
   каждого сервера одно (например, Host или ключ REALITY) и не попадает в группировку снимка,
   либо это записи-варианты, приходящие по одному к своим базам.
2. **Стоимость ротации за окно:** 34 скана за 30 минут — все запасные; замеров скорости 0, хотя
   панель показывала очередь «Замер скорости 0 из 20» — каждое обновление приносит ~21 «новый»
   запасной, и очередь замеров перезапускается с новыми серверами (предположение: замеры
   предыдущей партии при этом теряются). Итоговая строка шлюза: «Трафик проверок: ~892 МБ/сут
   (пробы 830, сканы 56; лимит 1024)» — основная статья трафика проверок не сканы, а пробы.
3. **Время обновления подписки** (новая строка журнала): после установки — «опрос 2 с, сборка
   39 с, применение 8 с»; оба обновления кнопкой — «опрос 67 с, сборка 21–22 с, применение 8–9 с».
   Опрос источников — основная часть шага; долгий шаг демона «99 с (…дольше всего — подписка и
   сборка конфига 98 с)» сходится с этими числами.
4. История отпечатков растёт ровно на ~21 вариантную запись за каждое скачивание
   (вариантов 176 → 218 → 239 → 260), базовых 112 стабильно — числа совпадают с ротацией;
   отдельной записи в историю добавляют и «повторные» значения (предположение: ключ варианта
   меняется хотя бы в одном поле при каждом скачивании, даже если видимые поля группы — нет).
5. Группа «близнецов» в этой проверке — 2 записи, а по числам отчёта audit6 было ~23 варианта
   одной точки входа: состав группы зависит от момента снимка (предположение: источник отдаёт
   вариантные записи не все сразу). Число групп при каждом снимке — 1, «исчезло 0».
6. Шаг 2.3: строка времени обновления не попала в первый вывод помощника — помощник прочитал
   журнал за 15 с до конца шага демона (файл log-install.txt — 14:45:30, строка шага —
   14:45:45). При повторе тем же блоком строка на месте; в «Если не так» этот случай описан как
   дефект, но по сути это гонка чтения, не отсутствие строки — записано «не по ожиданию» с
   объяснением.
