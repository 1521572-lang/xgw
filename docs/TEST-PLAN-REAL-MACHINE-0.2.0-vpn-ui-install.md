# ThinkCentre: установить новый GUI в рабочее приложение XGW

Дата: 2026-11-15. Ветка `freepool`, версия 0.2.0; выпуск дистрибутива не требуется.
GUI CODE = `7c20f59023ec39e5c5ce4606767ea915c3b91f64`.
Основание — [отчёт overview](TEST-REPORT-REAL-MACHINE-0.2.0-vpn-ui-overview-2026-11-15.md),
коммит `e84ff8943fe3b28c2d86a22da1c10bac8ceaaf8c`: приёмка главного окна прошла.
**Результат задания — новое окно остаётся установленным и запускается обычными средствами XGW.**
Запуск только из checkout с последующим удалением не закрывает это задание.

## 1. Полномочия и границы

Исполнитель сам читает файлы, выполняет команды, устанавливает GUI, работает Vision и
публикует отчёт. При отсутствии терминала/root/GUI/GitHub запросить доступ, затем продолжить
самому; не поручать владельцу запуск скриптов. Владелец вводит секрет в системном диалоге.
Использовать один имеющийся root-канал. GUI запускается обычным пользователем desktop-сессии.
Установка и переключение штатного запуска GUI прямо поручены владельцем этим заданием.

Разрешено: новый каталог GUI и резервной копии; одна вставка в установленный `gui/app.py`;
закрытие/открытие окон; контрольный откат этого файла и повторное включение нового GUI.
Не запускать `xgw install`, packaging/install.sh, apply, daemon-reload или restart служб.
Не заменять пакет `/opt/xgw/lib/xgw` на freepool и не менять конфиги/маршруты/подписки/ядра.
Не переключать VPN/zapret2/pin и не запускать нагрузочные сетевые пробы ради установки окна.
Сохранить исправления nft/nfqws2 установленного gui-light backend. Трей не перезапускать.

Отчёт выявил два ограничения backend: нет `zapret2` и `endpoint_country` в API.
После установки ожидаются честные «Нет данных» у zapret2 и карта без активной GeoIP-точки.
Это не повод вернуть страны из имён или выдумать успешное видео. Исправление API — отдельный
следующий блок, не скрытая переустановка backend в этом задании. Остальные функции проверить.

## 2. Получение закреплённого GUI и снимок машины

В существующем Git-клоне XGW от обычного пользователя:

```bash
set -euo pipefail
umask 077
REPO=$(git rev-parse --show-toplevel)
git -C "$REPO" fetch origin refs/heads/freepool:refs/remotes/origin/freepool
PLAN=$(git -C "$REPO" rev-parse origin/freepool)
CODE=7c20f59023ec39e5c5ce4606767ea915c3b91f64
git -C "$REPO" merge-base --is-ancestor "$CODE" "$PLAN"
D=$(mktemp -d "$HOME/xgw-gui-install.XXXXXXXX")
git -C "$REPO" worktree add --detach "$D/source" "$PLAN"
HELPER="$D/source/docs/helpers/install_proton_gui.py"
printf '%s  %s\n' f08c094b7bbe900fbefdc2a313882d3857b43bc3b0fd746beff8f4ec250a8739 "$HELPER" | sha256sum -c -
printf '%s\n' "$CODE" "$PLAN" >"$D/revisions.txt"
PY=/usr/bin/python3
"$PY" -I -c 'from PyQt6 import QtWidgets, QtSvg; print("Qt OK")'
```

Проверить actual `/usr/local/bin/xgw`, его shebang и sys.path, ExecStart служб и desktop Exec.
Ниже LIB=/opt/xgw/lib и PY=/usr/bin/python3 — штатные значения; если отличаются, использовать
фактические после чтения launcher, не исполнять текст launcher как shell. Проверить импорты
Qt именно интерпретатором launcher: dispatcher использует его `sys.executable`.
PyQt6/QtSvg уже проходили приёмку. Если отсутствуют — сначала найти правильный Python;
при реальном отсутствии разрешено поставить только необходимые Ubuntu-пакеты
`python3-pyqt6`, `python3-pyqt6.qtsvg`, без общего обновления системы.

```bash
LIB=/opt/xgw/lib
APP=$("$PY" -I -c 'import sys; sys.path.insert(0,sys.argv[1]); import xgw.gui.app as a; print(a.__file__)' "$LIB")
APP=$(readlink -f "$APP")
APP_SHA=$(sha256sum "$APP" | cut -d ' ' -f1)
printf '%s\n' "$APP" "$APP_SHA" >"$D/installed-entry.txt"
```

В root-канале сохранить приватно SHA всех файлов установленного пакета, launcher/desktop,
состояние/config SHA, режимы/pin, версии и PID daemon/Xray/sing-box, текущую доступность панели.
Проверить, нет ли параллельной установки XGW; не мешать ей. Сырые конфиги/cookie не печатать.
Файлы резервирования не заменяют снимок: helper сохраняет только точку запуска GUI.
Существующий GUI закрыть штатно через Vision; трей оставить. Новый GUI имеет отдельный socket
`…-proton`, поэтому открытое старое окно само не исчезнет. Записать способ запуска старого окна.

## 3. Stage: постоянный каталог, пока без переключения

Помощник [install_proton_gui.py](helpers/install_proton_gui.py) экспортирует **из Git CODE**
`vpn_ui/` с assets/NOTICE и `src/xgw/` в `/opt/xgw/gui/releases/<CODE>/`, root-owned 0755/0644.
Снимок src нужен для совместимых импортов клиента и страниц, включая gui/zapret2; он не
подключается к системному daemon/CLI. Не смешивать несколько GUI-модулей с чужой версией пакета.
Код GUI не будет зависеть от пользовательского checkout или каталога временного прогона.

Следующие команды выполняет исполнитель с имеющимся root-доступом; `sudo -n` — пример
для такого канала, не требование завести второй. Перенести абсолютные HELPER/APP/D в канал.

```bash
sudo -n "$PY" -I "$HELPER" stage --source "$D/source" --app "$APP" --expected "$APP_SHA"
BACKUP=/var/lib/xgw/gui-install/$CODE
sudo -n install -o root -g root -m 600 "$HELPER" "$BACKUP/install_proton_gui.py"
HELPER="$BACKUP/install_proton_gui.py"
sudo -n "$PY" -I "$HELPER" status
```

Ожидается STAGED, затем ORIGINAL. Проверяются Git-пути, отсутствие symlink/чужой записи,
SHA каждого установленного GUI-файла и исходный app.py. Бэкап:
`/var/lib/xgw/gui-install/<CODE>/`: original.py, patched.py, record.json, manifest.json.
Не удалять/перезаписывать существующий бэкап. При повторе сначала status; ORIGINAL означает,
что можно продолжить контроль GUI, ACTIVE — что сначала нужно проверить текущую установку.
CHANGED_EXTERNALLY/STOP требует чтения причины; не переписывать файл поверх чужого обновления.
При незавершённом stage временный `.stage-*` оставить до разбора; рабочий app.py ещё исходный.

Из обычной графической сессии запустить установленный кандидат, не checkout:

```bash
RELEASE=/opt/xgw/gui/releases/$CODE
"$PY" -I "$RELEASE/vpn_ui/main_xgw.py" --theme light --native-titlebar
```

Если shell NoNewPrivileges мешает polkit — запускать через пользовательский systemd с реальным
DISPLAY/XAUTHORITY/DBUS окружением, как в последнем отчёте, не ослаблять system services.
Видимое окно, ресурсы карты/иконок, подписки, карточки, настройки и инструменты должны открыться.
Для импортов запустить отдельный `python -I -c` с sys.path=[RELEASE/src, RELEASE, …]:
`xgw.__file__`, `xgw.gui.model.__file__`, `vpn_ui.xgw.window.__file__` принадлежат RELEASE.
А `/usr/local/bin/xgw --help` и установленный backend по-прежнему используют старый LIB.
Не вносить изменения через страницы. Закрыть кандидата после проверки.

## 4. Переключение обычного запуска и приёмка

```bash
sudo -n "$PY" -I "$HELPER" activate
sudo -n "$PY" -I "$HELPER" status
```

Ожидается ACTIVE. Помощник атомарно добавляет exec после запрета запуска от root в main()
установленного gui/app.py. `sys.executable -I` запускает неизменённый main_xgw из RELEASE
со светлой темой/системной рамкой. Остальное тело app.py, launcher, CLI/службы не меняются.
Старые sys.modules не переносятся в новый процесс. Не копировать patched app.py в RELEASE.

| ID | Что исполнитель проверяет сам |
|---|---|
| CLI | `xgw gui` от обычного пользователя открывает новый GUI; stdout/stderr без исключений. Для независимого от терминала запуска использовать ярлык/трей или пользовательский systemd, не закрывать терминал с foreground-процессом как тест установки |
| DESKTOP | Существующий ярлык XGW в меню и закреплённый рабочий ярлык открывают именно новое окно, не браузер и не старый GUI |
| TRAY | «Открыть XGW» в уже работающем трее открывает/поднимает новый GUI; отдельное действие «В браузере» сохраняет браузерную панель |
| SINGLE | Повторить CLI/ярлык/трей при открытом GUI: одно окно и один GUI-процесс, выбранная подписка/тема не сбрасываются |
| AUTH | Сохранённый сеанс работает. Отдельный XGW_GUI_SESSION в D: отмена polkit, затем успешный вход без замены основного gui.json; запуск по одной копии |
| VIEW | Реальные подписки/серверы/карточка соединения/трафик, темы, hover/Enter/Escape, 1024×720 и компактное окно; нет исключений в журнале |
| COMPAT | Записать отсутствие zapret2/endpoint_country, если API их всё ещё не предоставляет; не называть эти функции полностью установленными |
| NETWORK | Службы/установленные бинарники/конфиги и сетевой режим не менялись из-за установки GUI; панель доступна |

Путь desktop по исходникам: `xgw tray --window` → `xgw gui` → dispatcher. Если пользовательский
ярлык вызывает другой путь, прочитать его и резервировать; разрешено исправить только Exec
этого ярлыка на штатный launcher + gui, сохранив остальные поля/права. Проверить группировку
окна/значка в KDE. Не редактировать меню/иконки всего desktop или добавлять второй ярлык XGW.
Root-GUI не запускать для проверки: отказ root проверен в helper и сохраняется.
Для AUTH использовать XGW_GUI_SESSION только в отдельном тестовом запуске, не в постоянном ярлыке.
Команда panel --gui-login должна вызываться установленным launcher через обычный polkit.

## 5. Проверенный откат и окончательное состояние

Один раз закрыть новый GUI; `sudo -n "$PY" -I "$HELPER" rollback`, затем status=ORIGINAL.
Открыть `xgw gui` — прежнее окно; закрыть. Проверить точный SHA/права/владельца app.py.
При изменённом пользовательском ярлыке также испытать возврат его исходного Exec.
Затем activate и снова открыть через штатный ярлык: **успешный финал — новый GUI установлен**.
Если обязательные CLI/DESKTOP/TRAY/AUTH/VIEW не проходят, сначала исправить запуск/доступ;
при неустранённой ошибке rollback и исходный ярлык, статус INSTALL=FAIL, рабочий backend оставить.
Helper не удаляет release/бэкап и не трогает сеть. После успеха оставить их для будущего отката;
проверенный helper уже сохранён root-owned0600 рядом с record.json, записать SHA в журнал.
Обычное последующее обновление XGW может заменить dispatcher: это ограничение текущей
локальной интеграции, записать его, не обещать поддержку ещё не реализованного installer.

Закрыть тестовые экземпляры; открыть одно новое окно для владельца. Рабочий GUI — от пользователя.
Сверить пакетный manifest: допускается только вставка в установленный gui/app.py и свои новые
каталоги, при необходимости отдельно записанный ярлык. PID может смениться штатно: прочитать
причину, а не маскировать неожиданный restart. Не откатывать чужие/автоматические изменения.
Проверить повторное открытие после удаления временного worktree из путей запуска; сам D с
приватными свидетельствами можно оставить. Закрытие GUI не должно выключать шлюз.
