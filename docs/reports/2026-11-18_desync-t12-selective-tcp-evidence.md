## Наблюдения для Codex

1. **Точка отказа раньше TLS**: сокет B застревает в SYN-SENT — SYN-пакеты уходят
   через очередь (счётчик растёт, дропов нет), SYN-ACK не возвращается на сокет.
   Это не «TLS-handshake медленный»: рукопожатие TCP не начинается. При этом
   page-сокет (A, соседний Google-IP) в ту же секунду проходит ESTAB+данные через
   тот же probe-путь. Различие целей — IP/диапазон CDN и, возможно, маршрут
   ответа.
2. **Маршрут контроля не доказан**: host-curl с --resolve на B прошёл за 0.23 c,
   но host-трафик по умолчанию идёт через штатный VPN; сопоставление с probe-путём
   (метка XGW, direct) недоказано. Для следующего шага — контроль с явным
   маршрутом (например, подтверждённый direct через ip rule/mark или трассировка
   до B), иначе сравнение путей остаётся гипотезой.
3. SYN-ретрансляции доходят до 6–7 (бэкэкспонента ~1с→2с→4с…) — повторная отправка
   SYNs с меткой продолжается до истечения бюджета; поведение ядра штатное, потери
   на ответной стороне.
4. Сборщик с `--socket-stats` (ss fwmark+443, cookie, tcp_info) дал однозначную
   привязку «таймаут ↔ сокет» без захвата пакетов; совпадение endpoint между
   попытками (B) при разных подписанных URL — стабильная цель для следующего опыта.
