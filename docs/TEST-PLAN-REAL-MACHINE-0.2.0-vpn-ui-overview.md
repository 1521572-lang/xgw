## 1. Цель и исходные отчёты

Проверить главный экран с реальными подписками, метриками и состоянием шлюза:
понятные плитки соединения, статус zapret2, обе темы, компактное окно и прежние функции.
Основание GUI — [отчёт combo](TEST-REPORT-REAL-MACHINE-0.2.0-vpn-ui-combo-2026-11-13.md):
шевроны прошли проверку, но `--theme light` расходился с полем темы в настройках.

Учтён [новый Flowseal-отчёт 48f7eba](https://github.com/1521572-lang/xgw/blob/48f7ebae15096c40aaa4b82b7f3b19488ab24dd3/docs/TEST-REPORT-REAL-MACHINE-0.2.0-flowseal-youtube-2026-11-15.md):
короткое 1080p наблюдалось у G12/A1/A2; длительные пробы и NFQ_VIDEO не выполнены.
Этот GUI-прогон не повторяет сетевую матрицу и не объявляет YouTube рабочим по `active`.
Не переносить весь пакет freepool поверх установленного backend из gui-light ради окна.
Исходный код демона, nfqws2 и исправление capture остаются установленными.

## 2. Самостоятельный запуск

Модель сама читает файлы/отчёты, выполняет команды, управляет окном, смотрит его через Vision,
сопоставляет с данными панели и публикует отчёт. Если нет терминала, графической сессии,
доступа для входа или GitHub — запросить доступ, после получения продолжить самой.
Не просить владельца запускать команды или снимать экран вместо исполнителя.
Владелец вводит пароль в polkit при необходимости; окно не запускать от root.
Сохранить текущее состояние режимов и ручного выбора, версии и PID служб приватно.

В существующем клоне, от пользователя графической сессии:


Если Python с pytest/Qt иной — использовать имеющееся окружение, не переустанавливать систему.
Нет pytest — отметить это отдельно, выполнить compileall только изменённых модулей и
продолжить живой просмотр. При исключении сначала выяснить путь импорта и исправить запуск.
При shell с NoNewPrivileges запускать GUI через существующий пользовательский systemd,
как в отчёте combo. Не отключать ограничения у демона и не создавать второй root-канал.
Закрыть старый экземпляр нового окна штатно, иначе SingleInstance поднимет его вместо нового.

## 3. Проверки с реальным API

1. **THEME_START.** Сразу после `--theme light` открыть настройки: выбрана «Светлая»,
   окно светлое. Переключить в тёмную и обратно, повторить через меню заголовка.
   Новый запуск с `--theme dark` сразу показывает «Тёмная». Никаких POST к шлюзу от темы.
2. **OVERVIEW.** Внизу сервер/источник, четыре плитки: последний замер, RTT, ядро, при отказе.
   Сопоставить с `/api/state` через существующий авторизованный клиент: `main/pin`,
   строка `servers`, `speed_mbps/rtt_ms/core`, `capture.fail_mode`. Не публиковать cookie
   и полный state. Проба скорости обозначена как последняя, а не мгновенная скорость видео.
   Если единого активного сервера нет — честный автовыбор без выдуманного узла/метрик.
3. **ZAPRET_STATUS.** Справа рядом с кнопкой zapret2 виден статус: off/ожидание/готовность
   либо отсутствие данных. Он соответствует **публичной карточке** API, не наличию процесса
   на глаз. `state=active` не означает «YouTube работает». Tooltip это объясняет.
   Если установленный backend gui-light не передаёт этот контракт — «Нет данных» корректно;
   записать несовместимость, не подменять backend и не запускать лабораторные стратегии.
4. **ACTIONS.** Кнопка zapret2 открывает прежнюю страницу; настройки — подписки, серверы,
   устройства, zapret2, «Ещё». Открыть редакторы и отменить без сохранения.
   «Трафик ›» в нижней карточке открывает реальный расход. Страницы инструментов пока
   сохраняют своё светлое оформление — это не регрессия новой главной страницы.
5. **CATALOG_MAP.** Подписки сверху, их серверы ниже; поиск/фильтр/сортировка работают.
   В строках страна по IP, скорость, рейтинг. Hover и Enter открывают сведения справа;
   Escape закрывает, просмотр не выбирает сервер. На обновлениях сохранились прокрутка
   и выбранная подписка. Карта пульсирует на стране действующего сервера, не просмотренного.
   Автоматическую смену сервера, если случилась, сопоставить с API; не инициировать pin ради GUI.
6. **LAYOUT.** Осмотреть обе темы: 1100×760, 1024×720, 680×650, минимальное окно и развёрнутое.
   Шрифт/масштаб — текущий пользователя и 125% при доступности без смены всей desktop-сессии.
   Плитки в узком режиме идут 2×2, не перекрывают подписи/значения/футер; на широком — в ряд.
   Карта остаётся видимой. В шторке все пункты, тема и «Закрыть» достижимы мышью/Tab.
   Не нужны симуляции backend для проверки этой реальной вёрстки.

## 4. Переходные состояния без воздействия на рабочую сеть

Не отключать VPN, zapret2, панель или daemon ради stale/off-скриншота.
Исполнитель в отдельном процессе на **этой же машине** использует fixture/Client из
`tests/test_vpn_ui_xgw.py`: подаёт копию снимка без секретов в `XgwBridge`, живого ApiClient
в этом процессе нет. Сам открывает видимое окно и смотрит кадры через Vision.
Это проверка представления состояний, не живая проверка маршрута; в отчёте обозначить отдельно.

| Снимок/событие | Ожидаемый вид |
|---|---|
| LINK_OFFLINE после active | «Нет свежих данных», старый сервер/метрики скрыты, zapret2 «Нет связи», команды закрыты |
| capture off/open со старым main | Прямое подключение, старый VPN-сервер не назван действующим, замеры «—» |
| capture blocked / loaded=false | Маршрут не подтверждён, прежние метрики не выглядят текущими |
| standalone pending, without_vpn=false | Нет прежнего VPN-сервера и преждевременного «без VPN» в сведениях |
| without_vpn=true, state active | Прямое подключение без VPN, метрики VPN «—», карта без активной VPN-страны |
| zapret2 off/fallback/blocked/pending/unknown/compared | Выключен / возврат на VPN / ошибка / применяется / не подтверждён / сравнение завершено |
| zapret2 отсутствует | «Нет данных», не «работает» и не выдуманный выключенный бинарник |

При необходимости модель сама пишет небольшой временный сценарий для этих снимков,
используя те же mock Client/Login, без действий сети/служб. Закрыть его по завершении.
Проверьте отсутствие `Client.sent` при теме, просмотре карточек и переходах состояния.
Если нет GUI-доступа, запросить его; offscreen-тест не заменяет Vision-приёмку на машине.

## 5. Завершение и автоматическая публикация

Закрыть GUI и вспомогательный процесс штатно. Сверить исходные режимы/pin/настройки,
работоспособность панели/сети, отсутствие оставшихся окон. PID мог измениться сам по себе:
сопоставить журнал и причину, не считать любой штатный restart ошибкой окна без доказательств.
Этот прогон не устанавливает пакет, не перезапускает службы и не меняет конфиги маршрутизации.

Отчёт `docs/TEST-REPORT-REAL-MACHINE-0.2.0-vpn-ui-overview-ДАТА.md`:
CODE/PLAN, окружение/масштаб, реальные API-поля без секретов, PASS/FAIL/NOT_RUN по ID,
отдельно живой GUI и подставленные состояния, первое расхождение, восстановление.
Снимки с адресами/именами/подписками — приватно. Для публичного снимка использовать
обезличенные данные и явно назвать его демонстрацией.

При любом исходе исполнитель **сам автоматически commit и push отчёта в freepool**,
без запроса нового подтверждения. До staging проверить секреты; не включать чужие файлы.
Обновить origin/freepool, при гонке перенести только свой коммит поверх новой ветки,
без force/reset чужой работы. Сверить remote SHA и файл, сообщить ссылку и коммит.
При недоступной авторизации запросить доступ и сохранить готовый отчёт, не заявлять публикацию.
