# XGW Free Pool: план реализации

Основа — ТЗ «XGW Free Pool» v1.1 (28.10.2026, требования R01–R56, этапы F01–F16, сценарии
FP01–FP55). Ниже — как оно ложится на нынешний код (ветка `freepool` от `tspu2`, а не `d327aa4`,
под который ТЗ написано) и решения заказчика, которые меняют ТЗ.

## Решения заказчика (28.10.2026)

1. Бесплатный режим — **альтернативный режим работы**, переключаемый, «приложение внутри
   приложения». После испытаний — замена подписки примерно на 90 %.
2. **Подписка остаётся несущим каналом управления**: списки серверов на закрытых сайтах
   (VPN Gate, VPNBook, VPNJantit), профили и учётные данные качаются через неё. Трафик
   пользователей в бесплатном режиме идёт только через бесплатные серверы.
3. Делать всё по ТЗ, включая OpenVPN.

## Отступления от ТЗ и почему

| ТЗ | Здесь | Почему |
|---|---|---|
| R02: в free_pool подписки не скачиваются и не используются | Подписка — несущий канал управления (каталоги, профили, учётки), не выход для трафика | Решение 2: каталоги доступны только через VPN |
| R10/R43: каталог — напрямую, туннель — при восстановлении | Каталог — сначала через несущий канал, напрямую — только если источник открыт; холодный старт — сохранённый каталог или импорт | То же |
| R23 шаг 3: прямой TCP к серверу | Прямой TCP — признак «адрес закрыт» (как в tspu2); такой сервер в пул не берётся (через несущий канал его трафик съел бы квоту подписки) | Цель — заменить подписку, а не гнать трафик через неё |
| R05: пустой пул — CLOSED_DEGRADED | То же, плюс предупреждение в панели с кнопкой «Вернуть режим подписок» (сам шлюз не переключает) | Как с белыми списками: решения о стоимости — за заказчиком |
| Базовая ревизия d327aa4 | `tspu2` (main 4aeec24 + первый этап анти-ТСПУ) | Многие предпосылки ТЗ (§2) уже сделаны: независимая проверочная цель, отпечаток nft, точное правило маршрутизации, границы разбора, пределы HTTP |

Остальные требования — как в ТЗ: строгая изоляция OpenVPN (R44–R48), регион по фактическому
выходу (R14–R17), этапы проверки и бюджет (R23–R29), выбор и переключение (R30–R39), без
выдуманных API источников (R03, R07), отказ закрывает выход (R05).

## Архитектура

```
устройства LAN, сама машина, Docker, tailnet
  → перехват XGW (TPROXY/TUN, как сейчас)
  → Xray: балансировщик бесплатного пула (участники и запасные — бесплатные серверы)
      ├─ VLESS/Trojan/Shadowsocks/Reality (VPNJantit, VPNBook Outline) — обычные outbound'ы Xray
      └─ OpenVPN (VPN Gate, VPNBook, VPNJantit) — SOCKS-мост к изолированному работнику:
           netns fp-<gen> ← veth → хост (NAT, ACL: только адрес:порт сервера)
             openvpn (свой пользователь, без прав на сеть хоста) → tun
             SOCKS-сервер в netns → только через tun
  Xray: балансировщик carrier (серверы подписки) ← только inbound carrier-in (127.0.0.1, пароль)
      ← демон: каталоги, профили, учётки (никакой трафик пользователей сюда не маршрутизируется)
```

## Этапы (вехи — проверка на машине заказчика)

| Этап | Что | Веха |
|---|---|---|
| F01 | Ветка, окружение тестов, точки расширения | — |
| F02 | Режим источников, раздел `[free_pool]`, модели Candidate/Variant (id 128 бит), хранилище | М1 |
| F03 | Контракт источников, загрузка через несущий канал, снимки каталогов (атомарно, last-good) | М1 |
| F04 | VPN Gate: CSV (настоящий очищенный образец) | М1 |
| F05 | VPNBook: OpenVPN и Outline (по настоящим страницам) | М1 |
| F06 | VPNJantit: список узлов, импорт выданных учёток и ссылок Reality | М1 |
| F07 | Разбор .ovpn в типизированное описание и новый конфиг (ничего не исполняется) | М1 |
| F08 | Изолированный бэкенд OpenVPN: netns, veth, ACL, работник, SOCKS, отказ закрывает | М2 |
| F09 | Измерения: этапы проверки, страна по выходу, задержка, скорость, бюджет | М2 |
| F10 | Выбор: допуск, регион (EU/US/ASIA), рейтинг | М2 |
| F11 | Один управляющий (демон), эпохи решений | М2 |
| F12 | Поколения работников OpenVPN: подготовка → проверка → переключение → слив | М2 |
| F13 | Восстановление: истёкшие учётки, устаревший каталог, холодный старт | М3 |
| F14 | Панель, `xgw pool …`, diag | М3 |
| F15 | Интеграция, сутки наблюдения | М3 |
| F16 | Миграция и откат, инструкция | М3 |

**Веха М1 — режим наблюдения:** пул собирается и проверяется, панель его показывает, а трафик
ещё идёт через подписку. Домашняя сеть не рискует. Сделано: `free_pool.mode = observe`, карточка
«Бесплатные серверы», `xgw pool`, проверка на машине — `docs/TEST-PLAN-REAL-MACHINE-0.2.0-freepool-m1.md`. **М2** — трафик через бесплатный пул по
переключателю. **М3** — восстановление, интерфейс целиком, сутки наблюдения.

## Что нужно извне

- OpenVPN: на машине заказчика ставит установщик XGW (пакет Ubuntu). Пакет в окружение
  разработки не ставится (решение заказчика 28.10.2026): пространство имён, veth и правила
  проверяются здесь, сам OpenVPN — на машине заказчика по ТЗ.
- Настоящие образцы ответов источников (CSV VPN Gate, страницы VPNBook/VPNJantit) — с согласия
  заказчика, очищенные: без ключей, паролей и адресов в репозитории.
- Учётки VPNJantit (и других источников с ручной выдачей) создаёт заказчик; шлюз их только
  импортирует (`NEEDS_USER_ACTION`, R03).
