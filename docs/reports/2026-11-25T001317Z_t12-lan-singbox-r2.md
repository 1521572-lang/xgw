## §4 Причина отказа [sing-box] — петля захвата туннеля моста

Из сохранённых журналов стенда (kernel-private, реальный порядок):

1. Запрос LAN-клиента: `from 192.168.50.100 accepted tcp:<источник>:443
   [tproxy-in -> proxy-hk]` — назначение сохранено, маршрут выбран на
   участника моста (outbound моста — socks к ядру sing-box).
2. Сразу следом: `from <шлюз> accepted udp:<адрес сервера моста>:51299
   [tproxy-in -> proxy-hk]` — **собственный QUIC-туннель sing-box к
   серверу моста перехвачен прозрачным захватом и завёрнут обратно в
   outbound того же участника** — петля: туннель не устанавливается.
3. Сервер моста видел единичное начальное подключение (первая
   датаграмма), но dial для групп lan/pinned — нули; TLS обеих проб
   не завершился; фоновая проба :8080 прошла штатно (её dial
   зафиксирован) — разделение адресов r2 подтверждено: отказ
   специфичен для трассировочных запросов через мост.
