# ThinkCentre. standalone: исправленная готовность, один переход и видео

CODE `1e80fc10c421533725ce9567b34dbca01aad9f03`. Версия 0.2.0, freepool, GLM-5.3-Flash.
Исправляет отчёт 305d342: API-проверка standalone больше не требует VPN-балансировщика.
Ошибка применения сохраняется в SQLite и запрещает автоматические повторные переключения.
Виртуально выполнены только один настоящий Xray на loopback и три целевых проверки отказа.
Основная приёмка — здесь, на ThinkCentre. Результат требуется по ролику без VPN.

## 1. Исполнитель и подготовка

Исполнитель сам выполняет команды и управляет окнами через Vision. При отсутствии терминала,
root/sudo или графического доступа запрашивает доступ, ждёт ответа и продолжает сам.
Не просить владельца запускать команды. Отчёт публикуется автоматически при любом исходе.
Прочитать отчёт r2. Не повторять прежние 45 минут рестартов. При первом отказе — §6.
Разрешены установка исходников, смена режима, штатный откат, таймер возврата и перезапуск демона.
Не менять чужие службы, WAN/LAN/Tailscale, sysctl, подписки, не скачивать пакеты, не перезагружать ПК.
Git и GUI — от пользователя графической сессии. При root-инструменте самому использовать runuser
для пользовательских действий; административные команды выполнять без sudo в root-канале.
Все файлы с настройками, адресами и журналами остаются приватными. Записать UTC и инструмент.

## 2. Проверки на реальной машине перед переключением

Выполнить §3 актуального `docs/TEST-PLAN-REAL-MACHINE-0.2.0-zapret2-standalone.md`:
его блок с HostIndependent, переменными D/PY этого прогона, а не CODE из старой инструкции.
К списку files добавить test_applier.py. Исходники не подменять, UID 992 в тесты не вписывать.
Все перечисленные тесты и Qt должны пройти. Отсутствие root/nft вернуть на шаг доступа.
Затем обязательная проверка настоящего установленного Xray в отдельном процессе:

```bash
PY=${XGW_TEST_PYTHON:-$(command -v python3)}
(cd "$D/new" && sudo env PYTHONPATH=src \
 XGW_STANDALONE_XRAY=/opt/xgw/xray/xray XRAY_LOCATION_ASSET=/opt/xgw/xray \
 "$PY" -m pytest -o addopts= -q -p no:cacheprovider tests/test_zapret2_xray.py)
```

Этот тест не трогает systemd, nft и рабочие порты: своё ядро, временные файлы, loopback.
Он проверяет реальное применение через Applier, API, метрики, отсутствие auto и отсутствие
повторного рестарта при неизменном конфиге. Нужен PASS, skipped не допускается.
FAIL — не переключать рабочий шлюз, сохранить причину и опубликовать отчёт.

## 3. Установка исходников

Самому закрыть окно XGW. Выполнить только установочный bash-блок §4 прежнего ТЗ с текущим D:

## 4. Независимый возврат при потере управления

Разрешён следующий временный root-скрипт: он лишь запрашивает off штатным managed API
и перезапускает демон. Он не восстанавливает вручную конфиг Xray и не удаляет сетевые таблицы.
Сохранить его в root-only backup; проверить синтаксис. Номер таймера уникален для прогона.

```bash
sudo tee "$D/backup/return-vpn.sh" >/dev/null <<'SH'
#!/bin/bash
set -euo pipefail
/usr/bin/python3 -I - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, "/opt/xgw/lib")
from xgw import managed
managed.set_zapret2(Path("/etc/xgw/panel.json"), {"mode": "off"})
PY
systemctl restart xgw.service
SH
sudo chmod 0700 "$D/backup/return-vpn.sh"
sudo bash -n "$D/backup/return-vpn.sh"
RESCUE="xgw-standalone-rescue-$(date +%s)"
sudo systemd-run --quiet --unit="$RESCUE" --on-active=180s \
 --timer-property=AccuracySec=1s /bin/bash "$D/backup/return-vpn.sh"
sudo systemctl is-active "$RESCUE.timer"
```

Только active разрешает продолжить. В окне выбрать multidisorder, probe_urls оставить пустыми.
Нажать «zapret2 без VPN», самому подтвердить диалог. Максимум 60 с на готовность.
Один переход — одна попытка. Любой apply_failed/откат/потеря связи → §6, не нажимать повторно.
Нужны ready=true, without_vpn_config=true, vpn_bridges=0, queue=true, lease=true:

```bash
sudo python3 -I "$H" snapshot "$D/ready.json"
```

Подтвердить через Vision заголовок «без VPN», отсутствие новых рестартов Xray и работу обычной
страницы. API и метрики должны отвечать. Если готовность подтверждена и управление устойчиво,
остановить именно свой таймер и убедиться, что он уже не активен, служба не запускалась:

```bash
sudo systemctl stop "$RESCUE.timer"
sudo systemctl show "$RESCUE.timer" -p ActiveState
sudo systemctl show "$RESCUE.service" -p ActiveState -p Result -p ExecMainStartTimestamp
```

Если возврат уже начался, дождаться VPN и завершить этот прогон с причиной; с ним не соревноваться.

## 5. Главная приёмка и завершение

Выполнить §5 прежнего ТЗ целиком с нынешними D/H: новый видимый профиль Firefox от обычного
пользователя (snap — каталог ~/snap/firefox/common/), снимки до/после, минимум 60 с ролика,
три позиции плеера, качество, перемотка. Никаких повторных GET/fetch/curl видеосегментов.
PASS VIDEO требует direct_data_confirmed=true, рост uplink/downlink не менее 2 МиБ на приёме,
нулевой VPN-трафик, прежние PID и конфиг. Страница и запущенный процесс не заменяют видео.
Новый after-файл — с новым именем; помощник не перезаписывает существующие файлы.

Перед проверками отказа и кнопок повторно поставить новый таймер по §4. Выполнить §6 прежнего ТЗ:
остановка только nfqws2 → выбранные домены закрыты, обычная страница работает, VPN не включается;
рестарт демона → восстановление; питание off/on; явный возврат к исправному VPN.
При устойчивом результате снять свой таймер; при FAIL действовать по следующему разделу.
Смены PID Xray ожидаемы только при явных переходах VPN/standalone, не во время ролика.
При всех PASS последним защищённым таймером включить standalone, подтвердить готовность,
снять таймер и оставить standalone работающим по поручению владельца.

## 6. Первый отказ: остановка попыток и восстановление

Не ждать повторных циклов. Зафиксировать UTC, состояние и причину приватно.
Если связь есть, самому запустить `sudo /bin/bash "$D/backup/return-vpn.sh"`, затем остановить
свой таймер. При потере связи не посылать повторные команды: таймер запросит off самостоятельно.
После возврата связи проверить режим off и исправный VPN. Если таймер не восстановил связь,
запросить локальный терминал с правами, самому восстановить доступ и записать STOP.
При ошибке применения код должен оставить apply_failed и запретить новые попытки; отметка
переживает рестарт демона. Эта ветвь проверена целевыми тестами §2: на живой машине намеренно
ломать API/ядро запрещено. Любой повторный самопроизвольный рестарт после ошибки — отдельный FAIL.
При недоступной новой версии восстановить пакет из backup после возврата к VPN и перезапустить
демон. Не откатывать файлы ядер вслепую. Указать финальное состояние, исходники и активные таймеры.

## 7. Отчёт и публикация

Исполнитель сам публикует отчёт при PASS/FAIL/STOP/NOT_RUN без нового разрешения:
`docs/TEST-REPORT-REAL-MACHINE-0.2.0-zapret2-standalone-r3-ДАТА.md`.
До одной страницы: CODE, UTC, инструмент/права, тесты, API/метрики настоящего ядра, MODE/VIDEO/
FAILURE/RESTORE/GUI, кадры и позиции, байты в обе стороны, PID, таймер и конечный режим.
Секреты и полные журналы не публиковать. Коммитить только отчёт из свежей freepool, обычный push,
при обновлении ветки переносить коммит без force. Сверить удалённый файл, сообщить хеш и ссылку.
При недоступной публикации сохранить отчёт и причину. Не делать вывод о невозможности zapret2
по ошибке XGW. Не останавливаться после успешных тестов: довести согласованный прогон до результата.
