# ThinkCentre · маршрут конкретного HTTPS-сеанса через Xray

**Ubuntu 24.04 LTS.** Flash сама запускает эти команды и публикует
один обезличенный отчёт на GitHub при любом исходе. При недоступности
терминала, sudo, pytest или GitHub запроси доступ и выполни доступные
фазы. Код и проверки подготовлены Codex.

[Контроль VPN](../reports/2026-11-24T214447Z_t12-vpn-control.md)
подтвердил 70 контрактов и новые HTTP 200 через штатный вход и один
нативный выход Xray. Публичные IPv4 различались. Мост sing-box был
недоступен. Этот проход проверяет маршрут конкретного запроса по
локальному сокету, назначению, входу, времени и экземпляру Xray.

## Запуск на ThinkCentre

Запускай из рабочей копии обычным пользователем. При необходимости
выбери существующий интерпретатор с pytest через `XGW_TEST_PYTHON` и
авторизуйся через `sudo -v`. Сравниваем шлюз до и после. Один запуск
`--live --route` посылает по одному ограниченному HTTPS-запросу на
существующий путь и читает до 512 записей штатного журнала Xray. При
достижении предела результат сопоставления неполон. Прежний `--live`
продолжает работать без чтения журнала.

~~~bash
bash <<'BASH'
set -euo pipefail
umask 077
. /etc/os-release
[[ $ID == ubuntu && $VERSION_ID == 24.04 && $EUID != 0 ]]
BR=integration/zapret2-batch1
CODE=b1944b582e98e90eb59c5954f19163de9cb166f2
REPO=$(git rev-parse --show-toplevel)
PY=/usr/bin/python3
TEST_PY=${XGW_TEST_PYTHON:-$PY}
git -C "$REPO" fetch origin "$BR"
git -C "$REPO" merge-base --is-ancestor "$CODE" FETCH_HEAD
D=$(mktemp -d "$HOME/xgw-t12-vpn-route.XXXXXXXX")
mkdir "$D/tree"
git -C "$REPO" archive "$CODE" src tests docs/helpers vpn_ui pyproject.toml | tar -x -C "$D/tree"
printf 'OS %s\nPINNED %s\nPRIVATE_ARTIFACTS %s\n' "$PRETTY_NAME" "$CODE" "$D"
uname -r
export PYTHONPATH="$D/tree:$D/tree/src:$D/tree/tests"
export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTEST_ADDOPTS=
cd "$D/tree"

snapshot() {
  sudo -n timeout -k 3 60 "$PY" -I -B - snapshot <docs/helpers/audit_host_observe.py &&
    sudo -n sha256sum /etc/xgw/config.toml /etc/xgw/panel.json
}

run_phase() {
  local label=$1 code=0
  shift
  "$@" >"$D/$label.log" 2>&1 || code=$?
  tail -n 16 "$D/$label.log"
  printf '%s_EXIT %s\n' "$label" "$code"
  return "$code"
}

tests() {
  local tag=$1
  shift
  timeout -k 3 150 "$TEST_PY" -B -P -m pytest -o addopts= -p no:cacheprovider \
    --color=no -v -rs --tb=short --basetemp "$D/pytest-$tag" "$@"
}

vpn() {
  sudo -n timeout -k 3 55 /usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin \
    "PYTHONPATH=$D/tree/src" "$PY" -B -P -m xgw.desync.vpn_control "$@"
}

before=0
snapshot >"$D/state.before" 2>"$D/snapshot.before.err" || before=$?
run_phase CONTRACTS tests contracts --portable tests/test_desync_vpn_control.py \
  tests/test_desync_route_evidence.py tests/test_standalone_cdn_compare.py \
  tests/test_selective_probe_watch.py || true
run_phase LOOPBACK tests loopback tests/test_checks.py -k https_connect_reports_source || true
if run_phase PREVIEW vpn; then
  run_phase LIVE vpn --live --route || true
else
  printf 'LIVE_NOT_RUN_PREVIEW_UNAVAILABLE\n'
fi
after=0
snapshot >"$D/state.after" 2>"$D/snapshot.after.err" || after=$?
if [[ $before == 0 && $after == 0 ]]; then
  if cmp -s "$D/state.before" "$D/state.after"; then
    printf 'T12_GATEWAY_UNCHANGED\n'
  else
    printf 'T12_GATEWAY_SNAPSHOT_DIFF\n'
  fi
else
  printf 'T12_GATEWAY_SNAPSHOT_NOT_AVAILABLE %s %s\n' "$before" "$after"
fi
BASH
~~~

## Что фиксировать

- **CONTRACTS и LOOPBACK** — числа прошедших, упавших и пропущенных
  проверок и длительность. Loopback проверяет запись локального сокета
  после принятого CONNECT и её отсутствие после отклонённого CONNECT.
  Контракты проверяют обе формы журнала и отбрасывают записи другого
  процесса, входа, сокета, назначения и времени.
- **PREVIEW и LIVE** — доступные пути, HTTP-результат и `accepted_route`
  отдельно для каждого из них. `observed` означает единственную запись
  о выборе выхода Xray. Для служебного входа дополнительно укажи
  `matches_pinned_outbound`. Явные категории `direct` и `blocked`
  соответствуют штатным тегам XGW. Категорию `other` укажи как иной
  выход. При отсутствии уже настроенного моста отметь sing-box как
  `unavailable` и продолжи доступные проверки.
- **Открытый результат** — если журнала нет или запись не сопоставилась,
  запиши точную метку из `accepted_route`. Успешный HTTP, такой же IP
  и прирост счётчиков сами по себе не подтверждают маршрут. Для этого
  прохода достаточно одного запуска. Установку, смену сервера,
  включение логов и захват трафика оставь за пределами задания.
- **Шлюз** — итог сравнения снимков и хэшей. Свяжи вывод только с
  проверенным HTTPS-сеансом. Проверка воспроизведения и маршрута LAN,
  естественное истечение CDN и суточное наблюдение идут отдельно.

## Автоматическая публикация

Сырые журналы, настройки, адреса, теги, идентификаторы процессов и пути
оставь на машине. В отчёт включи версии, SHA, итоги фаз и агрегаты.
Подставь абсолютный путь к готовому Markdown в `REPORT_SRC`. Выполни
блок из рабочей копии и верни ссылку на коммит.

~~~bash
bash -s -- "$REPORT_SRC" <<'BASH'
set -euo pipefail
umask 077
REPORT_SRC=$1
BR=integration/zapret2-batch1
[[ $REPORT_SRC == /* && -s $REPORT_SRC ]]
REPO=$(git rev-parse --show-toplevel)
PUB=$(mktemp -d "$HOME/xgw-t12-vpn-route-report.XXXXXXXX")
git -C "$REPO" fetch origin "$BR"
git -C "$REPO" worktree add --detach "$PUB/repo" FETCH_HEAD
trap 'git -C "$REPO" worktree remove "$PUB/repo" && rmdir -- "$PUB"' EXIT
cd "$PUB/repo"
REPORT="docs/reports/$(date -u +%Y-%m-%dT%H%M%SZ)_t12-vpn-route.md"
test ! -e "$REPORT"
install -m 0644 -- "$REPORT_SRC" "$REPORT"
git add -- "$REPORT"
git diff --cached --check
git commit -m 'Report ThinkCentre exact fresh VPN HTTPS route'
if ! git push origin "HEAD:refs/heads/$BR"; then
  git fetch origin "$BR"
  git rebase FETCH_HEAD
  git push origin "HEAD:refs/heads/$BR"
fi
git fetch origin "$BR"
git merge-base --is-ancestor HEAD FETCH_HEAD
printf 'PUBLISHED %s %s\n' "$(git rev-parse HEAD)" "$REPORT"
BASH
~~~
