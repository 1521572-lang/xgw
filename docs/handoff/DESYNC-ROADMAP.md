# XGW: единый план T01–T12 и проверяемые гипотезы

Обновлено 2026-11-17. В исходный план включены гипотезы zapret2 и согласованная
интеграция Web UI Zapret-Manager в T11. Это продолжение исходного плана.
Разработка — Windows 11, переносимые тесты без Linux/сети; стенд — **Ubuntu 24.04 LTS**.
Исполнитель на стенде сам использует терминал, sudo, браузер и vision. Канал передачи —
эта ветка GitHub, NEXT_STEP и docs/reports; задания и отчёты публикуются автоматически.

## Разбор новых предложений

H-номера сохраняются в следующих заданиях и отчётах. Для каждой гипотезы отдельно записывать
реализованность, наблюдение и пользу. Возможность API не доказывает ускорение или обход.

| ID | Предложение / вывод по исходникам | Реализация и опыт, способный опровергнуть гипотезу |
|---|---|---|
| H01 | Закреплённый upstream считает ранние TCP-сигналы с порогом входящей последовательности 4096. Shadow отдельно измеряет остановки плеера после старта | [T07](../reports/2026-11-16_desync-t07-shadow.md) подтвердил 15/30/60 с и отрицательные контроли. Открыты поздний RST, EOF, смена CDN и CDP JSONL |
| H02 | Запись Chrome связывается с точным IP, префиксом и hostname внутри одного сетевого, клиентского и протокольного контекста | [T07/T08](../reports/2026-11-16_desync-t08-cache.md) увидел один IP. Перенос INCONCLUSIVE до появления других адресов |
| H03 | Снимок привязан к ревизии журнала. Два свежих прохода для exact IP дают подсказку, новый FAIL снимает её | Проверки хранения прошли. Переимпорт старых записей не подтвердил воспроизведение по порогу прогресса. Новый флаг diagnostics раскрывает критерий результата |
| H04 | В чистом опыте Lua получила кэшированный TTL 62 при входящем 58, а расчёт 58 → 5 пропустил fake до сервера за два hop | [Результат](../reports/2026-11-16_desync-t06-preflight.md). AutoTTL остаётся лабораторным. Включение на WAN потребует отдельной проверки пользы и разных маршрутов |
| H05 | Общий обработчик static/clone применяет rnd/rndsni и к ClientHello в одном пакете. TCP MD5 и параметры разбиения одинаковы | [Опыт](../reports/2026-11-16_desync-t06-h05.md): fake дошли до сервера, оба варианта воспроизвели YouTube без VPN с 99–100 % 720p и без остановок. | H06 | `status.json` содержит до 64 переходов. Приёмка подтвердила 13 событий, передачу очереди и восстановление после SIGKILL | [Локальный сокет принят](../reports/2026-11-16_desync-t08-event-socket.md): курсор, SO_PEERCRED, лимиты, защита от медленных клиентов и смена эпохи. Pin/reset впереди |
| H07 | Shared memory может помочь при нескольких worker, но текущему одному worker не нужна | T03/T05/T08: сначала однопроцессный baseline и доказанный CPU bottleneck; затем affinity потока, два worker, contention/crash/versioning. Сравнить throughput и ошибки выбора. Fanout без согласованности маршрута/состояния не внедрять |
| H08 | Вызовы nft/conntrack из Lua в обход контроллера нарушат транзакцию | T03/T04/T08: Lua сообщает событие, контроллер ставит ограниченный set с TTL для новых потоков. Тесты отказа VPN, shared CDN IP, смены поколения, восстановление direct. Один TCP-сеанс не мигрировать обещанием «мгновенно» |
| H09 | Добавлены шесть сочетаний split/disorder и none/MD5/seq. Сокращённый вариант проверяется на тех же завершённых окнах | [Пересчёт T09](T09-CDN-REPLAY.md) разделяет совпавшие контексты и формальный отбор на неоднородных записях. Выигрыш в реальном времени пока не измерен |
| H10 | Браузерный curl и длинная передача улучшают метод проверки; 1 MiB может пройти за долю секунды | **Прибор готов**: 45s, ≥1 MiB, без пауз ≥10s после 64 KiB, pinned IP и проверка фактического h1/h2/h3. Обычный curl, совместимый curl-impersonate, настоящий браузер — три разных свидетельства. Эмитируется только shortlist до появления совместимого circular |
| H11 | CRYPTO split/disorder в QUIC потребует корректной расшифровки/re-encryption Initial, offsets, packet numbers, HP/AEAD, min datagram size | Расширение T06/T09 после T05: сначала interop на своём HTTP/3 endpoint, loss/reorder/MTU/IPv6, затем линия. | H12 | obfs требует внешнего узла, ключей и двусторонней настройки; это уже резерв через сервер | Расширение T04/T06: сначала существующий VPN fallback, затем отдельно предоставленный remote endpoint. Тесты отказа/восстановления/ключей/циклов/MTU. Без узла BLOCKED_DEPENDENCY. «95% напрямую» — число без измерений, исключено из требований |

## Правила вывода

- `PASS_IMPLEMENTATION` означает проверенную реализацию, не доказанный выигрыш на ТСПУ.
- `SUPPORTED_ON_THIS_LINK` — повторяемый полезный эффект в обозначенных условиях;
  `NO_BENEFIT_OBSERVED` — корректный опыт без улучшения; `REGRESSION` — ухудшение.
- `INCONCLUSIVE` — смена условий/мало данных/некорректный контроль;
  `NOT_IMPLEMENTED` / `NOT_RUN` / `BLOCKED_DEPENDENCY` не смешивать с сетевым FAIL.
- Не объяснять отказ «адаптацией ТСПУ», если не исключены URL, маршрут, CDN, клиент и worker.
  Отсутствие эффекта не опровергает все варианты идеи; отсутствие реализации не проверка идеи.
- Процент ускорения считать из сырых парных измерений. Полные конфиги, URL с подписью,
  токены, адреса подписок и pcap остаются приватными; в Git только обезличенные метрики.

Опорные источники — локальные `third_party/zapret2/lua/zapret-{lib,antidpi,auto}.lua`,
[закреплённый upstream automate](https://github.com/bol-van/zapret2/blob/038c97e5819df10f8e8c22a2f1fffe57f2f7379b/lua/zapret-auto.lua)
и [curl manual](https://curl.se/docs/manpage.html).
Совместимость установленного клиента и Lua подтверждается на Ubuntu перед сетевым опытом.
