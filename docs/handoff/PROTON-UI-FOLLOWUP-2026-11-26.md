# ThinkCentre · оставшиеся проверки Proton на Ubuntu 24.04

**Flash выполняет проверку в сеансе обычного пользователя. Код — `c9a853474dc535058fc2af0c228b16897db7a782`.** При недоступности терминала или рабочего стола запросить доступ. По сводке прогона `9205314` уже пройдены чистая установка, обновление из `2c98b28`, каталог и активный маркер, запуск из трея, повторное открытие и возврат на встроенный Qt. Оставшиеся пункты — закрытие средствами рабочего стола, смена выхода в согласованное окно и предварительный отказ установки при неполной поставке. [Первое ТЗ](https://github.com/1521572-lang/xgw/blob/5c93e07453db6dd35e73d74455a7fcb2be9c78fc/docs/handoff/PROTON-UI-MANIFEST-2026-11-26.md)

## 1. Получить кандидат и установить клиент

Команды выполнять в одном Bash из клона XGW с GitHub в `origin`. При необходимости запросить установленный pytest для пункта 4. [Git bundle](https://github.com/1521572-lang/xgw/blob/docs/flash-proton-ui-manifest/docs/handoff/artifacts/xgw-proton-p1-followup.bundle)

```bash
set -euo pipefail
. /etc/os-release
test "$ID" = ubuntu
test "$VERSION_ID" = 24.04
test "$(id -u)" != 0
repo=$(git rev-parse --show-toplevel)
pin=c9a853474dc535058fc2af0c228b16897db7a782
umask 077
d=$(mktemp -d)
bundle="$d/xgw-proton-p1-followup.bundle"
git -C "$repo" fetch --no-tags origin refs/heads/docs/flash-proton-ui-manifest
git -C "$repo" show FETCH_HEAD:docs/handoff/artifacts/xgw-proton-p1-followup.bundle > "$bundle"
printf '%s  %s\n' '52a5b4da22f3fc8d922c325c40a4e9097550a2f88738b81d0bd1820f1050f709' "$bundle" | sha256sum --check -
git -C "$repo" bundle verify "$bundle"
git -C "$repo" fetch "$bundle" refs/heads/feat/reproducible-proton-ui-and-manifest
test "$(git -C "$repo" rev-parse FETCH_HEAD)" = "$pin"
mkdir "$d/src" "$d/root" "$d/prefs"
git -C "$repo" archive "$pin" | tar -x -C "$d/src"
export XGW_ROOT="$d/root" XDG_CONFIG_HOME="$d/prefs"
export XGW_GUI_INSTANCE="xgw-proton-followup-$(id -u)-$(basename "$d")"
export XGW_GUI_SESSION="$d/session.json"
if [ -r "$HOME/.config/xgw/gui.json" ]; then
    install -m 600 "$HOME/.config/xgw/gui.json" "$XGW_GUI_SESSION"
fi
cd "$d"
PYTHONPATH="$d/src/src" /usr/bin/python3 -P -c \
    'from xgw.config import Config; from xgw.install import Installer; from xgw.paths import Paths; Installer(Config(), Paths.from_env())._code()'
app="$XGW_ROOT/usr/local/bin/xgw"
```

## 2. Закрытие окна и возврат через трей

Проверить Qt командой `/usr/bin/python3 -I -c 'from PyQt6 import QtWidgets, QtSvg'`. Если импорт не удался, записать версию установленных пакетов и перейти к пункту 4. Иначе запустить `"$app" gui >"$d/custom.log" 2>&1 & custom_pid=$!`.

1. Сверить, что PID относится к тестовому Proton, и записать `XDG_SESSION_TYPE` и версию Qt. На открытом окне со своей рамкой вызвать команду закрытия рабочего стола, например Alt+F4 при активном окне. Зафиксировать, исчезло ли окно и завершился ли процесс в пределах 15 секунд. Для X11, если доступен `xprop`, проверить `WM_PROTOCOLS` именно у верхнеуровневого окна тестового клиента по `_NET_WM_PID`. Для Wayland достаточно результата команды композитора. Если системная команда не сработала, закрыть тестовое окно его кнопкой.
2. Выполнить `"$app" gui --set-default proton-native`, затем `"$app" gui >"$d/native.log" 2>&1 & native_pid=$!`. Проверить системную рамку и ту же сессию. Закрыть окно системной командой. Зафиксировать исчезновение и завершение PID.
3. Запустить `"$app" tray --run >"$d/tray.log" 2>&1 & tray_pid=$!`. Найти именно тестовый SNI по регистрации нового элемента и PID владельца. Открыть его через `Activate` либо через идентифицированный значок. Дважды активировать и проверить Proton с системной рамкой и один PID окна. При открытом окне выполнить `"$app" gui --set-default proton` и снова активировать тестовый значок. Проверить возврат к своей рамке и завершение предыдущего PID. Тестовое окно и тестовый значок закрыть после пунктов 3–4.

## 3. Смена сервера и карты

Проверка требует согласованного короткого окна и исходного автоматического выбора. Если условия не выполнены, оставить этот пункт `NOT_RUN` и записать причину. Остальные пункты выполнить.

1. Записать текущий сервер, его страну из GeoIP, маркер, режим и результат обычного контрольного запроса через VPN. Выбрать доступный сервер обычной подписки в другой известной стране. В диалоге подтвердить «На 10 минут».
2. Дождаться подтверждения нового активного сервера и маршрута от панели. Сверить страну и перемещение маркера. Ограничить ожидание 90 сек. Записать отдельно, наблюдалась ли анимация. Успех команды HTTP и просмотр карточки сервера сами по себе подтверждают только ответ и открытие карточки.
3. Нажать «Автовыбор XGW» сразу после замера либо по истечении 90 сек. Убедиться, что временный выбор снят, режим остался исходным и штатный контрольный запрос через VPN снова проходит. При проблеме возврата завершить испытание и сообщить владельцу состояние шлюза.

## 4. Неполная поставка

Выполнить два регрессионных теста установки на реальной Ubuntu. Они используют временный корень и подставные системные команды.

```bash
(cd "$d/src" && PYTHONPATH=src:. python3 -m pytest -o addopts= -q \
    tests/test_install.py -k incomplete_update_stops_before_any_system_changes)
```

Ожидаются два PASS. При отсутствии Qt-библиотеки, pytest или права доступа описать условие и продолжить доступные пункты. Полный системный install с перезапуском служб относится к отдельной приёмке поставки.

## 5. Отчёт

Записать результат каждого пункта, полный SHA, версию ОС и Qt, тип сеанса, способ закрытия и PID только тестовых процессов. Для трея указать, как отличили тестовый значок. Для смены сервера записать страны, время до подтверждения, состояние маркера и результат возврата. После сохранения результатов удалить временную копию сеанса. При любом исходе опубликовать обезличенный отчёт `docs/reports/<UTC>_proton-ui-followup.md` в ветке `docs/flash-proton-ui-manifest`. Включить имя предыдущего отчёта `2026-11-26T050041Z_proton-ui-manifest.md` и, если доступен обезличенный текст, сохранить его там же отдельным файлом. Скриншоты с адресами, именами подписок или секретами оставить локально.
