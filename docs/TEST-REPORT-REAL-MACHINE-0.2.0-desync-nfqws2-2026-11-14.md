### Диагностика нового падения (выполнена до STOP, без изменений кода и машины)

Требование теста: SIGTERM во время ждущего ответа опроса подписки завершает шаг быстрее 2 с;
опрос прерывается через cancel, вторая подписка не запрашивается, сбоем подписки не считается.
Факт на CODE: шаг длится 10,3 с (BASE — <2 с), при этом `asked` содержит только первую
подписку и stop установлен — то есть цикл останавливается корректно, но **быстро**.

- Воспроизводимость: на TARGET падает в каждом запуске (12,8–12,9 с); на BASE проходит
  (2,2 с).
- nfqws2 не причина: conftest CODE уже добавляет autouse-фикстуру `_no_nfqws2`
  (find_installation → None), а принудительное отключение `nfqws2.enabled` плагином не меняет
  исход.
- Бисект: в дерево BASE подложены daemon.py + nfqws2.py + config.py из CODE (conftest BASE,
  без глушения) — тест падает так же; так что регрессия именно в этих изменениях, а не в
  новой тестовой фикстуре.
- Внутри теста: `cancel.wait(5)` в подменённом fetch возвращает False (5 с ожидания), хотя
  stop уже установлен — cancel, дошедший до fetch, не «видит» stop-событие; плюс ещё ~5,3 с
  лишнего ожидания в цикле после сбоя опроса (место не локализовано: engine.py, fetch.py и
  тайминги config.py между BASE и CODE не менялись; все содержательные изменения daemon.py —
