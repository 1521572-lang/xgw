# C05. Сверить байты сканов на рабочем шлюзе

G1 частично принят владельцем и вошёл в main 0ccedb6. Права процесса в момент запуска
и одновременность мостов остаются открытыми. Для C05 менять поколение вручную не требуется.
На машине по предыдущему отчёту установлен f82fbca. Новый код 59353da добавляет журнал
полезного тела каждой попытки сканера демона и CLI. Повтор на другом адресе — отдельная запись.
Панель и статус показывают скользящие 24 часа. Сумма квоты по множителям — расчётная.
До установки прежние записи последних вердиктов не позволяют восстановить историю расхода.

Критерии этой части C05: совпадение байтов одной пробы CLI со строкой журнала; на одном
срезе статус и независимая выборка SQLite совпадают по сумме, числу попыток и квоте каждой
подписки; есть новая строка origin=daemon; панель и CLI показывают расход. При живом сервере
нужно увидеть ненулевое тело. Контрольный снимок прогноза quota_mb/quota_share/warnings —
отдельно. Интервалы проб, резерв здоровья и допуск новых профилей в этом шаге не меняются.
Весь трафик Xray, сквозных проверок, замеров скорости и TLS этим журналом пока не покрыт.

Разрешены терминал, браузер, зрение, чтение status/diag/logs, приватный SQLite в mode=ro.
Пути, sudo и ожидание адаптировать по месту. При недоступности части серверов продолжать
с рабочим on. WAN, LAN, Tailscale, подписки, пул, pin, настройки не менять. Никаких faults.
Никаких ручных исправлений базы. В отчёте — числа и обезличенные признаки, без имён,
адресов, доменов, полного MAC, конфигов, идентификаторов и скриншотов.

## 1. Подготовить код, предыдущую копию и помощника

```sh
cd ~/xgw
git status --short
git switch freepool
git fetch origin
git merge --ff-only origin/freepool
CODE=59353daad93acc24fc757ea9cc595c51fa8bf5ac
BASE=f82fbca998ca673d947f48d33c1bddfdc7912983
TARGET="$HOME/xgw-c05-$CODE"
PREV="$HOME/xgw-g1-$BASE"
git worktree add --detach "$TARGET" "$CODE"
HELPER="$PWD/docs/helpers/scan_body_acceptance.py"
printf '%s  %s\n' '1a41dfd2d88ca85275705b0693859c3bbcb3d7242d6cc8e8f8fd5f846c0c8532' "$HELPER" | sha256sum -c -
git -C "$TARGET" rev-parse HEAD
git -C "$PREV" rev-parse HEAD
sudo python3 -I "$HELPER" health
```

Ожидаются чистый клон, сумма OK, точные CODE/BASE, {"health": true} и rc0.
Если PREV отсутствует, создать git worktree add --detach "$PREV" "$BASE".
Существующие worktree проверить, не удалять. До установки сверить исходную копию:

```sh
match_package() {
  sudo sh -s -- "$1" <<'SH'
set -e
files=$(git -c safe.directory="$1" -C "$1" ls-files src/xgw packaging)
test -n "$files"
for file in $files; do
    case "$file" in src/*) to="/opt/xgw/lib/${file#src/}";; *) to="/opt/xgw/$file";; esac
    cmp -s "$1/$file" "$to"
done
printf '%s\n' 'Пакет совпадает'
SH
}
match_package "$PREV"
```

Если установлена другая версия, нет рабочего on либо сумма/код расходятся, ограничиться
чтением и сообщить владельцу. Приватно записать исходные состояние, пул/pin, checksum
конфига, прогноз квоты и предупреждения. Прогноз может меняться штатно при изменении состава.

## 2. Обычная установка с локальным возвратом

Нужно согласие владельца на обычную установку CODE, одну пробу выбранного сервера и
условный возврат штатным установщиком BASE, если установка или on/HTTPS откажут.
Согласие на слияние G1 относится к Git. При отсутствии согласия — INSTALL_NOT_RUN.
Установщик повторно применяет конфигурацию и перезапускает службы. Обе версии поддерживают
поколения sing-box. Возврат оставляет дополнительные записи учёта в SQLite; старая версия
их не использует. Восстановление всей базы поверх свежей истории не требуется.

Выполнить одной командой в устойчивой локальной сессии ThinkCentre, окно не менее 30 минут.
При потере интернета следующая команда модели для возврата не нужна:

```sh
sudo sh -s -- "$TARGET" "$PREV" "$HELPER" <<'SH'
umask 077
d=/run/xgw-c05-scan
mkdir -m 700 "$d" || exit 3
sh "$1/packaging/install.sh" --yes >"$d/install.log" 2>&1
i=$?; echo "$i" >"$d/install.rc"
python3 -I "$3" health >"$d/health.json" 2>&1
h=$?; echo "$h" >"$d/health.rc"
if [ "$i" -ne 0 ] || [ "$h" -ne 0 ]; then
    sh "$2/packaging/install.sh" --yes >"$d/return.log" 2>&1
    echo "$?" >"$d/return.rc"
    python3 -I "$3" health >"$d/return-health.json" 2>&1
    echo "$?" >"$d/return-health.rc"
fi
printf '%s\n' 'Проверьте сохранённые rc'
SH
sudo cat /run/xgw-c05-scan/install.rc /run/xgw-c05-scan/health.rc
```

Ожидается 0 и 0. После возврата связи проверить терминал и сохранённые rc; дождаться
запущенного shell, установку заново не начинать. При откате снять результат health
и закончить с PARTIAL. Логи установки приватны. При здоровом шлюзе продолжить:

```sh
match_package "$TARGET" && sudo python3 -I "$HELPER" verify
printf 'verify rc=%s\n' "$?"
sudo python3 -I "$HELPER" health
```

Ожидаются «Пакет совпадает», затем cli_matches/window_matches/daemon_seen=true, cli_bytes>0,
verify rc0 и health rc0. При несовпадении пакета остановиться до verify. Помощник выбирает
одного участника, выводит только числа и признаки. После одной CLI-пробы до 180 с читает статус
и БД. Параллельные пробы других CLI делают сравнение неоднозначным. В таком случае — PARTIAL.
При отсутствии штатного скана в окне допускается дольше ждать и сверять только чтением:

```sh
sudo sqlite3 -readonly /var/lib/xgw/state.db 'SELECT origin,COUNT(*),SUM(bytes) FROM scan_bodies WHERE ts>unixepoch()-86400 AND ts<=unixepoch() GROUP BY origin;'
sudo xgw status
```

Если sqlite3 CLI отсутствует, использовать системный Python sqlite3 с URI mode=ro. Сумма
может меняться; для строгого сравнения использовать границы as_of из конкретного снимка.
Отдельно отметить сообщения «Не удалось записать расход скана» в журнале с момента
установки. Пропуски записи, пустое тело либо недоказанное совпадение отражать как PARTIAL.
Не повторять активную пробу ради PASS. Проверить панель зрением: раздел трафика отделяет
прогноз от строки журнала; назвать только значения. При отсутствии лимитированных сканов
пустой словарь зафиксировать как наблюдение; начисление с множителем на машине тогда открыто.
