# ThinkCentre: совпадает ли лёгкий признак «YouTube принимает сервер» с настоящим браузером

Исполнитель — GLM-5.3-Flash. Код шлюза не меняется, ничего не устанавливается, настройки не правятся.
Прошлая проверка показала: через самый быстрый сервер YouTube просит подтвердить, что это не робот, а
режим `best` выбирает сервер только по скорости. Чтобы шлюз мог обходить такие серверы, ему нужен лёгкий
признак без браузера. Кандидат — состояние плеера, записанное в самой странице ролика. Прежде чем
встраивать его в выбор сервера, надо убедиться, что он говорит то же, что настоящий браузер.

Помощник берёт до пяти самых быстрых безлимитных серверов и через каждый делает одно и то же: запрашивает
страницу ролика лёгким запросом и читает из неё состояние плеера, открывает два ролика в Firefox без окна,
повторяет лёгкий запрос и сравнивает. Страница и видео каждый раз идут через один сервер. Браузерную часть
он берёт из помощника прошлой проверки `youtube_watch_check.py` как есть, поэтому сверяются две суммы.

Разрешения владельца даны 10.11 только для этой проверки: запросы к адресам YouTube вне настроек XGW
(страницы роликов лёгким запросом и в браузере) и запуск уже установленного Firefox без окна. Спрашивать
отдельно не нужно. Трафик — только через безлимитные серверы, до 500 МБ, всего до 35 минут.

Что проверяется: совпадает ли признак с тем, что видит браузер, по каждому серверу. Что не проверяется и
не заявляется: качество и плавность видео, режим `best` как таковой, приложения YouTube на телефонах.
Невидимость для ТСПУ не заявляется. Просьбу YouTube подтвердить, что это не робот, помощник не проходит,
а только записывает. На запросе о cookie в браузере он выбирает отказ от необязательных. Лёгкий запрос
cookie не отправляет и ничего не нажимает.

Можно: терминал, `xgw status`, `xgw diag --no-net`. **Машинное зрение на шлюзе по окну не кликает.**
Нельзя: config.toml, подписки, пул, ручной выбор (ни ставить, ни снимать), «Обновить», замеры, WAN, LAN,
Tailscale и сетевые правила; перезапуск демона, `xgw net down`, перезагрузка, `--force`, установка
программ. В отчёт — только числа, признаки и строки помощника: без ссылок на видео, адресов, имён
серверов и подписок, доменов, тегов, SNI, short_id, сумм файлов и снимков экрана.

## 3. Проверка

```bash
sudo python3 -I "$H" run "$D" 2>&1 | tee "$D/run.txt"
```

Идёт до 35 минут, второй раз не запускать, Firefox вручную не открывать. Норма — сначала `OK on`,
`OK https`, `OK user`. Затем по каждому серверу пять строк: `SIGN … video=plain1`, `TRIAL … video=plain1`,
`TRIAL … video=plain2`, `SIGN … video=plain2`, `MATCH …`. В конце `INFO …`, `OK on`, `OK https`,
`RESULT …` и `helper_rc=0`.

Все строки `SIGN`, `TRIAL`, `MATCH`, `INFO` и `RESULT` переписать в отчёт как есть. `S1`, `S2` — номера
серверов в прогоне по убыванию скорости, имён в них нет.

- `RESULT sign_matches` — признак и браузер совпали по всем сравнённым серверам, и среди них есть сервер,
  которому YouTube отказал. Итог DONE.
- `RESULT sign_agrees_no_refusal` — совпали, но браузеру YouTube не отказал ни через один сервер: признаку
  нечего было ловить. Итог DONE.
- `RESULT sign_differs` — хотя бы по одному серверу признак и браузер разошлись. Это результат измерения,
  а не сбой. Итог DONE.
- `NOT_RUN no_browser`, `NOT_RUN few_servers` (серверов меньше двух) или `NOT_RUN few_compared` (сравнить
  удалось меньше двух серверов), `helper_rc=4` — сравнить не удалось. Итог NOT_RUN, не FAIL. Повторять
  не надо.
- `STOP on` / `STOP https` — сразу владельцу, ничего не чинить.
- `STOP` с другим словом, `helper_rc=3` — записать слово, итог PARTIAL.

Что значат поля. В `SIGN`: `verdict` — `accept` (плеер на странице готов играть), `refuse` (YouTube
требует входа), `unknown` (понять нельзя); `code` — ответ сервера, 0 — ответа нет; `where` — куда привёл
запрос: `watch` (страница ролика), `consent` (страница запроса о cookie), `sorry` (страница «необычный
трафик»), `other`, `none`; `status` — состояние плеера из страницы как есть, `-` — не найдено; `reason` —
причина одним словом (`bot`, `sign_in`, `unavailable`, `player_error`) или `-`; `kb` — размер ответа.

В `TRIAL`: `played` — ролик шёл; `bot` — YouTube просит подтвердить, что это не робот; `sign_in` — просит
войти; `unavailable` — ролик недоступен; `player_error` — другая ошибка плеера; `media_err_N` — браузер не
смог декодировать видео; `consent_page` — осталась страница запроса о cookie; `consent_dialog` — окно
запроса поверх плеера, а видео не пошло; `ad` — время кончилось на рекламе; `stuck` — видео есть, но не
идёт; `no_video` — плеера нет; `no_browser` — Firefox не запустился или перестал отвечать.

В `MATCH`: `sign` — признак по двум запросам (разные ответы дают `unknown`); `browser` — `accept` (сыграл
хотя бы один ролик, отказов не было), `refuse` (отказ `bot` или `sign_in`, ни один ролик не сыграл),
`unknown` (остальное); `same` — `yes`, `no` или `-` (сравнить нельзя). Причины не придумывать.
