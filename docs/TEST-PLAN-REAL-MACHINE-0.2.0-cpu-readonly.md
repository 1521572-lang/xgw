# CPU и расход квоты: три минуты только чтения

Выполнить перед приёмкой G1 fix1; затем продолжить её без отдельного задания, если согласие
на установку есть. Можно выполнить самостоятельно, если установка пока не согласована.
Шлюз работает на принятой базе. Здесь нет установки, перезапуска, сетевых проб или смены настроек.
Scout и неудавшуюся загрузку 100 МБ не повторять. Измерительный адрес Cloudflare не использовать.

Нужны: 120–300 с наблюдения, 10 самых загруженных процессов (имена без аргументов), среднее
и максимум за окно, отдельно демон и трей XGW. CPU процесса — в процентах одного ядра,
может превышать 100 %. CPU всей машины — от всех логических CPU; эти две величины не смешивать.
Высокая загрузка — результат измерения, не причина останавливать процессы или шлюз.

Разрешены все инструменты и машинное зрение. Только читать; не закрывать вкладки/процессы,
не менять службы, сеть, пул, pin, настройки или интервалы проб. Повтор чтения и подстройка
пути/sudo разрешены. В отчёте без PID, аргументов, URL, заголовков вкладок, серверных имён,
имён устройств/подписок, адресов и полных MAC. Скриншоты и сырьё остаются приватными.

## 1. Подготовка из Git
```sh
cd ~/xgw
git status --short
git switch freepool
git fetch origin
git merge --ff-only origin/freepool
CODE=f82fbca998ca673d947f48d33c1bddfdc7912983
TARGET="$HOME/xgw-g1-$CODE"
git worktree add --detach "$TARGET" "$CODE"
CPU="$TARGET/docs/helpers/cpu_snapshot.py"
printf '%s  %s\n' '0aae39f94632cba5d252b226195794811243cac4df03045ad602ae9131466785' "$CPU" | sha256sum -c -
```
Если TARGET уже создан шагом 1 ТЗ G1 — проверить его HEAD, не пересоздавать. Ожидается точный
CODE, сумма OK. Клон и источник не сбрасывать/не править. Это единственный CPU-помощник.
Несовпадение суммы — сообщить разработчику; не перепечатывать код с невидимыми символами.

## 2. Один трёхминутный замер
```sh
sudo python3 "$CPU" --seconds 180
```
Ожидается прогресс каждые ~30 с, затем stage=complete, seconds не меньше 120,
top10 до 10 строк, xgw.daemon/xgw.tray, panel, budget и mask_sources с тремя true.
Предел внешнего инструмента дать не меньше 10 минут; сам замер выбирается от 2 до 5 минут.
Помощник читает /proc, MainPID и уже сохранённый status.json, не вызывает сетевых проверок.
Аргументы локально используются только для распознавания xgw run/tray, не сохраняются.
Имена маскируются совместно по inventory.json, status.json и read-only базе nodes.
Если какой-то источник не прочитан — имена будут скрыты, числа сохранятся: сообщить причину,
не ослаблять маскирование. Короткие процессы между срезами могут быть пропущены.

Если инструмент вернул управление раньше — дождаться той же операции. При потере связи
после возврата читать готовый результат, не начинать новый замер ради пересчёта:
```sh
sudo python3 "$CPU" --report
```
Данные находятся в /run/xgw-cpu-readonly/summary.json. Это обезличенный результат.
Если замер прервался — записать фактическое окно; не выдавать частичный срез за три минуты.

## 3. Отдельно панель XGW

Сервер панели — потоки внутри процесса демона, отдельного серверного PID нет.
Его CPU уже включён в daemon; не ставить панели выдуманный ноль и не складывать дважды.
Если панель открыта в браузере, использовать его диспетчер задач/доступное зрение только
для чтения: записать CPU вкладки/приложения XGW несколько раз в течение тех же 2–5 минут.
Публиковать только метку «панель XGW в браузере» и числа, без URL и прочих названий вкладок.
Это отдельные UI-наблюдения, не среднее из /proc. Если выделить нельзя — явно NOT_SEPARABLE;
если панель закрыта — NOT_OPEN. Не менять состояние вкладок ради снижения загрузки.

## 4. Суточная оценка квоты — без изменения проб

В budget помощника сохранены существующие поля продукта с анонимными номерами подписок.
- total_mb около 893 — МБ/сут; all_mb около 1142 — со сквозной проверкой, тоже за сутки.
- quota_mb — МБ квоты за сутки с множителями серверов для конкретной лимитированной подписки.
- quota_share — процент полной квоты подписки за 30 дней, а не доля суточного лимита.
- limit_mb сейчас сравнивается с total_mb без сквозной проверки; all_mb включает её отдельно.
- warnings перенести обезличенно; отсутствие поля не заменять нулём.
Числа могли измениться после Scout: записать текущие. Это расчёт status.json, не журнал
фактических байт. Около 34 ГБ за месяц относится ко всему расчётному трафику, не автоматически
к одной лимитированной подписке. Интервалы/квоты/пул ради снимка не менять.
Если имена скрыты из-за недоступного источника — всё равно сохранить численные результаты.

## 5. Один короткий отчёт
```text
# CPU и квота — ДАТА
- Код CODE; helper SHA; окно ... с, ... срезов; mask_sources inventory/status/database ...
- Вся машина: среднее ... %, максимум ... %, логических CPU ... .
- Top10: № | имя процесса | среднее % одного ядра | пик % одного ядра.
- Демон XGW ... %; трей ... %; число наблюдавшихся процессов ... .
- Сервер панели: входит в демон; отдельно не выделен. Панель в браузере: ... / NOT_OPEN / NOT_SEPARABLE.
- Бюджет за сутки: total_mb ..., all_mb ...; подписка №1 quota_mb ..., quota_share ... % за 30 дней.
- warnings ...; данные расчётные, не фактический журнал. Отклонения/неполнота ...
```
Без сырых cmdline, PID, статуса или скриншотов. Никаких «оптимизаций» по ходу чтения.
Создать docs/TEST-REPORT-REAL-MACHINE-0.2.0-cpu-readonly-ДАТА.md в исходном freepool:
```sh
git add -- docs/TEST-REPORT-REAL-MACHINE-0.2.0-cpu-readonly-ДАТА.md
git diff --cached --name-only
git diff --cached --check
git commit -m "Отчёт чтения CPU и суточной квоты XGW"
git fetch origin
git rebase origin/freepool
git push origin HEAD:freepool
```
В staged только этот новый отчёт. Конфликт — не переписывать код/чужие отчёты, сообщить.
Далее продолжить G1 fix1. C05/C06 сначала используют этот снимок квоты, затем журнал байт
и уменьшение проверок с сохранением обнаружения отказов. DAE/новые транспорты не запускать.
