# ThinkCentre · сопоставимый диапазон CDN через VPN и zapret2

**Ubuntu 24.04 LTS.** Flash сама выполняет команды, техническую
проверку и публикацию. Если недоступны терминал, права чтения,
sudo или GitHub, запроси доступ. При блокере опубликуй достигнутый
результат. Исходный код и сценарии меняет Codex.

Последний пересчёт подтвердил zapret2 на прямом плече и Xray для
VPN-контроля с повтором. В том живом опыте прямой TLS завершился
таймаутом до `ServerHello`, обе VPN-попытки получили `302`.
Изменение способа выбора CDN должно дать сопоставимую пару с полным
контрольным диапазоном. [Пересчёт](../reports/2026-11-24T195604Z_t04-xray-access.md) ·
[Предыдущий опыт](../reports/2026-11-24T172518Z_standalone-cdn-tls.md)

## Один проход

Запусти блок из рабочей копии с доступом к панели XGW. В
интерактивном терминале при необходимости выполни `sudo -v`, затем
`sudo -n true`. Проверь короткое согласованное окно ранее принятого
сценария Standalone. Оно включает временную установку, остановку
VPN в режиме Standalone, возврат управляемого sing-box и откат.
Обычная подготовка VPN выполняется до временной установки.
Если для pytest требуется существующий venv, укажи его
интерпретатор в `XGW_TEST_PYTHON`. Если обычный тестовый ролик
недоступен, задай согласованный идентификатор в `XGW_T09_VIDEO`
до запуска. Его значение остаётся на машине.

~~~bash
bash <<'BASH'
set -euo pipefail
umask 077
. /etc/os-release
[[ $ID == ubuntu && $VERSION_ID == 24.04 && $EUID != 0 ]]
BR=integration/zapret2-batch1
CODE=59b66137a898cd668cc3f80b8bdcd4916249720b
cd "$(git rev-parse --show-toplevel)"
REPO=$PWD
PY=/usr/bin/python3
TEST_PY=${XGW_TEST_PYTHON:-$PY}
git fetch origin "$BR"
git merge-base --is-ancestor "$CODE" FETCH_HEAD
D=$(mktemp -d "$HOME/xgw-cdn-pair-check.XXXXXXXX")
mkdir "$D/tree"
git archive "$CODE" src tests docs/helpers vpn_ui pyproject.toml | tar -x -C "$D/tree"
printf 'OS %s\nPINNED %s\nPRIVATE_ARTIFACTS %s\n' "$PRETTY_NAME" "$CODE" "$D"
curl --version | sed -n '1p'
contract_rc=0
(
  cd "$D/tree"
  export PYTHONPATH="$D/tree:$D/tree/src:$D/tree/tests"
  export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTEST_ADDOPTS=
  timeout -k 3 120 "$TEST_PY" -B -P -m pytest -o addopts= -p no:cacheprovider \
    --color=no -v --tb=short --basetemp "$D/pytest" tests/test_standalone_cdn_compare.py \
    tests/test_desync_route_evidence.py tests/test_selective_admission.py \
    tests/test_selective_probe_watch.py
) >"$D/contracts.out" 2>&1 || contract_rc=$?
tail -n 18 "$D/contracts.out"
printf 'CDN_PAIR_CONTRACTS_EXIT %s\n' "$contract_rc"
[[ $contract_rc == 0 ]]

sudo -n true
git -C "$REPO" show "$CODE:docs/helpers/standalone_return_preflight.sh" |
  bash -s -- "$CODE"
git -C "$REPO" show "$CODE:docs/helpers/standalone_return_live.sh" |
  bash -s -- "$CODE" cdn-pair
BASH
~~~

При блокере установленной копии запиши шаг и результат сверки.
Не исправляй пакет и команды на машине. После установки помощник
сам восстанавливает настройки и файлы. При обрыве терминала
используй готовый [независимый возврат](STANDALONE-MANAGED-LIVE-2026-11-23.md#3-независимый-возврат)
по приватному файлу `restore-location`.

## Что проверить и записать

1. **Контракты и совместимость.** Укажи версии Ubuntu и curl, код
   и счётчики тестов. Отдельно отметь неверный `Content-Range`,
   просроченный и посторонний redirect, второй `302`, чужой IPv4 и
   неоднозначную запись маршрута.
2. **Подготовка VPN.** Укажи `vpn_range_verified` или код блокера из
   `vpn-prepare.out`. При `302` допустима одна проверка свежей
   цели HTTPS `/videoplayback` на CDN YouTube. Запиши статус и
   проверку `Content-Range` для каждого шага. При
   `STANDALONE_LIVE_CDN_PAIR_NOT_STARTED` переключения не ожидается.
   Убедись, что базовый off/off и VPN остались рабочими.
3. **Сопоставимая пара.** Возьми обезличенный `pair-verdict.out`, статусы
   HTTP, число байт и TLS-события из `cdn-comparison.out`, группы из
   `direct-route.out` и `off-route.out`. Для `pair_verified` нужны
   одинаковые URL и фактический IPv4, точный `Content-Range` с
   байтами 0–65535, ответ `206/65536` и совпадение сокета с zapret2
   на прямом плече и VPN на другом. Выбранный CDN проверяется новым
   соединением после возврата VPN. Если получен `302`, сохраняется
   один повтор этой же ссылки на том же IPv4.
4. **Возврат.** При временной установке укажи результат off/off,
   VPN HTTPS, маркер восстановления managed, совпадение файлов и
   настроек, состояние таймера и итоговый код. При несовпадении
   запиши категорию и оставшееся состояние.

Если снова получен таймаут до `ServerHello`, зафиксируй его отдельно
от результатов VPN и закрой этот проход. Успешная пара подтверждает
транспорт и конкретные выходы. Живая замена новой ссылки в Selective
и воспроизведение остаются отдельной фазой плана.

В отчёте оставь только SHA, версии, агрегаты и коды. Подписанный URL,
Location, его хеш, адреса и сырые журналы хранятся локально.
[Поля curl для чтения диапазона и redirect](https://curl.se/docs/manpage.html#-w)

## Автоматическая публикация

Подставь абсолютный путь к обезличенному Markdown-отчёту в
`REPORT_SRC`. Выполни из рабочей копии при любом исходе и верни
ссылку на опубликованный коммит.

~~~bash
bash -s -- "$REPORT_SRC" <<'BASH'
set -euo pipefail
umask 077
REPORT_SRC=$1
BR=integration/zapret2-batch1
[[ $REPORT_SRC == /* && -s $REPORT_SRC ]]
REPO=$(git rev-parse --show-toplevel)
PUB=$(mktemp -d "$HOME/xgw-cdn-pair-report.XXXXXXXX")
git -C "$REPO" fetch origin "$BR"
git -C "$REPO" worktree add --detach "$PUB/repo" FETCH_HEAD
trap 'git -C "$REPO" worktree remove "$PUB/repo" && rmdir -- "$PUB"' EXIT
cd "$PUB/repo"
REPORT="docs/reports/$(date -u +%Y-%m-%dT%H%M%SZ)_t04-cdn-pair.md"
test ! -e "$REPORT"
cp -- "$REPORT_SRC" "$REPORT"
git add -- "$REPORT"
git diff --cached --check
git commit -m 'Report ThinkCentre pinned CDN range pair'
if ! git push origin "HEAD:refs/heads/$BR"; then
  git fetch origin "$BR"
  git rebase FETCH_HEAD
  git push origin "HEAD:refs/heads/$BR"
fi
git fetch origin "$BR"
git merge-base --is-ancestor HEAD FETCH_HEAD
printf 'PUBLISHED %s %s\n' "$(git rev-parse HEAD)" "$REPORT"
BASH
~~~
