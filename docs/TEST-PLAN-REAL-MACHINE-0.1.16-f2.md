**Для исполнителя.** Выполняй шаги строго по порядку. В каждом шаге — команда (копируй
целиком), «Ожидается» и «Если не так». Ничего не придумывай сверх написанного. Не уверен —
остановись и спроси заказчика. Выводы команд сохраняй в файлы, как написано: из них
собирается отчёт (§6).

Машина: ThinkCentre, Ubuntu 24.04.5 LTS, шлюз дома (LAN `enp4s0`). Стоит XGW **0.1.16**.
Клон репозитория — `~/zcod/xgw`. Номер версии не меняется: и после обновления
`xgw --version` пишет `xgw 0.1.16`. Новый код узнаётся по строке «события: есть» (шаги 2.1
и 2.3).

Что нового (ASSUMPTIONS п. 218, фаза Ф2 `VPN_IMPROVEMENT_PLAN.md`):

- Демон больше не ждёт очередного шага (20 с), чтобы заметить, что правила nftables кто-то
  убрал: он слушает `nft monitor`, `ip monitor` и сигнал сна и возвращает правила за доли
  секунды. Раньше `nft flush table ip xgw` вообще не замечался: цепочки оставались пустыми,
  а XGW считал правила на месте.
- В панели под кнопкой — строка «Перехват: работает / подключается / заблокирован / …», в
  `xgw status` — строка «Сейчас: перехват …».
- Опоздавшая под нагрузкой проверка связи не считается провалом, если через сервер идёт
  трафик.
- Службы `xgw-net` (правила) и `xgw-dhcp` (DHCP) работают в песочнице systemd: файловая
  система только для чтения, кроме своих каталогов, и только сетевые права.

Цели:

2. Оценка защиты служб (шаг 3).

4. Чужой `nft flush table ip xgw` — правила возвращаются не дольше чем за 2 с (шаг 5).
5. Перезапуск демона по-прежнему быстрый (шаг 6). Итоговое состояние (шаг 7), отчёт (§9).

## 5. Чужой flush правил

Скрипт шага 5.1 считает строки правил в таблице `ip xgw`, стирает их (`nft flush table ip
xgw` — как это сделала бы чужая программа), каждые 0,1 с проверяет, вернулись ли они, и
показывает журнал демона. Ждёт не дольше 10 с.

Шаг 5.1. Создать скрипт (копируй блок целиком):

```bash
cat > flush.sh <<'EOF'
#!/bin/bash
# flush.sh N — попытка N: стереть правила XGW и замерить, когда демон их вернёт.
n() { sudo nft -a list table ip xgw 2>/dev/null | grep -c 'handle'; }
BEFORE=$(n); echo "попытка $1: строк до: $BEFORE"
SINCE=$(date '+%F %T')
T0=$(date +%s.%N); sudo nft flush table ip xgw; AFTER=$(n)
for i in $(seq 1 100); do [ "$(n)" -ge "$BEFORE" ] && break; sleep 0.1; done
T1=$(date +%s.%N)
echo "сразу после flush: $AFTER; сейчас: $(n)"
echo "попытка $1: правила вернулись через $(python3 -c "print(f'{$T1 - $T0:.2f}')") с"
sleep 3
sudo journalctl -u xgw --since "$SINCE" -o short-precise --no-pager | grep -E 'внеочередная|загружены заново|Traceback' | cut -c1-160
EOF
chmod +x flush.sh; echo "скрипт создан"
```

Ожидается: «скрипт создан».

Шаг 5.2. Попытка 1:

```bash
./flush.sh 1 2>&1 | tee after/flush-1.txt
```

Ожидается:
- «сразу после flush» — число **меньше**, чем «строк до» (правила стёрты), «сейчас» — не
  меньше «строк до»;
- «правила вернулись через» — **не больше 2,00 с**;
- в журнале **одна** строка «внеочередная проверка правил перехвата» и одна «правила сети не
  были загружены — загружены заново»; `Traceback` нет.

Если «вернулись через» больше 2 с или «сейчас» меньше «строк до»: **сразу** выполни

```bash
sudo xgw net up; sudo nft -a list table ip xgw | grep -c handle
```

(правила вернутся), запиши всё в отчёт — это дефект — и перейди к шагу 6. Если строк
«внеочередная…» больше одной: записать в отчёт (наблюдение), продолжать.

## 6. Перезапуск демона

Мониторы событий — три дочерних процесса демона. Остановка не должна из-за них
затягиваться: на 0.1.16 `systemctl restart xgw` занимал меньше 1,5 с.

Шаг 6.1. Создать скрипт:

```bash
cat > restart.sh <<'EOF'
#!/bin/bash
# restart.sh N — попытка N: перезапустить демон, измерить, проверить мониторы.
SINCE=$(date '+%F %T')
T0=$(date +%s.%N); sudo systemctl restart xgw; T1=$(date +%s.%N)
echo "попытка $1: restart занял $(python3 -c "print(f'{$T1 - $T0:.2f}')") с"
sleep 10
echo "мониторов: $(pgrep -f 'nft monitor|ip -o monitor|busctl --system monitor' | wc -l)"
sudo journalctl -u xgw --since "$SINCE" -o short-precise --no-pager | grep -E 'Stopping|Stopped|Started|остановлен|запущен|не отслеживаются|Traceback' | cut -c1-160
EOF
chmod +x restart.sh; echo "скрипт создан"
```

Ожидается: «скрипт создан».

Шаг 6.2. Попытка 1:

```bash
./restart.sh 1 2>&1 | tee after/restart-1.txt
```

Ожидается: «restart занял» — **меньше 1,5 с**; «мониторов: 3» (старые ушли вместе с прежним
демоном, новых — три); в журнале `Stopping`, `Stopped`, `Started`/«демон XGW запущен»; нет
`Traceback` и «не отслеживаются».
Если 1,5 с или больше: записать время и журнал попытки, продолжать. Если мониторов не 3:
выполни `pgrep -a -f 'nft monitor|ip -o monitor|busctl --system monitor'`, запиши вывод
(дефект), продолжать.
