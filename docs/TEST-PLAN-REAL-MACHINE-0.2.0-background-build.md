# Сборка конфига в фоне — проверка на рабочем ThinkCentre

Исполнитель: GLM-5.3-Flash. Только эта машина; отдельного клиента за роутером нет.
Волна 3 закрыта владельцем без трёх правок. Старые cut/isolation/watch/clarify не выполнять.
Цель: рабочий on сохраняется, сборка не задерживает шаг демона, статус обновляется до 25 с.
Проверка loaded, сетевые повреждения, смена серверов/региона/пула и установка целиком не входят.
Здесь один помощник, один запуск, десять минут наблюдения, один отчёт, включая неуспех.
Не менять WAN/LAN/Tailscale, конфиги, подписки, выбор сервера, службы ядер и версию.
Не запускать старые стенды, install, off, reset, rebase, force, ручную починку или диагностику.
Закрыть редакторы настроек; во время прогона никто не меняет настройки или версии ядер.

## 1. Обновить чистый клон

```bash
cd "$HOME/zcod/xgw" && test "$(git branch --show-current)" = freepool && test -z "$(git status --porcelain)" && git fetch --quiet origin freepool && git merge --quiet --ff-only origin/freepool && printf 'Исходники обновлены\n'
```
Ожидается `Исходники обновлены`, код 0. Иначе STOP, без исправления клона наугад.
Только Git FF. Это ещё не обновление установленного XGW.

## 2. Проверить помощник

```bash
printf '%s  %s\n' 'c5fa81fc08bb8b9c4eb402a9347da89043b70b0f221d60b50a026d200b697fd0' "$HOME/zcod/xgw/docs/helpers/background_build.py" | sha256sum --check --status && printf 'Сумма помощника верна\n'
```
Ожидается `Сумма помощника верна`, код 0. Иначе STOP: не править файл и сумму.

## 3. Подготовить независимую копию для возврата, без обновления XGW

```bash
sudo -n python3 -I -B "$HOME/zcod/xgw/docs/helpers/background_build.py" prepare "$HOME/zcod/xgw"
```
Ожидается `Подготовлено. Установленный XGW не изменён`, код 0.
Помощник сверяет старые и новые суммы daemon.py и watch/status.py, права, неизменный unit
xgw.service без drop-in, HEALTHY/on/HTTPS и исходный статус не старше 120 с. Loaded не вызывается.
Приватные старые/новые файлы, unit и помощник сохраняются в /run/xgw-background-build (0700).
Исходники, конфиги, службы и правила на этом шаге не меняются.
Если код 3: STOP; передать точный безопасный этап из сообщения. Prepare не повторять,
каталог не удалять, другую установленную версию не подгонять под ожидаемые суммы.
Ошибка sudo означает необходимость терминала владельца, а не перенастройку sudoers.

## 4. Получить согласие владельца на конкретное обновление

Показать владельцу: «Обновятся только daemon.py и watch/status.py; перезапустится только
xgw.service. Ядра и сетевые службы штатно не перезапускаются. При неуспехе помощник сам
вернёт старый код и снова запустит демон; если on не восстановится, выполнит xgw net up.
Во время проверки один раз нажму “Обновить” подписки. Настройки и ручной выбор сохраняются».
Нужно явное согласие на эти действия. Согласие на разработку не подменяет это согласие.
При отказе: STOP до start, установка и проверка NOT_RUN, сообщить владельцу без нового прогона.
В отчёт не копировать личную переписку. Не убеждать владельца разрешить сетевые повреждения.

## 5. Запустить один раз

```bash
sudo -n python3 -I -B /run/xgw-background-build/helper.py start --owner-approved
```
Ожидается `Прогон запущен. Помощник сам завершит проверку или вернёт прежний код`, код 0.
Он работает отдельным процессом и не зависит от следующей команды модели или связи.
Файлы заменяются каждый атомарно; перезапуск демона — после замены обоих файлов.
Ошибку второй замены тоже обрабатывает возврат обоих файлов. Unit только сохранён, не заменён.
При неуспехе — прежние файлы, перезапуск демона, до 15 с ожидания, затем xgw net up при нужде.
Старые конфиги ядер и настройки не перезаписываются. Успех возврата проверяется отдельно.
Повторный start запрещён даже при обрыве терминала; повторного рабочего потока не будет.
При тайм-ауте инструмента читать report, а не повторять start или запускать _worker/_sample.

## 6. Дождаться наблюдения и один раз обновить подписки

```bash
sudo -n python3 -I -B /run/xgw-background-build/helper.py report --wait
```
Код 2 и `Прогон продолжается: наблюдение` — открыть уже используемую панель XGW, на вкладке
подписок один раз нажать существующую кнопку «Обновить». Ожидается «Обновляю подписки…».
Ничего не добавлять/удалять/переключать. Не искать токены, не открывать конфиги и raw API.
Если всё ещё `запущен`: разрешено ещё одно чтение той же командой; кнопки пока не нажимать.
Если `возврат` или готовый отрицательный отчёт: кнопку не нажимать, перейти к шагу 7.
Если панели нет, кнопка не отвечает или подпись другая: не подбирать API/команды;
отметить действие NOT_RUN и дать помощнику закончить. Это partial, а не успешная проверка кнопки.
Код 3 — STOP, сообщить этап; не запускать исправление сети вручную.

## 7. Дождаться конечного результата чтением, без новых действий

```bash
bash <<'BASH'
for n in $(seq 1 16); do
  sudo -n python3 -I -B /run/xgw-background-build/helper.py report --wait
  rc=$?
  case "$rc" in 0) exit 0;; 2) continue;; *) exit "$rc";; esac
done
printf 'Срок ожидания исчерпан; start не повторять\n'
exit 3
BASH
```
Ожидается короткий отчёт и `Сбор данных: завершён`, код 0. «Не прошло» также завершённый факт.
Код 2 внутри цикла — только продолжающееся наблюдение, не ошибка и не разрешение повторить старт.
Код 3/пропажа прогресса: STOP, без kill/retry/prepare/старых ТЗ. Сообщить владельцу.
Если связь пропадала, после возврата разрешено только report; следующая команда не является rescue.
Помощник проверяет HEALTHY/on/HTTPS, прежние настройки, пул, выбор и процессы ядер;
считает промежутки обновления статуса и строки журнала о шагах от 60 с, без публикации журнала.
Критерии: завершена сборка, шагов от 60 с — 0, промежуток статуса не больше 25 с,
неудачных HTTPS-проб — 0. Медленная сборка сама по себе не означает медленный шаг.
Промежутки измерены опросом с погрешностью его длительности, не непрерывной трассировкой.

## 8. Сохранить и прочитать один отчёт

```bash
cd "$HOME/zcod/xgw" && sudo -n python3 -I -B /run/xgw-background-build/helper.py report > "docs/TEST-REPORT-REAL-MACHINE-0.2.0-background-build-$(date +%F).md"
```
Ожидается код 0. Если не так, не публиковать пустой файл и не сочинять недостающие наблюдения.
Дополнить внизу только: проверенный Git commit; согласие владельца да/нет;
кнопка «Обновить»: выполнено/NOT_RUN и её безопасный результат. Форма рядом.
Прочитать весь файл. Без IP, доменов, имён серверов/устройств/подписок, MAC, конфигов,
токенов, PID, сырых журналов, исключений и снимков экрана. Числа помощника не переписывать.
Успех помощника без нажатия кнопки — partial; отрицательный завершённый отчёт публикуется.
Не выдать наблюдение хоста за проверку LAN/UDP/IPv6/DNS или завершение blue-green.
