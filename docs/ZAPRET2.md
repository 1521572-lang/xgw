# Дополнительный режим zapret2

Первая версия: выбранные HTTPS-домены идут из Xray напрямую через `nfqws2`, остальные —
прежним маршрутом. По умолчанию `[zapret2] mode = "off"`. Это прямой выход с домашним IP,
не VPN. Невидимость для ТСПУ и улучшение видео не заявляются.

## Управление из окна

В нативном окне XGW на «Обзоре» под кнопкой VPN показан статус zapret2. По нажатию открывается
раздел с режимами «Сравнить с VPN», «Включить для доменов» и «Выключить zapret2».
В настройках раздела доступны домены, стратегия и два HTTPS-адреса для проверок страницы и видео.
Изменения сохраняются в приватном `panel.json` и перекрывают соответствующие поля `[zapret2]`
в `config.toml`. Пути к бинарнику и Lua, очередь и лимиты берутся из `config.toml`.
Редактирование доступно после подтверждённого выключения. Сохранённые URL не возвращаются в API,
пустые поля сохраняют их, флажок удаления очищает. Режим включается отдельной кнопкой.
После сохранения окно ждёт подтверждения демона. Старые данные и неудавшийся возврат не
обозначаются как успешная работа. Сравнение не включает клиентский маршрут и выполняется один раз.
Для повторного круга сначала выключить режим. Результаты сравнения видны до выключения.
Файлы панели, демона и окна обновляются вместе по ТЗ gui-zapret2. Браузерный интерфейс пока
не содержит этих кнопок.

## Подготовка

XGW сам не скачивает и не устанавливает zapret2. Нужны уже подготовленные `nfqws2` и Lua-файлы
из одного выпуска официального [bol-van/zapret2](https://github.com/bol-van/zapret2).
Скачивание и установка на шлюзе — только с отдельным согласием владельца. Записать точный
upstream commit/release и контрольные суммы приватно до установки. Запускать `install_easy.sh`,
общую службу `zapret2` и её автоматическую настройку firewall не нужно.

Файлы и родительские каталоги должны принадлежать root и быть закрыты на запись группе/остальным.
Бинарник должен быть исполнимым. Сначала допустимы `--version` и штатная проверка `--intercept=0`:
XGW выполняет последнюю до запуска своего временного unit `xgw-zapret2.service`.
Служба запускается с NET_ADMIN/NET_RAW, закрытой файловой системой и прекращает работу с демоном.

Пример раздела (адреса проб владелец заполняет приватно):

```toml
[zapret2]
mode = "off"                     # selective — включить после подготовки
domains = ["domain:youtube.com", "domain:googlevideo.com",
           "domain:youtubei.googleapis.com", "domain:youtube-nocookie.com"]
binary = "/opt/zapret2/nfqws2"
lua_dir = "/opt/zapret2/lua"
strategy = "multisplit"           # также multidisorder; универсальной стратегии нет
queue_num = 200                   # свободная NFQUEUE; чужая очередь не захватывается
probe_port = 19999                # свободный служебный HTTP-вход на loopback, с паролем
probe_urls = []                   # HTTPS-страница YouTube и HTTPS-файл видеосети
check_seconds = 180
retry_seconds = 300
daily_probe_mb = 256
```

Для YouTube нужны оба проверочных адреса: из youtube.com и googlevideo.com. Они должны отдавать
2xx и хотя бы 16 КиБ без перенаправления, cookie и входа. Истёкшая подписанная ссылка не годится:
её отказ вернёт режим в VPN. Адреса разрешены только внутри `domains`, порт 443. В отчётах их нет.
Пустой список сохраняет VPN; файл скорости Google не подставляется вместо проверки видеосети.

Первая версия требует `network.block_quic = true` и пустого `routing.proxy_domains`.
HTTP/80, UDP/QUIC и IPv6 на прямом выходе не обрабатываются; Xray использует IPv4 и TCP/443.
Перехваченный клиентский IPv6 при этом может попасть в тот же выход Xray как IPv4.
Прямые исключения, правила устройств и режим всего дома через бесплатный пул остаются главнее.
Служебные входы обычных проверок, обновления подписок и VPN-соединения в очередь не попадают.

## Проверка и отказ

Перед первым прямым соединением клиента демон создаёт отдельные обработчики через API Xray,
запускает очередь и проверяет все `probe_urls` через тот же выход. Проверки ограничены 8 секундами
и 64 КиБ тела на адрес, до четырёх адресов. До каждого круга из постоянного суточного бюджета UTC
списывается резерв 256 КиБ на адрес, включая накладные расходы и прерванные запросы.

Не отвечает один адрес, умер процесс/очередь, кончился бюджет или произошла ошибка — разрешение
снимается, правило удаляется через API, новые соединения идут прежним маршрутом VPN.
Повтор — после `retry_seconds` с новой проверкой. Переключение не перезапускает Xray.
Живые соединения не мигрируют между выходами: плееру может понадобиться открыть видео заново.

Состояния видны в `xgw status`, `xgw status --json` (`zapret2`) и `xgw diag`:
`preparing`, `active`, `fallback`, `blocked`. Последнее означает, что вернуть правило через API
не удалось; это не успешный возврат. HTTP-ответы доказывают доступность адресов, не воспроизведение,
отсутствие bot-проверки, качество или плавность видео. `youtube-sign` пока отдельно от этого режима.

Исходная метка — `0x10000000`, добавляемый nfqws2 бит — `0x40000000`, итог — `0x50000000`.
Общий `mark_bypass` по-прежнему сравнивается точно. Свои копии не возвращаются в очередь.
Правила находятся в таблицах XGW; `queue bypass` отсутствует. Разрешение в `xgw_guard` истекает
через `check_seconds + 60` секунд без продления. При остановке обработчика пакеты закрыты до
следующего успешного шага демона, который вернёт маршрут. При зависшем/остановленном демоне
автоматический возврат не выполняется: разрешение истекает, выбранный путь закрывается.
После перезагрузки и полной сборки Xray нужны новое разрешение и работающая очередь.

Глобальные sysctl, ip rule, WAN/LAN и Tailscale не меняются. Чтобы не включать
`nf_conntrack_acct`, в очередь идут все исходящие TCP/443 пакеты только этого выхода; Lua
обрабатывает ClientHello. Нагрузку CPU и реальную скорость обязательно проверить на машине.
Удаление самих правил firewall вручную — вне штатного переключения; их восстанавливает страж XGW.

Тесты конфигурации, маршрутов, бюджета, отказа/возврата, горячего применения; принятие правил
настоящим nftables в отдельном network namespace; Xray 26.10.21 `run -test` для трёх состояний.
Пакетами в namespace проверены закрытые ворота, отсутствие NFQUEUE-обработчика, проход собственной
сгенерированной метки, истечение разрешения и сохранение обычного bypass.
