# Программа испытаний XGW 0.1.10 на реальной машине

Задание для модели-тестировщика. Машина та же, что в отчёте
`docs/TEST-REPORT-REAL-MACHINE-0.1.9-2026-10-17.md`: ThinkCentre, Ubuntu 24.04.5 LTS, Docker,
роутер HUAWEI AX2 за шлюзом. Стоит XGW **0.1.9** в боевом режиме. На момент того отчёта
(17.10.2026, 11:58) шлюз был в `RESERVE`: все пять безлимитных серверов в работе не отвечали
около двух часов, трафик машины и сети нёс резервный лимитированный сервер x1. Заказчик просил
резервный не отключать.

Задачи по порядку:

## 0. Правила работы

Те же, что в программах 0.1.8 и 0.1.9 (§0 там):

- сеть меняется только командами XGW, действиями в панели и правкой `/etc/xgw/config.toml`;
- аварийный выход — `sudo xgw disable`;
- секреты в отчёт не попадают: адреса подписок, UUID, пароли, ключи, токены, токен панели;
- код XGW не чинить;
- только фейковые данные: единственный добавляемый сервер — ненастоящий F из REAL-43
  программы 0.1.8;
- команды — те, что в программах, а если нужна другая — только читающая;
- записывать время (`date +%T`), команду, вывод и сравнение с ожиданием.

Дополнительно:

1. **Машина боевая.** Перед REAL-62 (вариант Б) и REAL-67, п. 4 — предупредить заказчика и
   записать время: в REAL-67, п. 4 интернет может пропасть до минуты. Перезагрузка (REAL-66) —
   только с согласия заказчика.

## 2. REAL-60. Разбор сбоя 17.10 (на 0.1.9, до обновления)

Только читающие команды. Ничего не включать, не отключать и не перезапускать. Если шлюз к
началу испытаний уже `HEALTHY`, всё равно выполнить пп. 1, 3, 4 и 7 — по журналу.

1. Снимок:

   ```bash
   cd ~/xgw-0.1.10-test
   date; sudo xgw --version
   sudo xgw status > before/status.txt; sudo xgw status --json > before/status.json
   sudo xgw servers > before/servers.txt; sudo xgw diag > before/diag.txt
   ```

   Записать в отчёт:
   - состояние и с какого времени;
   - участников с отметками «МЁРТВ уже …»;
   - резервный выход;
   - вердикты и время последней проверки у безлимитных запасных;
   - строки «Квота «…»: …» и «Подписка «…»: …» — дословно, без адресов.

2. **Подписка не истекла?** Если в строке квоты безлимитной подписки есть «действует до …» —
   сравнить с текущим временем. В `before/status.json` посмотреть `sub_errors`.
3. **Хронология.** Журнал с 16.10 22:00:

   ```bash
   sudo journalctl -u xgw --since "2026-10-16 22:00" --no-pager -o short-iso > before/journal-xgw.txt
   grep -E ' → |rotation:|priority:|reserve:|subscription:|main:|probe:|скан |сквозная проверка' before/journal-xgw.txt > before/timeline.txt
   wc -l before/journal-xgw.txt before/timeline.txt
   ```

   По `timeline.txt` составить таблицу ключевых моментов:
   - первая смерть участника (`DEGRADED` или «замена участников»);
   - переход в `RESERVE`, `WAN_DOWN` и возврат из него;
   - внеочередные обновления подписки и их итог;
   - сканы безлимитных запасных: сколько, когда и с какими вердиктами (`OK`, `TIMEOUT`,
     `CONNECT_FAIL`, `FREEZE` и т. п.);
   - замены участников — были ли после того, как участники умерли;
   - «сквозная проверка не прошла» — когда и с какой ошибкой.
4. **Что видел Xray.** Ошибки соединений за то же время:

   ```bash
   sudo journalctl -u xgw-xray --since "2026-10-17 06:00" --until "2026-10-17 12:30" --no-pager -o short-iso | grep -iE 'fail|timeout|refused|reset|handshake|EOF|invalid' | tail -60 > before/xray-errors.txt
   ```

   Определить вид ошибки у безлимитных серверов:
   - `i/o timeout` — сервер или его адрес недоступен;
   - `connection refused`;
   - `connection reset` — часто так выглядит блокировка;
   - ошибка TLS или REALITY;
   - соединение закрывается сразу после рукопожатия — так бывает, когда сервер не принимает
     пользователя, например подписка истекла.

   Адреса в выписке заменить (§0, п. 3).
5. **Собственная проба.** До трёх безлимитных серверов, без «[xN]» в `sudo xgw servers` (это
   бесплатно, ~57 КБ каждый):

   ```bash
   sudo xgw probe <тег>
   ```

   Записать вердикт и ошибку. Лимитированные не пробовать.
6. **Вопрос заказчику** (одно сообщение). Работает ли сейчас безлимитная подписка в Happ на
   телефоне через **мобильный интернет**, не через домашний Wi-Fi? Активна ли она в личном
   кабинете VPN-сервиса? Записать ответ и время.
7. **Вывод** — одна из причин, с доказательствами из пп. 1–6:
   - **(а) подписка или VPN-сервис**: истекла, или серверы не работают и с телефона через
     мобильный интернет;
   - **(б) домашний провайдер**: с телефона через мобильный интернет работает, а пробы шлюза
     падают по таймауту или сбросу соединения;
   - **(в) дефект XGW**: собственная проба проходит, а ядро считает серверы мёртвыми; или
     запасные отвечали, но замены не было; или сканы не шли. Если (в) — описать как
     дефект: как повторить, что ожидалось, что получилось.

   Если доказательств не хватает, так и написать и перечислить, чего не хватило.

## 4. Кейсы 0.1.10

### REAL-61. Уровень записей в журнале (D2)

1. Проверочная запись через модуль журнала XGW во временной службе. Она ничего не меняет:
   две строки в журнал, без сети.

   ```bash
   sudo systemd-run --wait --quiet --unit=xgw-d2-check /usr/bin/python3 -I -c "import sys; sys.path.insert(0, '/opt/xgw/lib'); from xgw import log; log.setup(); log.get_logger('d2').warning('проверка D2: предупреждение'); log.get_logger('d2').info('проверка D2: событие')"
   sudo journalctl -u xgw-d2-check -o json --no-pager | python3 -c 'import sys, json; [print(d.get("PRIORITY"), d.get("MESSAGE")) for d in map(json.loads, sys.stdin) if d.get("_TRANSPORT") == "stdout"]'
   sudo journalctl -u xgw-d2-check -p warning --no-pager -o cat
   ```

   Ожидается:
   - строка с «предупреждение» — `4`, строка с «событие» — `6`;
   - в тексте нет «<4>» и «<6>»: префикс уровня journald снимает сам;
   - `-p warning` выводит только «предупреждение».
2. Служба после установки:

   ```bash
   sudo journalctl -u xgw --since "<время установки>" -o json --no-pager | python3 -c 'import sys, json, collections; print(collections.Counter(d.get("PRIORITY") for d in map(json.loads, sys.stdin) if d.get("_TRANSPORT") == "stdout"))'
   ```

   Ожидается: большинство записей — `6`; строки с `WARNING` в тексте — `4`, с `ERROR` — `3`.
   Сверить выборочно: `sudo journalctl -u xgw --since "<время установки>" -p warning --no-pager`
   показывает только строки с `WARNING` и `ERROR`.

### REAL-67. Ручной выбор сервера, как в Happ

В панели — кнопка «Выбрать» у каждого сервера в работе и у запасного, «Автовыбор» — в верхнем
блоке. Без графического сеанса — запросами (§0): выбрать — `P pin '{"tag":"<тег>"}'`, вернуть
автовыбор — `P unpin '{}'`. Тег — из `sudo xgw servers`. Выбирать только **безлимитные**
серверы (без «[xN]»): через выбранный идёт весь трафик сети.

1. **Запасной.** Выбрать безлимитный запасной с вердиктом `OK` (`spare-…`). Ожидается:
   - ответ «… выбран вручную: весь трафик идёт через него, пока не вернёте автовыбор…»;
   - в течение 30 с: «Selecting Override» в `xray api bi` (команда `W` из программы 0.1.9,
     одной строкой) — тег этого сервера;
   - `curl -s https://api.ipify.org` на машине и из контейнера — адрес его выхода. Он
     отличается от адреса основного — записать оба;
   - панель (`S`): `pin.tag` — этот тег, `pin.until` — `null`, `pin.down` — `null`; в
     интерфейсе вверху «Выбран вручную» и имя, у сервера метка «выбран вручную»;
   - `sudo xgw status` — «Выбран вручную: «имя» (тег) — весь трафик через него»; строки
     «Основной сервер» нет.
2. **Переживает перезапуски.** `sudo systemctl restart xgw-xray`, через минуту — override тот
   же. `sudo systemctl restart xgw`, через минуту — тот же. Уведомлений нет.
3. **Другой сервер.** Выбрать участника (`proxy-…`), не основного. В течение 30 с override —
   он, адрес выхода сменился, в панели метка переехала.
4. **Выбранный не отвечает.** Предупредить заказчика (§0, п. 1): до минуты интернет может
   пропасть. Во втором терминале — `ping -D 1.1.1.1 | tee ~/xgw-0.1.10-test/ping-67.txt`.
   Добавить ненастоящий F (ссылка — REAL-43 программы 0.1.8), через минуту он в `sudo xgw
   servers` (участник или запасной), и выбрать его. Ожидается:
   - не позже 90 с — уведомление «выбранный вручную сервер «XGW-TEST-DEAD» не отвечает —
     трафик идёт через серверы, выбранные автоматически; когда он снова ответит, шлюз
     вернётся к нему» (журнал: строка `pin:` с `WARNING`, PRIORITY 4);
   - `pin.down` — время; override — основной (или нет, если основной выключен); интернет
     есть; в панели вверху снова автоматический сервер, а заметка над списком — о том, что
     выбранный не отвечает;
   - состояние — не `ALL_DEAD`; перерыв по `ping` — не дольше 90 с.
5. **Выбранного больше нет.** Убрать F (`P link/remove` или в панели). В течение минуты —
   уведомление «выбранного вручную сервера «XGW-TEST-DEAD» больше нет среди серверов …»;
   `pin` в `S` — `null`, `xgw status` без строки «Выбран вручную». Остановить `ping`,
   перерывы записать.
6. **Автовыбор.** Снова выбрать безлимитный запасной из п. 1, затем «Автовыбор» (`P unpin
   '{}'`): ответ «автовыбор: через минуту шлюз снова закрепит основной сервер…»; в течение
   минуты override — основной.
