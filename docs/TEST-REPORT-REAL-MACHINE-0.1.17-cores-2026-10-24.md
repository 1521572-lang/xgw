## Наблюдения

1. **Версия в статусе обновляется не мгновенно.** Сразу после возврата sing-box (через ~3 с)
   `xgw status` ещё показывал «sing-box 1.14.4: работает», через ~20 с — уже 1.14.3; карточка
   и бинарник были верны сразу. То же с полем «установлен» карточки после обновления Xray:
   первые секунды показывала прежнюю версию, к следующему замеру демона — новую. Это кэш на
   интервале опроса демона, не ошибка данных.
2. **Формулировка CLI.** `xgw cores` описывает версии, возвращённые кнопкой, как «не прошла
   проверку: 26.3.27 / 1.14.4 — возвращена прежняя версия», хотя проверки они проходили и убраны
   вручную. Карточка панели формулирует верно: «убрана: … — возвращена прежняя версия».
3. Один запрос подписки при установке не прошёл (таймаут рукопожатия SSL через Xray при первой
   загрузке) — без последствий, следующие обновления подписки прошли.
4. Известные WARN конфига (4 строки Telegram + `xray.version = "26.10.10" не учитывается`) —
   не связаны с веткой, были до испытания.
5. Во время обновления и возврата Xray состояние шлюза ни разу не покинуло HEALTHY (счётчик
   состояния непрерывен с 20:42), событий XRAY_DOWN нет — перезапуски ядра быстрее порога
   реакции демона.
6. После возврата карточка снова предлагает sing-box 1.14.4 («на GitHub: 1.14.4») — так и
   задумано (выпуск снова доступен для обновления).

## Что не проверено и почему

- Самовозврат ядра в сутки наблюдения (ядро перестало отвечать после обновления) — на
  работающем шлюзе не воспроизводится; проверен юнит-тестами.
- Обновление Xray на выпуск новее 26.10.21 — на GitHub его нет (26.10.21 — последний стабильный
  и предварительный); механизм проверен вариантом Б на 26.3.27.
- Кнопка «Обновить до …» в панели для Xray — предложения не было (новее нет); путь панели
  проверен для sing-box (та же команда API, что у кнопки), кнопка «Вернуть» для Xray нажата
  заказчиком.
- Суточное наблюдение за принятым ядром не дожидалось: возврат выполнялся через несколько минут
  после обновления (по плану испытания).
